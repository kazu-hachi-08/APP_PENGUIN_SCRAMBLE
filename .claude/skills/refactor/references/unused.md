# 観点: 未使用コードの削除

どこからも呼ばれていない関数・フィールド・プロパティ・クラス・using を消す。
一番誤検出が怖い観点。Unity は文字列・属性・SceneBuilder 経由で呼ばれるものが多いので、「grep で見つからない」だけでは消さない。

## 事前に確認すること

1. **public なメンバー**: 消してよいか
   - 推奨: プロジェクト全体（Tests も含む）で参照が0件なら消してよい
2. **将来使うつもりで置いてあるもの**（例: 仕様書 §11「未実装・今後の候補」に関係するもの）: 消す／残す
   - 推奨: 残して「要確認」にする
3. **ファイルごと未使用のクラス**: ファイル削除まで行うか
   - 推奨: 行う（.meta も消す）
4. **テストからしか使われていないもの**: 残す／消す（テストも直す必要がある）
   - 推奨: 残す。Tests/ はこのスキルで編集しないため

## 補助情報

解析の前にメインがコンパイラ警告を集めておくと、haiku の「高」確度の根拠になる:

```bash
python .claude/skills/refactor/scripts/build_check.py --unused-warnings
```

CS0169（使われていないフィールド）、CS0414（代入だけされるフィールド）、CS8321（使われていないローカル関数）、CS0168/CS0219（使われていない変数）を担当ファイル別に出す。担当に該当する行をプロンプトに貼る。
CS0649 は SceneBuilder が値を入れているので出さない（誤検出）。

```
## 手順
1. 担当ファイルの private / internal / public なメソッド・フィールド・プロパティ・定数・クラスと、using を洗い出す。
2. それぞれ、名前で Assets/_Project 全体（Tests/ と Editor/ を含む）を grep する。例: grep -rn "\bMethodName\b" Assets/_Project --include=*.cs
   - 定義行以外にヒットが1件でもあれば「使われている」。
   - nameof(...)、文字列 "MethodName"、FindProperty("_field") でのヒットも「使われている」。
3. 次のものは grep で0件でも未使用と判断しない:
   - Unity メッセージ（Awake, Start, Update, OnEnable, OnDisable, OnDestroy, OnValidate など On〜で始まる Unity のコールバック）
   - [MenuItem] [InitializeOnLoad] [RuntimeInitializeOnLoadMethod] [ContextMenu] [ServerRpc] [ClientRpc] [Rpc] が付いたもの
   - [SerializeField] のフィールド（SceneBuilder が値を入れている）
   - override / interface の実装
4. 「定義以外に参照なし」で上の例外にも当たらないものだけを書く。

{common-rules.md の「haiku に必ず渡すルール」}

## 出力
1行1件、次の形式だけで返してください。
- [高|中|要確認] 相対パス:行 | 未使用の○○ `名前`（grep で確認した結果: 定義以外 0件） | 削除（ファイルごとなら「ファイル削除」）
確度: コンパイラ警告に載っている or private で0件 → 高、public で0件 → 中、テストからだけ使われる・将来用に見える → 要確認。
指摘がなければ「なし」とだけ返してください。
```

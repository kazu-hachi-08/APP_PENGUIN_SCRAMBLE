# 観点: 重複処理の共通化

同じロジックのコピペを1か所にまとめる。4観点のなかで唯一 **コードの構造が変わる** 観点なので、小さくまとめることを優先する。
CLAUDE.md の「小さく作る」に従い、2か所の短い重複のためにヘルパークラスや抽象を増やすのは避ける。

フォルダ単位の分担だと、フォルダをまたぐ重複は見えにくい。haiku には担当外のフォルダも grep で探させる。

## 事前に確認すること

1. **まとめる基準**: 何か所・何行以上の重複を対象にするか
   - 推奨: 3か所以上、または2か所でも10行以上のまったく同じ処理
2. **置き場所**: 共通化したメソッドをどこに置くか
   - 推奨: 同じクラス内なら private メソッド、複数クラスなら既存の近いクラスの static メソッド。新しいファイルは原則作らない（csproj が古いままでコンパイル確認から漏れるため）
3. **asmdef をまたぐ重複**（純C#の Logic と View の間など）: まとめるか
   - 推奨: まとめない。純C#の asmdef は UnityEngine に依存しない約束なので、境界を越える共通化は「要確認」
4. **SceneBuilder（Editor/）の UI 生成コードの重複**: 対象に含めるか
   - 推奨: 含める。ただしシーン生成の結果が変わらないことが条件

## 解析プロンプト

```
あなたは乱戦！ペンモンスクランブル（Unity / C#）のコードを解析する担当です。観点は「重複した処理」だけに絞ってください。他の問題は書かないでください。
このタスクではファイルを編集しないでください。読んで指摘するだけです。

## 担当ファイル
{ファイル一覧}

## 方針（ユーザーと決めたこと）
{手順2で決めた方針}

## 手順
1. 担当ファイルの中で、同じ（または変数名だけ違う）処理が繰り返されている箇所を探す。
2. 見つけた処理の特徴的な行（メソッド呼び出しの並びなど）で Assets/_Project 全体を grep し、担当外にも同じ処理がないか確かめる。
3. 方針の基準を満たすものだけを書く。共通化すると読みにくくなる・引数が増えすぎるものは書かない。

{common-rules.md の「haiku に必ず渡すルール」}

## 出力
1行1件（1つの重複グループで1件）、次の形式だけで返してください。
- [高|中|要確認] 相対パス:行, 相対パス:行, ... | 重複している処理の説明（何行×何か所） | まとめ方（メソッド名案・置き場所・シグネチャ）
確度: まったく同じ処理で同じクラス内 → 高、クラスをまたぐ → 中、asmdef をまたぐ・挙動が微妙に違う → 要確認。
指摘がなければ「なし」とだけ返してください。
```

## 修正プロンプト

1つの重複グループは1体の haiku に渡す。グループ同士でファイルが重なる場合は同時に走らせない。

```
あなたは乱戦！ペンモンスクランブル（Unity / C#）の重複処理をまとめる担当です。下の「承認済みリスト」の重複グループだけをまとめてください。リストにないことは、気づいても直さないでください。
まとめたあとも動作がまったく同じになるようにしてください（呼び出し順・引数の値・null の扱いを変えない）。新しいファイルは作らないでください。
```

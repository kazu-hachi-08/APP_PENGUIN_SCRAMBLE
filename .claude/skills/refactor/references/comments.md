# 観点: コメント・宣言の整理

開発の経緯（「PLAN_STORY_TOWN01.md フェーズ5」「仕様書 §7」）が書かれたコメントや、同じ説明の繰り返し、重複した宣言を整える。
経緯は git の履歴にあるので、コードには「今どうなっているか」「なぜそうしているか」だけを残したい。

## 事前に確認すること

1. **「仕様書 §N」の参照**: 消す／残す（仕様書の章番号は今も有効なので、仕様の出典として残す価値はある）
   - 推奨: 残す。ただし章番号が今の仕様書とずれているものは直す
2. **「PLAN_*.md フェーズN」「区切りN」の参照**: 消す／残す
   - 推奨: 消す。PLAN は当時の計画メモで、コードを読む人には不要
3. **経緯コメントを消したあとの文**: 文の残りが「なぜ」を説明していればそのまま残すか
   - 推奨: 残す。経緯の括弧書きだけを取る
4. **重複した宣言**（同じ定数・同じ using の重複など）の扱い: 片方に寄せてよいか
   - 推奨: 寄せる。ただし別 asmdef にまたがるもの（純C#の Logic と View など）は要確認

## 背景

- エリアは 16×9 マスと狭く、ガードも回避も無い。雑魚とステージのボスは、技が届く距離の 80% まで寄るとすぐ殴る（構えが無い。`StageWorld.EnemyAi.cs`）ので、よけようがない
- 予告（赤い範囲）があるのは大ボスだけ。その大ボスも、狭いエリアでは逃げる先がすぐ壁になる
- 方針: ボタンは増やさない。「敵の構えを見て歩いてよける」遊びにする。大ボスとは広い丸い闘技場で戦う

## フェーズ1: 雑魚とボスの構え

Core:

- [x] `Unit` に「構え」の状態を持たせる（残り時間・出す技の枠・構えたときの向き）
- [x] 敵の動き: 届く距離に入ったら、すぐ技を出す代わりに構えに入る。構えている間は動かず向きも変えない。時間が来たら、構えたときの向きのまま技を出す
- [x] 構えている間に強く飛ばされた（速さが `StunSpeed` より上）・凍ったら、構えをやめる（殴って止められるようにする。待ち時間は使ったことにして、すぐ構え直さない）
- [x] 構えの時間は `Balance` に持つ: 雑魚 0.4 秒・ボス 0.5 秒（技2は 0.7 秒）くらいから始める
- [x] 大ボス（`Brain` を持つ）と、技を持たない的（`SkillPractice`）は今のまま
- [x] 通信: `UnitFlags` に「構えている」を足す（`StageRecorder`・`StageCodec`。`FormatVersion` を上げる）

見た目（Game）:

- [x] 構えている敵は、体がぷくっと膨らみ、白く光る（`UnitView` / `PenguinMotion`）
- [x] 地面にうすい予告を出す: 近接・周囲は扇か円、弾・拡散・突進は向きの線。大ボスの赤より薄く小さくして、画面がうるさくならないようにする
- [x] 構えに入った瞬間に小さな音を鳴らす（`GameSounds`。数が多いので音量は小さめ、同時に鳴る数をしぼる）

テスト・仕様:

- [x] テスト: 構えの間は技が出ない・構えたときの向きで出る・構えの間に横へ逃げたら当たらない・飛ばされたら構えをやめる・通信で「構えている」が届く
- [x] 仕様書 §4.7 に構えのルール、§9.4 に見た目を書く。遊び方のルールの文（`HowToPlayPages`）に「敵が光ったら攻撃の合図」を足す

**完了の確認**: ソロで1ステージ遊び、雑魚の攻撃を歩いてよけられる。協力でも、ゲストの画面で構えが見える。

## フェーズ2: 攻撃の順番待ち

Core:

- [x] プレイヤー1人に、同時に「攻撃してよい」敵は 2 体まで（ステージのボスは数えない。`Balance` に持つ）。近い順に権利を渡し、構え・技が終わったら手放す
- [x] 権利の無い敵は、プレイヤーから少し離れた距離（技が届く距離＋1.5 マスくらい）で止まり、ゆっくり横へ回り込む（止まって並ぶと間が抜けて見えるため）
- [x] 協力では、敵はそれぞれ一番近いプレイヤーの権利を取り合う。ダウンした人の分は持たない
- [x] 刻みごとに決まった順で計算する（ホストの結果をそのまま送るので、乱数と順番がずれないように）

テスト・仕様:

- [x] テスト: 10 体に囲まれても、同時に構えるのは 2 体まで・権利を持った敵が倒れたら次の敵に渡る・2 人なら 4 体まで構えられる
- [x] 仕様書 §4.7 に書く

**完了の確認**: 大量に囲まれても、殴ってくるのは数体だけで、囲まれている見た目は残っている。

## フェーズ3: 当たった後の短い無敵

Core:

- [x] プレイヤーのペンモンは、敵の攻撃が当たった後 0.4 秒は無敵（`Balance`）。今ある `InvincibleSeconds` を使う
- [x] 交代で出てきた子は引き継がない（交代して逃げる遊びはしない。必要なら調整で考える）
- [x] 必殺技・復活の無敵（3 秒・2 秒）より短い時間で上書きしない

見た目:

- [x] 今の無敵の点滅を使う。必殺技の無敵と見分けたいかは遊んでから決める

テスト・仕様:

- [x] テスト: 当たってから 0.4 秒は次が当たらない・必殺技の無敵が短くならない
- [x] 仕様書 §4.1 か §4.7 に書く

**完了の確認**: 囲まれても一瞬で溶けない。無敵が長すぎて、ごり押しで勝ててしまわない。

## フェーズ4: 大ボスの闘技場（ルールと計算）

形:

- 大ボスのエリアだけ、横 32 × 縦 18 マスの楕円（横長の丸）。人数で広さは変えない
- 前のエリアの右の出入口から、楕円の左端につながる（左端の高さは今のエリアの真ん中にそろえる）
- 観客席は置かない
- ステージのボス（強い野生ペンモン）のエリアは、今の 16×9 マスの四角のまま

Core:

- [x] `StageLayout`: エリアの広さと形をエリアごとに持てるようにする。大ボスのエリアだけ広さと「楕円」を持つ（`AreaDef` に持たせるか、ボスの番号 101〜 から決める）。ほかのエリアの位置は変えない
- [x] 壁: 楕円の中に押し戻し、飛ばされて当たったら、楕円の面に対して跳ね返す（速さ 60% は今と同じ）。純C# で計算する
- [x] 入るとき: 前のエリアの出入口が開いている間は、前のエリアと楕円の左端だけを動ける範囲にする。誰かが 2 マス入ったら闘技場が始まり、外にいる人は楕円の中へ引き寄せる
- [x] 敵の出る場所・`RandomPointInArea`・`ClampInsideArea` を楕円の内側にする
- [x] 大ボスの攻撃を闘技場に合わせる
  - 波: 楕円の上半分か下半分を、端から端まで流す（帯の長さは楕円の幅）
  - シャチの横切る突進: 楕円の柵まで
  - 羽の雨: ばらばらの円を、広さに合わせて増やす（3 → 5 か所くらい）
  - 休みの間に寄ってくる距離（3 マス）は今のまま。広いぶん、寄るのに時間がかかりすぎないかは調整で見る
- [x] 通信: ゲストが楕円の形を知れるようにする（エリアの形はステージの番号から引けるなら送らない。引けなければ `StageSnapshot` に足す）。`FormatVersion` を上げる

テスト・仕様:

- [x] テスト: 楕円の外へ出られない・飛ばされて柵に当たると跳ね返る・出入口から入れて、入ったら戻れない・敵と予告が楕円の中に出る・ほかのエリアの位置が変わっていない
- [x] 仕様書 §6.1・§6.2 に闘技場の形と攻撃の変更を書く

メモ（実装で決めたこと）:

- 闘技場かどうかは `AreaDef.IsArena`（大ボスがいるか）で決める。形は `AreaShape`（四角か楕円）。`StageLayout.Area(stage, i)` で引く
- 出入口が開いている間は「前のエリア・通り道（幅3マス）・楕円」を合わせた範囲。楕円の左端はとがっていて、壁と楕円だけでは通り抜けられないため
- 大ボスの突進は、予告の道の長さ（柵まで）だけ走る。シャチの横切る突進の距離は柵で決まる
- 羽の雨のばらばらの円は、広さの比の平方根で増やす（3 → 5）
- 仮の見た目: 床は楕円を囲む四角のまま。カメラは闘技場の中で縦にも追う（フェーズ5で作り直す）
- 通信の中身は変えていないが、ルールが変わったので `FormatVersion` は 10 に上げた

**完了の確認**: 見た目は仮（四角の床でもよい）のまま、闘技場の中で大ボスと戦い、柵で跳ね返る。

## フェーズ 0: アデリンの顔の絵を直す（済み）

### 原因（解析済み）

- 前回の Rebuild（コミット `dac42e4`）で、`Penguin01.png` だけが**体・目・くちばしまで同じ水色 (160,232,245)** で撮られ、縁の線だけ残った。1つ前の版（`006e6ea`）は正常
- 縁の線は別のシェーダーでまとめて描いているので線は出た。Toon シェーダーの準備（エディタはシェーダーを裏で読み込む＝非同期コンパイル）が1枚目に間に合わず、仮の色で描かれたと考えられる。撮る順番が1番目のアデリンだけが外れ、2体目以降・大ボス・アプリのアイコンは正常
- ペンモン画面の図鑑カード・一覧・ガチャ・カットイン・ロビーの名前の札など、顔の絵を使う所すべてに出ている

### やること

1. `PenmonScrambleSceneBuilder.Portraits.cs` の撮影（`WithPortraitStudio`）の間だけ、シェーダーの裏読み込みを止める（`ShaderUtil.allowAsyncCompilation = false`。終わったら元に戻す）
2. 撮る前に、使う素材を一度空撮りしてシェーダーを準備させる（念のため）
3. 撮った絵が「ほとんど1色」なら失敗とみなして書き込まず、警告を出す（同じことが起きても、正しい絵を壊さない）。アプリのアイコン（`AppIcon.cs`）の撮影にも同じ守りを入れる
4. Rebuild して、20種類と大ボスの顔を目で確かめる

## フェーズ 1: 記録の作り直しと育成（済み）

> 実装済み。決めた細部は仕様書 §7.3・§10 に書いた（上限解放は先に数えてから上限を決める・何も変わらない強化は押せない・一覧の◆は解放した子だけ、など）。

### 1.1 記録（セーブ）

- 保存のキー `PenmonScramble.Save` はそのまま。`SaveData.CurrentVersion` を **2** にする
- **version が 2 より小さい記録は読まずに、新しい記録で上書きする**（今回だけの例外。ユーザー承認済み）。名前（`UserProfile.Name`）と音量はキーが別なので残る
  - これまでの `Broken` への退避（JSON でない記録）はそのまま残す
  - 消したときは、初回の「タップしてスタート」の後に一言「新しいバージョンになったので、記録を初めからにしました」と出す
- 初回は今と同じく無料ガチャ3回から
- 記録の項目（v2）
  - 個体: `id`・`speciesNo`・`basePower`（引いたときのパワー）・`boost`（強化で足した分）・`limitBreak`（上限解放の回数 0〜4）
  - パワー ＝ `basePower` ＋ `boost`
  - ボスラッシュ: ステージごと・難易度ごとのクリア済み（`clearedRush`。例: ステージ番号×10＋難易度）
  - そのほか今と同じ（コイン・編成・クリア済みのストーリー・無料ガチャの回数）
- v2 以降はまた CLAUDE.md §3.5 どおり「足すだけ」に戻す。仕様書 §10 と CLAUDE.md に「v1→v2 だけ消した」と書き残す

### 1.2 強化（どの子でも素材にできる）

- 強化する子を1体選び、素材を1〜10体まとめて選んで「強化する」
- 1体ごとに上がるパワー ＝ 素材の★の基本値（★1: 8 / ★2: 20 / ★3: 50。案）＋ 素材のパワー × 10%（案）
- 上限 ＝ `basePower` × (1.5 ＋ 0.25 × `limitBreak`)（案。最大 ×2.5）。上限を超える分は捨てる（選ぶ画面で「上限まで あと ○」と、あふれる分を赤で見せる）
- コイン ＝ 素材1体につき、強化する子の今のパワー × 0.5（案）。足りなければ押せない
- 素材にできないもの: 編成の3体・強化する子自身
- ★3 や、強化する子より強い子を素材に入れたときは確認を出す（売るのと同じ2回押し）

### 1.3 上限解放（同じ種類を素材にする）

- 同じ種類の子を素材にすると、上の強化に加えて `limitBreak` が1上がる（最大4）
- 上限まで上がった子には、同じ種類を素材にしても上限は増えない（パワーは上限まで足す）
- 一覧のカードと図鑑カードに、上限解放の数を小さな★の点（◆◆◇◇）で出す

### 1.4 画面

- ペンモン画面の図鑑カードの下に「強化」を足す（「編成に入れる」「売る」と並べる）
- 強化の画面（ペンモン画面の上に重ねる窓）
  - 左: 強化する子（顔・パワー・上限・上限解放の点）と、強化後の見込み（パワー 150 → 182 のように数字を並べ、ゲージで上限との関係）
  - 右: 素材を選ぶ一覧（一覧と同じカード。編成の子は暗く押せない。同じ種類は「上限UP」の札）
  - 下: 必要なコインと「強化する」
- 強化した瞬間: 素材の顔が吸い込まれ、強化する子の顔が光って数字が数え上がる。上限解放のときは点が1つ金に灯る（短く。押せばとばせる）
- 強化した直後に保存する

### 1.5 コード

- Core: `PlayerRecord.Enhance.cs`（強化・上限・コインの計算と実行）、`Balance.Growth.cs`（数値）
- Game: `Menu/EnhanceScreen.cs`（と演出を分けた partial）。組み立ては `PenmonScrambleSceneBuilder.Enhance.cs`
- テスト: 強化の量・上限で止まる・上限解放の回数・編成の子を素材にできない・コイン不足・記録の version 1 を消して新規になる

## フェーズ 3: 闘技場・ボスの土台を広げる

ボスラッシュと新しいワールドのための Core の土台。ここではテスト用の開発ステージでだけ使う。

### 3.1 闘技場の決め方を変える

- 今は「大ボスがいるエリア＝闘技場」。巨大ペンモンの戦いも闘技場にするため、`AreaDef` に闘技場かどうかを明示して持たせる（大ボスがいれば必ず闘技場、はそのまま守る）
- **闘技場が続けて並べる**ようにする: 前の闘技場の右端と次の闘技場の左端を、幅3マスの通り道でつなぐ（`StageLayout`）。勝ったら通り道が開いて「すすめ →」、入ると次の大ボスが降りてくる（今の入場の演出をそのまま使う）
- ボスラッシュは始まりのエリア（短い四角）を置かず、最初から闘技場に立って始める

### 3.2 戦いの合間

- 1戦勝つごとに「ROUND CLEAR!」を出し、全員の HP を 30% 回復（案）・ダウンしていた人は HP 30% で起き上がる
- 次の闘技場に入るまでは敵が出ないので、ここで一息つける

### 3.3 巨大ペンモンの闘技場の大技

- 1戦目の巨大ペンモン（ステージのボスより大きく硬い。HP・大きさは別の倍率）は、自分の技1・技2に加えて、**大ボスと同じ赤い予告の大技**を属性ごとに1つ持つ
  - 氷: 闘技場にばらばらにつららが降る（羽の雨と同じ形）
  - 水: 横一列の波（波と同じ形）
  - 風: 3か所に竜巻が立ち、中へ吸い込む（新しい形「吸い込みの円」）
  - 雷: 一番近いプレイヤーへ向けた稲妻の帯（突進の帯と同じ形で、ボスは動かず帯に雷が走る）
- 2体組なので、2体の大技が重ならないよう順番を交互にする

### 3.4 大ボスの「本気」

- ボスラッシュの3戦目の大ボスは「本気」: 頭に「本気」の札、体のまわりに赤い湯気
- HP が半分を切ると一度吠えて（全体が 0.5 秒止まる）、予告が 2 割短く・休みが 3 割短くなり、攻撃が1つ増える（案）
  - カモメ: 羽の雨が2回続けて降る / アザラシ: 飛び出しが3回続く / シャチ: 波が2本同時 / オオフルマカモメ: 竜巻が増える / サメ: 背びれが2本になる

### 3.5 難易度を Core に持たせる

- `StageWorld` に難易度（ふつう / むずかしい / げきむず）を渡す。敵の HP・攻撃・予告の長さに倍率を掛ける（`Balance.Difficulty.cs`。案: HP ×1 / ×1.8 / ×3、攻撃 ×1 / ×1.5 / ×2.2、予告 ×1 / ×0.9 / ×0.8）
- ストーリーは「ふつう」固定
- 通信: スナップショットの頭に難易度と「何戦目か」を足す（ゲストの HUD・結果・報酬で使う）。ステージの番号はボスラッシュを 101〜105 にする（1 バイトのまま収まる）

### 3.6 テスト

- 闘技場が続くときの形と通り道・合間の回復・本気の切り替わり・難易度の倍率・巨大ペンモンの大技の予告・通信で難易度と何戦目かが届く

## フェーズ 4: 新しい大ボス2体

今の3体と同じ作り（Core の攻撃の定義 `BigBossTable` ＋ 3D の `BigBossModelBuilder.*.cs` / `BigBossMotion.*.cs`）で足す。番号は 104・105。

### 4.1 オオフルマカモメ（104・風。嵐の崖）

- 見た目: 大きな灰色の海鳥。太く大きなくちばし（先が黄色）。カモメより大きく重たく、低く滑空する
- 攻撃（この順に繰り返す。案）
  1. 突風: ボスから扇形の広い赤い範囲 → 強い風で押し流す（ダメージ小・柵まで押される。柵に当たると少し痛い）
  2. 竜巻: 闘技場に3つの赤い円 → 竜巻が立ち、ゆっくり動きながら近くのプレイヤーを吸い込む（4 秒）
  3. 急降下: 一番近いプレイヤーへ赤い帯 → 低く突っ込む
- 新しい攻撃の形: 「押し流す扇」「動く吸い込みの円」（Core に足す）

### 4.2 サメ（105・水。火山の入り江）

- 見た目: 青灰色のサメ。白いお腹・大きな背びれ・尾びれ。口を開けると歯が並ぶ（おもちゃらしく丸く）
- 攻撃（案）
  1. 背びれ: もぐって背びれだけが床を走る（攻撃が効かない）。走る道を少し先まで赤い線で見せ、背びれに触れると飛ばされる
  2. 食いつき: 一番近いプレイヤーの足元に赤い円 → 下から大口で飛び出す（アザラシより円が大きく、出た後に溶岩のしぶきの小さな円が3つ残る）
  3. 突進: 浮き上がって大口で突っ込む
- 背びれの「床を走る当たり」は新しい形（Core に足す）。アザラシの「もぐる」と違い、もぐっている間も動き回って当たりがある

### 4.3 ほか

- 顔の絵（`Boss104.png`・`Boss105.png`）は Rebuild で撮る（フェーズ 0 の守りが効く）
- 闘技場に降りてくる演出・HUD の顔・端の印は今の仕組みに乗る
- テスト: 攻撃の順番・予告の形・もぐっている間の扱い・本気の追加攻撃

## フェーズ 6: ボスラッシュ（オンライン専用）

### 6.1 流れ

```text
ロビー →「みんなで遊ぶ」→ 部屋を作る / コードで参加
  → 待ちの窓（ホスト: ステージ ◀ ▶ と難易度を選ぶ。ゲスト: 選ばれたものが見える）→ ホストが「開始」
  → 1戦目（巨大ペンモン2体）→ ROUND CLEAR → 2戦目（大ボス）→ ROUND CLEAR → 3戦目（本気の大ボス）→ 結果
```

- 「みんなで遊ぶ」からはストーリーを遊べなくする。「ひとりで遊ぶ」はストーリーだけ
- ホストがひとりのまま「開始」してもよい（友達を待たずに練習できる。報酬も同じ）（案）
- 待ちの窓の中: ステージのカード（番号・名前・3戦の顔・解放していなければ鍵）、難易度の3つの札（ふつう 緑 / むずかしい だいだい / げきむず 赤。開いていなければ鍵）、選んだ難易度の報酬のコイン
- ホストが選び直すたびにゲストへ送る（通信のメッセージを1つ足す）

### 6.2 5ステージ（案）

| No | 名前 | 1戦目（巨大ペンモン2体） | 2戦目（大ボス） | 3戦目（本気の大ボス） |
| --- | --- | --- | --- | --- |
| 101 | 海鳥の闘技場 | キングス・オヤブン（氷） | ヒョウアザラシ | オオトウゾクカモメ |
| 102 | 氷の闘技場 | マゼラ・ロワイヤル（水） | オオトウゾクカモメ | ヒョウアザラシ |
| 103 | 深海の闘技場 | マカロ・キガシラ（風） | オオフルマカモメ | シャチ |
| 104 | 嵐の闘技場 | エレペン・ライジン（雷） | シャチ | オオフルマカモメ |
| 105 | 火山の闘技場 | ★3 の4体から2体（ステージごとに固定） | オオフルマカモメ | サメ |

- 定義は `Core/Stage/RushTable.cs`（ストーリーの `StageTable` と分ける。番号 101〜）
- 闘技場の床: ボスラッシュ専用の「コロシアム」の絵（石の円形の舞台・氷の柱・旗）を ComfyUI で作り、ステージごとにその大ボスのワールドの色を掛ける。柵はコロシアムらしく太い石の柱と旗の飾りにする（`ArenaFence` に見た目の種類を足す）
- 1戦ごとに取り巻きの雑魚が少し出る（大技をよける邪魔をしすぎない数）

### 6.3 報酬（コインだけ）

- クリア: ふつう 300 / むずかしい 800 / げきむず 2000（案）。各難易度の初クリアは同じだけ上乗せ
- 失敗: 勝った戦いの数 × クリアのコインの 15%（案）＋ 倒した数 × 1
- 協力では全員がもらう。クリア済み・解放は参加者全員の記録に付く（今のストーリーと同じ考え方）。ゲストは、ホストが選んだステージ・難易度を自分が解放していなくても遊べて、クリアすると自分の記録にも付く
- 結果の画面: 見出しの下に「ボスラッシュ 嵐の闘技場 むずかしい」。札は「倒した数」→「勝った戦い 3/3」→「コイン」→「初クリア ボーナス」→「〇〇 解放！」（次のステージ・次の難易度）

### 6.4 HUD

- 右上のエリアのつぶの代わりに「ROUND 1 2 3」のつぶ（3戦目は赤い王冠）
- 3戦目が始まるときは「FINAL ROUND」の知らせ

### 6.5 テスト

- 解放の順番（ステージは前の「ふつう」、難易度は1つ下）・報酬の計算・ゲストの記録に付く・待ちの窓の選択がゲストへ届く

## フェーズ 7: バランス調整

「いろいろテストして調整」のため、人の代わりに戦わせて数値で測る仕組みを先に作る。

### 7.1 測る仕組み

- 純C#の「バランスの試験場」（`Tests/Editor` とは別に、エディタのメニュー `Tools > PenmonScramble > Balance > Run`）: ボットに編成を持たせてステージを最初から最後まで高速で回し、表にまとめる
  - 測るもの: クリアできたか・かかった時間・受けたダメージ・倒れた子の数・ダウンの回数・大ボスの戦いの長さ
  - 条件を並べて回す: ステージ（1-1〜5-3・ボスラッシュ×3難易度）× 人数（1〜4）× 編成のパワー（その時点の想定）× 種（乱数）
- ボット（`StageBot`）を賢くする: 赤い予告と構えの予告の中にいたら外へ歩く・HP が減ったら交代・倒れた仲間を起こしに行く。「うまい人」「ふつうの人」の2段階（よけるまでの遅れを変える）

### 7.2 目標（ここに合わせる。案）

| 場面 | 想定する編成 | 目標 |
| --- | --- | --- |
| 1-1 | 無料3回の子（強化なし） | ふつうの人でクリアできる。HP の半分ほど削られる |
| 各ワールドの3ステージ目 | その時点のガチャ＋少し強化 | ふつうの人で 6〜7 割クリア。大ボスに何回か当たる |
| 5-3 | 強化を進めた子 | ふつうの人で半分ほど |
| ボスラッシュ ふつう | ストーリー同じワールドをクリアした頃 | 2〜4人で 7 割ほど |
| むずかしい | 上限解放を何回かした子 | 2〜4人で 5 割ほど |
| げきむず | 上限まで育てた ★3 | うまい人4人で 3〜5 割 |

- コインの流れも合わせる: ストーリーのクリアと、ボスラッシュの報酬で、ガチャと強化をどのくらいの速さで回せるか（1時間遊んで何回引けて何回強化できるか）を表で出す
- 調整する数値: ワールドの敵の倍率・敵の攻撃・構えと予告の長さ・攻撃してくる雑魚の数（`AttackersPerPlayer`）・ボスの HP・難易度の倍率・ガチャのパワーの範囲・強化の量と上限・コインの報酬

### 7.3 実機

- 測った数値で合わせた後、実際に遊んで確かめる（Windows 版で友達と）。手ごたえが違えば数値を直してまた測る

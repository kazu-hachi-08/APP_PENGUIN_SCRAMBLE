# 乱戦！ペンモンスクランブル 仕様書

> 対話で中身を決めながら埋めていく。未定の項目は「未定」と書いておく。「（案）」は Claude の提案で、まだ確認していないもの。

## 1. 概要

おもちゃのペンギン「ペンモン」を3体連れて、大量の野生のペンモンをなぎ倒していく見下ろし型アクション。ひとりではストーリーを進め、最大4人のオンライン協力ではボスラッシュに挑む。仲間はガチャで集める。

| 項目 | 内容 |
| --- | --- |
| アプリ名 | 乱戦！ペンモンスクランブル |
| ジャンル | 乱戦アクション（斜め見下ろしの3D） |
| 雰囲気 | おもちゃのようなコミカル。丸くてかわいく、倒されても痛そうに見えない |
| グラフィック | 球・卵形を組んだおもちゃの3D（トゥーン調）。形も動きもコードと定義表から作る（§9）。地面だけ ComfyUI の絵 |
| プレイ人数 | 1〜4人（ソロはストーリー / オンライン協力・参加コードはボスラッシュ） |
| 1ステージの長さ | 3〜5分 |
| ペンモンの数 | 20種類（★1〜★3。§5） |
| ステージ | ストーリー: 5ワールド×3ステージ＝15ステージ（1-1〜5-3）。各ワールドの最後に大ボス（§6）。ボスラッシュ: 5ステージ×3難易度（§6.5） |
| プラットフォーム | Android / Windows / ブラウザ（WebGL）。横画面固定 |
| 操作 | タッチ・キーボード・コントローラー（§3） |

### 1.1 権利まわりの方針

遊び方はポケモン乱戦スクランブルを参考にするが、キャラクター名・技名・見た目はすべてオリジナルにする。ペンモンは実在のペンギンの種類を題材にしてよい。

## 2. ゲームの流れ

```text
タイトル（ロゴと「タップしてスタート」）→ ロビー（§3.3。ストーリーのステージを ◀ ▶ で選ぶ）
 ├ ひとりで遊ぶ → 選んだストーリーのステージ → 結果
 ├ みんなで遊ぶ → 部屋を作る / コードで参加 → 待ちの窓（ホストが遊ぶもの＝ボスラッシュ / ゴルフ / サッカー / 野球を札で選ぶ）→ ホストが「開始」
 │    ├ ボスラッシュ（ステージと難易度）→ 1戦目（巨大ペンモン2体）→ 2戦目（大ボス）→ 3戦目（本気の大ボス）→ 結果（§6.5）
 │    │    → ホストが「ステージを選ぶ」→ 同じ顔ぶれのまま待ちの窓へ戻る（§8）
 │    ├ ゴルフ（コース）→ 全員でゴルフのシーンへ → 3ホールを順番に → 結果（順位）→ ホストが「コースを選ぶ」→ 待ちの窓へ（§13.3）
 │    ├ サッカー（スタジアム・対戦 / 協力・席の赤・青）→ 全員でサッカーのシーンへ → 3分の試合（同点なら PK戦）→ 結果（MVP）→ ホストが「スタジアムを選ぶ」→ 待ちの窓へ（§13.4）
 │    └ 野球（球場・対戦 / 協力・席の赤・青）→ 全員で野球のシーンへ → 3イニングの試合 → 結果（MVP）→ ホストが「球場を選ぶ」→ 待ちの窓へ（§13.5）
 ├ ガチャ
 ├ ペンモン（一覧・図鑑と技の実演・並べ替え・強化・売る・編成の3体。§7.2・§7.3）
 ├ ミニゲーム → ミニゲームを選ぶ画面（§13）→ コースを選ぶ →「ひとりで」→ ミニゲームのシーン →「もどる」でミニゲーム画面へ
 │    └「みんなで」→ 遊ぶもの＝そのミニゲーム（ゴルフ・サッカー・野球）・そのコースを選んだ状態で「みんなで遊ぶ」の窓（部屋を作る / コードで参加）
 ├ 遊び方（§3.1）
 ├ 名前の札（名前の変更）
 └ 設定（名前・BGM・効果音・記録の初期化。§3.3）

ステージ中: 右上の ‖ / Esc → メニュー（つづける・やり直す・遊び方・設定（音量）・タイトルへ。§3.2）
```

- 初回起動: 「タップしてスタート」を押すと、まず名前を決める（決めるまで閉じられない）。続けてロビーの上にガチャが開き、無料ガチャを3回引くまで閉じられない。引いた3体がそのまま編成になる（§7）
- ステージ・ミニゲームから戻ったときは「タップしてスタート」を出さずにロビーから（アプリを起動し直したら、また出す）。ミニゲームから戻ったときは、ロビーの上にミニゲーム画面を開いた状態から（§13）
- 編成はステージの前ではなく「ペンモン」の画面で決めておく（毎回選ぶ手間を省くため）。協力では各自の編成で遊ぶ
- ソロは「ホストだけで部屋を作った」のと同じ動きにする（通信しないだけ。コードを分けない）
- 「ひとりで遊ぶ」はストーリーだけ、「みんなで遊ぶ」はボスラッシュかミニゲーム（ゴルフ・サッカー・野球）。ボスラッシュはひとりでは遊べないが、部屋を作ったホストがだれも待たずに「開始」してもよい（友達を待たずに練習できる。報酬も同じ。このときはソロと同じくメニューで止まる）

## 3. 操作

| 操作 | スマホ | PC（キーボード） | コントローラー（PS5 表記） |
| --- | --- | --- | --- |
| 移動 | 左の仮想スティック | WASD / 矢印 | 左スティック / 方向キー |
| 技1 | 右のボタン（大） | J | ×（南） |
| 技2 | 右のボタン（中） | K | ○（東） |
| 必殺技 | 技1の上のボタン（ゲージ満タンで光る） | L | △（北） |
| 交代 | 技2の上の小ボタン | Space | L1 |
| メニュー | 右上の ‖ | Esc / P | OPTIONS |

- 技は向いている方向へ出す。狙いをつける操作は無い（スマホで遊びやすくするため）
- 向きは最後に動いた方向。止まっているときに技を出すと、一番近い敵の方を向く
- ボタンはセーフエリア（ノッチ・角の丸み）の内側から測って、角から少し離して置く（機種によって角が押せないため）
- スマホのスティックとボタンは、ステージで遊んでいる間だけ出す（タイトル・ロビー・結果では隠す。出し入れは短くフェード。`TouchControlsVisibility`）。PC など触れない端末では出さない
- ボタンの見た目（`PenmonScrambleSceneBuilder.TouchControls.cs`、絵は `PenmonScrambleSceneBuilder.TouchArt.cs`）: 影・下の濃い厚み・白い縁・上が明るい色の面・上のつや。押している間は面が厚みのぶん沈んで少し縮む（`TouchButtonPress`）。中身は場に出ている子に合わせて変わる（`TouchControlsView`）
  - 技1・技2: 面は属性の色で、中に技の形のアイコン（§4.2。ペンモン画面と同じ絵）。待ちの残りを暗い扇で見せ、明けた瞬間に白く光る
  - 必殺技: 金の面。縁のリングにゲージがたまり、たまるまでは面をくすませる。満タンで後ろの光が脈打ち、外の輪が回り、「必殺」の文字が弾む
  - 交代: 次に出る子の顔と小さく「交代」。交代の待ち（2秒）を扇で見せ、交代できる子がいなければ灰色
  - スティック: 暗い半透明の台に白い外の輪・うすい内の輪・上下左右の矢印。つまみはつやのある白い玉
- 技ボタンは押しっぱなしにすると、待ち時間が明けるたびに出し続ける（スマホで連打しなくてよいように）
- コントローラーの表記は PS5（DualSense）に合わせる。ボタンの割り当ては場所（南・東・北など）なので、ほかのコントローラーでも動く
- 入力は共通基盤の `InputManager`（Input System）・`VirtualJoystick`・`VirtualButton` を使う

### 3.1 遊び方の画面

- ロビーの左の列の「遊び方」と、ステージ中のメニューの「遊び方」から開く（同じ画面）。「もどる」か Esc / OPTIONS で閉じる
- 上のタブで「操作」と「ルール」を切り替える（`HowToPlayScreen`）
- 操作: 「キーボード」「PS5」「スマホ」を切り替えて、§3 の表を絵で見せる。開いたときは、スマホならスマホ、コントローラーがつながっていればコントローラー、それ以外はキーボード
  - キーボード: キーの並びどおりに置く（左に WASD と矢印の逆T字＝移動、右に J K L＝技1・技2・必殺技、その下に Space＝交代、左上に Esc＝メニュー）。押しているキー・ボタンは光って少し縮む（絵を見ながら試せるように。`HowToPlayKey`）
  - PS5: PS5 コントローラーのボタンの絵（× 青・○ 赤・△ 緑の記号、L1・OPTIONS）と、何をするかを2列に並べる。光る判定はボタンの場所なので、ほかのコントローラーでも同じ場所が光る
  - スマホ: 横長の画面の絵に、ステージ中の仮想スティック・ボタンを同じ配置で縮めて描く
- ルール: 1ページに1つのことを、短い文と顔の絵で見せる（3体で戦う・技・必殺技・吹っ飛ばして連鎖・ステージの進み方・強化と上限解放・協力プレイ・ボスラッシュ・難易度と解放。文は `HowToPlayPages`。§4・§6・§7.3 を変えたらここも直す）。顔はペンモンのほか、ボスラッシュはサメ・難易度はオオフルマカモメ。◀ ▶ のほか、← → / A D / 方向キーの左右でもめくれる
  - 文は1行を枠の幅（日本語フォントで 1100）に収め、途中で折り返さない・5行まで。文字の配置の確かめ（§3.3）が全ページを枠に当てて測る
- ミニゲームの遊び方: 同じ画面を各ミニゲームのシーンにも置き、操作の絵（キーボード・PS5・スマホ）はミニゲームが描いて渡し（`CreateHowToPlayScreen` の `createPanels`）、ルールのページは起動時に差し替える（`HowToPlayScreen.UsePages`。本編の Game はミニゲームを知らないので、ミニゲームの側から渡す）。ボタンの置き場所が本編と同じミニゲーム（サッカー）は、本編の操作の絵を言葉（`ControlWords`）だけ替えて使う。ゴルフは §13.3、サッカーは §13.4、野球は §13.5 の「遊び方」

### 3.2 ステージ中のメニュー

- 遊んでいる間だけ、右上（セーフエリアの内側）に ‖ のボタンを出す。Esc / P / OPTIONS でも開け閉めできる。結果が出たら閉じる
- 中身（ゲーム専用の `StageMenu`。共通基盤の `PauseDialog` は使わない）:
  - 左: HUD と同じ斜めに切った札を上から「つづける・やり直す・遊び方・設定・タイトルへ」（緑・だいだい・青・むらさき・赤）。下の札ほど少し右へずらす。開くと左から1枚ずつ少しずらしてすべり込む（`StageMenuCard`）
  - 選んでいる札は前（右）へ出て大きくなり、後ろが金色に光って左に ▶。選んでいない札は暗くする。開いたときは「つづける」を選んでおく
  - 選び方: マウスを乗せる・方向キー / WASD / 十字キー / スティックの上下（押し続けると少し待ってから1つずつ進む）。決定は Enter / ×（南のボタン）/ クリック / タップ
  - 上の帯: 左に「‖ いちじていし」（協力は「‖ メニュー」とその下に「協力中は ゲームが止まりません」）、右にステージ名とエリアのつぶ（HUD と同じ見た目）
  - 右: 編成の3体（属性の色の丸に顔・名前・HP のバーと数）。場に出ている子は金の輪と「出ている」の札、倒れた子は灰色に×（`StageMenuParty`）。協力は開いている間も HP が動く
  - 後ろ: 暗い幕。ソロは止まった画面を1枚撮って、ぼかして敷く（`StageMenuBackdrop`。撮ってから札を出すので、出るのは1フレーム遅れる）。協力は後ろが動き続けるので幕だけ
  - 開いている間は、HUD・スマホのボタン・右上の ‖ を隠す（帯と右の欄が同じことを大きく出す。協力で後ろが透けて重ならないように）
- 「設定」を押すと、札の右に音量の板（BGM・効果音のつまみ）がすべり出る（`StageMenuVolume`）。「設定」を選んでいる札で → でも開く。キーボード・コントローラーでは上下で行・左右で 10% ずつ動かし、決定か Esc / OPTIONS で板だけ閉じる。ほかの札を選ぶと閉じる。値はタイトルの設定と同じで、板を閉じたときに保存する
- 「遊び方」は遊び方の画面を上に開く（閉じるとメニューに戻る）
- 「やり直す」「タイトルへ」は、札と同じ見た目の小さな確認の窓を出す（左上に赤い見出しの札・文・「もどる」と「やり直す / タイトルへ」の札。`StageMenuConfirm`）。最初は「もどる」を選んでおき、左右で選ぶ。Esc / OPTIONS は「もどる」。「やり直す」はソロとホストだけで、出さないときは残りの札を詰めて並べる（§8「結果の「ステージを選ぶ」はホストだけ」とそろえる）
- 閉じる: 「つづける」か Esc / P / OPTIONS（確認の窓・音量の板が出ていれば、それだけを閉じる）。札が上から順に左へ抜け、帯・右の欄・後ろの幕も薄くなる（0.2 秒ほど）。ソロは抜け終わってから動き出す。やり直し・タイトルへ・結果が出たときは、待たずにすぐ閉じる
- ソロ: 開いている間は全体が止まる（`Time.timeScale` を 0 にする）
- 協力: 止めない（ホストがすべて計算するので、1人の都合で全員を止めない）。開いている間は自分のペンモンは動かず技も出さない（その入力を「メニュー中」としてホストへ送る）。ほかの人の画面では、その人の頭の上に「P2 MENU」と出す（頭の上の文字は標準フォントの英数字なので英語）。メニュー中もやられることはある
- 協力で「タイトルへ」: ゲストは部屋から抜ける（§8 の切断と同じ）。ホストは全員がタイトルへ戻る（確認でそう伝える）
- 閉じた瞬間に技が出ないよう、開いている間に押したボタンは貯めない

### 3.3 タイトル・ロビー・設定

- タイトル: 後ろの乱戦のジオラマ（§9.6）の上に、大きなロゴと「画面をタップしてスタート」（PC は「クリック / Enter でスタート」）だけを出す。どこを押しても、どのキーでも、コントローラーの × / OPTIONS でも進む（`TitleFlow`）。押すとロゴが小さくなって上へ動き、ロビーの部品がすべり込む
- ロビー（`TitleMenu`）: まん中は後ろの自分の編成の3体が見えるよう空けておく
  - 上: 左に名前の札（編成の先頭の子の顔と自分の名前。押すと名前を変えられる）、まん中に小さなロゴ、右にコインと設定の歯車
  - 左の列: 横長のボタン（左にアイコン、右に名前。名前もボタンの中なので押せる）を縦に並べる。ガチャ・ペンモン・ミニゲーム（芝の上の旗と球の絵）・遊び方。左の端は名前の札にそろえ、ボタンどうしは少しあける
  - 右下: ストーリーのステージのカード（「ワールド 1 - 2」・ステージの名前・「★ クリア済み」か、ワールドの最後なら「大ボス出現」。◀ ▶ で選ぶ。「ひとりで遊ぶ」専用）と、「みんなで遊ぶ」（下に小さく「ボスラッシュ・ゴルフ」）「ひとりで遊ぶ」（いちばん大きいボタン）
  - 「みんなで遊ぶ」は窓を開く: 左に「部屋を作る」、右に参加コードの入力と「参加する」。右上の × か Esc / OPTIONS で閉じる。部屋を作る・参加したあとの待ち（参加コード・参加者の数・コピー・開始・キャンセル）は、ロビーを隠して窓だけを出す
  - 待ちの窓（部屋に入ったら）: 左に接続の状態（参加コード・参加者の数）、右上に遊ぶものの札（「ボスラッシュ」「ゴルフ」「サッカー」「野球」。`RoomModeSelector`）、その下に選んだ遊びの板。札はホストだけが押せ、切り替えるとゲストへ届く（`scramble.room.choice`。ゲストは見るだけで、届くまでは札も板も出さない）。ホストの選んだ遊びは、遊んで戻っても覚えている（最初はボスラッシュ）。遊びの板は差し替えられる部品（`IRoomMode`。ミニゲームは自分の板を作り、本編はミニゲームを知らない）
  - ゴルフの板（`GolfRoomPanel`）: コースの板（「コース 1」・景色の名前。◀ ▶ はホストだけ）・旗の絵と「3ホール  パー 2・3・4（合計 9）」・報酬（基本・パーより少ない打数・初回ボーナスは見ている人の記録で・順位のボーナス）。解放はホストの記録（ストーリー連動）。開いていない・準備中のコースは鍵の板（「ワールド 2 に入ると解放」/「このコースは準備中」）で「開始」を押せない。選び直すたびにゲストへ届く（`scramble.golf.choice`）。ホストの選んだコースは戻っても覚えている（最初は、開いていて遊べる中で一番先のコース）
  - ボスラッシュの板（`RushLobby`。§6.5）。ホストはステージを ◀ ▶、難易度を3つの札（ふつう 緑 / むずかしい だいだい / げきむず 赤）で選ぶ。ステージのカードには「ステージ 1」・名前・3戦の顔（1戦目の巨大ペンモン2体・2戦目の大ボス・3戦目の本気の大ボス）。選んだ難易度の報酬（「クリア報酬 210　初クリア +210」。初クリアは見ている人の記録で出す）
    - 解放はホストの記録で決める。開いていないステージは顔の上に鍵の板（「「前のステージ」をふつうでクリアすると解放」）、開いていない難易度は札が薄く鍵が付いて押せない。開いていないものを選んでいる間は「開始」を押せない
    - ホストが選び直すたびに、ゲストへ届く（`RushLobbyLink`）。ゲストは見るだけ（◀ ▶ は出さず、札は押せない。鍵も出さない）。ゲストは、つながってから「いまの選択を教えて」とホストに頼み、届くまではカードを出さない
    - ホストの選択は、ステージから戻っても覚えている（最初は、解放した中で一番先のステージの「ふつう」）
    - 結果の「ステージを選ぶ」で戻ったときは、ロビーを通らずにこの窓から（参加コード・参加者はそのまま。§8）
- 名前（共通基盤の `UserProfile`・`NameEntryDialog`）: 6文字まで。初回は決めるまで閉じられない。あとから名前の札か設定でいつでも変えられる（変えるときは「やめる」がある）。ブラウザ版は入力欄を押すとブラウザの入力ダイアログが出る（Unity の入力欄では日本語に変換できないため）
  - 名前はステージの頭の上と HUD に出る（§8・§9.4）。名前の無い席（決める前・届かなかった人）は「P1」など
- 設定（`SettingsScreen`）: 名前（いまの名前と「変更」）・BGM・効果音の音量・記録の「初期化」。音量はステージ中のメニュー（§3.2）と同じ値で、どちらで変えても同じになる。効果音のつまみを動かすと音が鳴って大きさを確かめられる。「とじる」か Esc / OPTIONS で閉じ、閉じたときに保存する
  - 初期化（最初の3体を引き直したい人向け）: 赤い「初期化」を押すと確認の窓（何が消えて何が残るか）が開く。窓の赤い「初期化する」を2回押すと確定（1回目で「もう一度押す」に変わる。間違えて消さないように）。「やめる」か Esc / OPTIONS で確認の窓だけ閉じる
  - 確定したら、コイン・ペンモン・クリア済みのステージ・無料ガチャの回数を消して初めからにする（§10）。名前と音量は残す。設定を閉じ、ロビーの上に無料ガチャが開いて、初回と同じく3回引くまで閉じられない（名前はもう決まっているので聞かない）
- ボタンの見た目（`PenmonScrambleSceneBuilder.UiParts.cs`）: 色の面（上が明るく、下に厚みの濃い帯）・上半分のつや・白い縁・下の影・文字はボタンの色を濃くした縁取り。マウスを乗せると少し大きく、押している間は縮み、押すと「ピッ」と鳴る（`UiButtonMotion`）。押せないときは全体を薄くする。文字が入りきらなければ7割の大きさまで縮める（途中で折り返したり、はみ出したりしないように）。ガチャ・ペンモン・遊び方の画面のボタンも同じ見た目
- 文字の配置の確かめ: `Tools > PenmonScramble > Check > UI Text Layout` で、開いているシーンの文字が枠からはみ出す・途中で折り返す・となりの部品に重なるところを一覧にする（実行時の日本語フォントで測る。`UiLayoutCheck`）。シーンでは空で開いたときに入る文のうち、遊び方のルールのページは全ページを、ペンモン画面（一覧・編成のカード、図鑑カード、技のタブと詳しい欄）とガチャの結果の技のカードは全種類の子の文（パワーは4桁の見本）を枠に当てて測る。文の行数より1行以上多く入る高さの枠（技の説明など）は、折り返して読ませるつもりなので折り返しは知らせない（縦のはみ出しだけ確かめる）。わざと重ねたものは知らせない（文字を丸ごと含む板・ふだんは透明で一瞬だけ光る部品・文字の板の中の層＝ボタンの面に載せた名札・文字の板が上に載っている部品＝枠の角の札）。1字の記号や名札は、字の真ん中を変えずに枠を行の高さ（字の 1.45 倍）まで広げる（`FitLineHeight`）
- 窓（設定・名前・みんなで遊ぶ・接続待ち）は、後ろを暗くして、角の丸い濃い紺の板が下から少し持ち上がって開く

## 4. ステージ中のルール

### 4.1 ペンモン3体と交代

- 編成した3体を連れていく。場に出るのは1体
- 交代ボタンを押すと、次の控えと入れ替わる（1→2→3→1 の順で、倒れた子は飛ばす）。交代した後、2秒は交代できない。押しっぱなしでは1回だけ替わる
- HP と技の待ち時間は1体ずつ。控えにいる間も待ち時間は進む
- 倒れたら、次の控えが自動で出る（このときは2秒の待ちを付けない）
- 3体とも倒れたら「ダウン」（§4.5）

### 4.2 技

- 1種類につき技は2つで固定（§5）。技1は短い待ち時間で連打できる技、技2は待ち時間が長い代わりに派手な技
- 技の属性は、そのペンモンの属性と同じ
- 技は「形」を組み合わせて作る（20種類×2＝40個の技を、少ない数のコードで作るため）

| 形 | 動き | 例 |
| --- | --- | --- |
| 近接（Melee） | 前方の扇形にすぐ当たる | パンチ・ビンタ |
| 突進（Dash） | 前へすべり、ぶつかった敵を吹っ飛ばす | 腹すべり |
| 弾（Projectile） | 前へ飛ぶ。貫通するかどうかは技ごと | 水てっぽう |
| 拡散（Spread） | 弾を扇形に複数発 | つらら3本 |
| 周囲（Nova） | 自分の周りに円形で当たる | ボディプレス |
| 設置（Zone） | 前方にしばらく残る範囲。中の敵に少しずつダメージ | うず潮 |
| 落下（Drop） | 近くの敵の頭上に遅れて落ちる | 落雷 |

- 技ごとの数値: 威力・待ち時間・範囲・吹っ飛ばす強さ（技の定義表 `Core/Penguins/SpeciesTable.cs` に持つ）
- 形ごとの細かい決まり
  - 突進: すべっている間は歩くことも別の技を出すこともできない。1回の突進で同じ敵には1回だけ当たる。飛ばされると止まる
  - 設置: 置いた瞬間と、その後の決まった間隔で中の敵に当たる。「吸い込み」の技は外へ飛ばす代わりに中心へ寄せる
  - 落下: 近い敵から順に、技ごとの数（1〜5か所）だけ狙う。落ちるまでの間（0.5〜0.7秒）は地面に赤っぽい輪を出す。近くに敵がいなければ前に1つ落とす

### 4.3 必殺技

- 敵にダメージを与えるとゲージがたまる。敵1体分の HP を削るとゲージの 1/5（5体分で満タン）。満タンで必殺技ボタンが光る
- 必殺技のダメージではゲージはたまらない（続けて出せないようにするため）
- ゲージはプレイヤーごとに1本（交代しても引き継ぐ）
- 必殺技は属性ごとに1種類（4種類）。出すときは、ペンモンの顔のカットイン（0.6秒）・画面の揺れ・ヒットストップ
  - カットインの0.6秒は、全員の画面で全体が止まる（ホストの計算ごと止める）。効き目はカットインが終わってから出る
  - 氷「ダイヤモンドダスト」: 画面全体の敵が1.5秒凍って（動けない）、溶けるときにその場で砕ける
  - 水「大つなみ」: 向いている側と反対の画面の端から大波（縦一列の大きな弾）が流れて、敵を押し流す（大ボスの闘技場では、それぞれの高さの柵から）
  - 風「大竜巻」: 自分を中心に半径5マスの大竜巻が起き、敵を強く飛ばす
  - 雷「いかずちの雨」: すべての敵の頭上と、ばらばらの4か所に、少しずつずらして雷が落ちる
- 必殺技を出してから、カットインの後3秒は、出した本人は無敵（点滅して見せる）

### 4.4 吹っ飛びと連鎖

- 技には「吹っ飛ばす強さ」がある。強く飛ばされた敵は、ほかの敵に当たるとその敵にダメージを与え、その敵も飛ばす（ピンボールのように連鎖する）
  - 連鎖するのは、速さ 6マス/秒 以上で飛んでいる敵だけ（弱い技で押しただけでは起きない）。向かっている相手にだけ当たる（隣にくっついているだけの敵には当たらない）
  - ダメージ ＝ ぶつかった速さ × 1。ぶつけられた敵はその速さの 80% で飛び（ボス・大ボスはさらに飛ばされる割合 1/4・1/10 が掛かる）、ぶつかった側は速さが半分になる（ぶつかるたびに弱まって、いつまでも続かない）
  - 1回飛ぶ間に、同じ相手には1回だけ当たる。技で倒された敵も、消える前の一瞬はぶつかる
  - 連鎖のダメージでは、必殺技のゲージはたまらず、合体技も起きない（誰の技か分からなくなるため）
  - 数値は `Balance`（`ChainMinSpeed` など）
- 壁に当たると跳ね返る（速さは 60% 残る）
- 強く飛ばされている間（速さ 1マス/秒 より上）は、歩くことも技を出すこともできない
- 計算は 1/30 秒ごとの固定の刻みで進め、画面はその間を補間して描く
- 当たり判定は円同士で、Unity の物理は使わず純C#で計算する（ホストの計算をそのまま送ればよく、テストも書けるため）

### 4.5 ダウンと復活

- 3体とも倒れたら、その場に「ダウン」の状態で残る（動けない・敵に狙われない）。灰色でつぶれて見せ、足元に復活の範囲の輪を出す
- 協力: 仲間の体がダウンした人の周り半径1.5マスにかかっている時間が、合計3秒になると復活する（離れても、ためた分は残る）。HP 30% の先頭の子で起き上がり、2秒は無敵（起きた瞬間に囲まれていて、またすぐ倒れないように）
- 全員がダウンしたらステージ失敗
- ソロ: ダウンしたらステージ失敗
- 数値は `Balance`（`ReviveRadius` など）

### 4.6 合体技（協力）

- 別のプレイヤーの技が、同じ敵に1秒以内に当たると、自動で合体技が起きる（その敵の位置で）
  - 必殺技・合体技・連鎖（§4.4）のダメージでは起きない（画面中で起き続けないため）
  - 属性は、それぞれの技を当てたときに場に出ていた子の属性。威力は2人目（合体技を起こした人）の攻撃で決める
- 合体技の種類は、2つの属性の組み合わせで決まる（数値は `Core/Penguins/ComboMoves.cs`）

| 組み合わせ | 合体技 | 効果 |
| --- | --- | --- |
| 氷＋水 | 凍結 | 半径2マスの敵を2秒凍らせる（動けない） |
| 氷＋風 | 吹雪 | 半径2.2マスに3秒、少しずつダメージを与えて足を半分の速さにする |
| 氷＋雷 | 氷晶爆発 | その場ではじけて、周り8方向へ破片が飛び散る |
| 水＋風 | うず潮 | 半径2.5マスに3秒、敵を中心へ吸い込む |
| 水＋雷 | 感電 | 3.5マス以内の近い敵から順に電気が伝わる（最大5体） |
| 風＋雷 | 雷雲 | 雷雲が4秒、一番近い敵を追いかけて0.6秒ごとに雷を落とす |
| 同じ属性 | 大ばくはつ | 半径2.5マスの範囲ダメージ＋強い吹っ飛ばし |

- 同じ敵では、1回起きたら2秒は起きない（連続で起き続けないため）
- 起きたときは「合体！○○」の文字（画面の真ん中。同時にいくつ起きても最後の1つだけ）・大きめのエフェクト・画面の揺れ・0.1秒のヒットストップ
- ソロでは起きない（合体技は協力だけの楽しみにする）

### 4.7 敵

- 雑魚: 野生のペンモン。20種類の絵を暗い色にして使い回す。技は技1だけを使う
  - 数値は種類の倍率から作る: HP ＝ HP の倍率 × 25 × 人数の倍率 × ワールドの倍率 / 攻撃 ＝ 攻撃の倍率 × 0.9 × ワールドの倍率 / 速さ ＝ 種類の速さ × 0.45 / 技の待ち時間 ＝ 技の待ち時間 × 5（`Balance` に持つ）
- ステージのボス: 強い野生ペンモン（§6.1）。同じ種類の雑魚の HP ×15・攻撃 ×1.3・大きさ ×2。技1と技2の両方を使い（待ち時間はプレイヤーと同じ ×2。雑魚の ×5 より短い）、飛ばされる強さは 1/4。頭の上に「BOSS」、画面の上の真ん中に HP のバーを出す（§9.8）
- 大ボス: 各ワールドの最後に、ペンギンの天敵（§6.2）
- 構え（雑魚とステージのボス）: 技が届く距離の 80% まで寄ったら、すぐ殴らずに構える。構えを見て歩いてよける遊びにする（ボタンは増やさない）
  - 構えの長さ: 雑魚 0.4 秒・ボス 0.5 秒（技2は 0.7 秒）（`Balance.WindUpSeconds`）。むずかしい・げきむずは難易度の倍率（0.9・0.65）を掛けて短くなる
  - 構えている間は動かず、向きも変えない。時間が来たら、相手がよけていても構えたときの向きのまま技を出す
  - 構えの途中で強く飛ばされた（速さが `StunSpeed` より上）・凍ったら、構えをやめる。待ち時間は使ったことにして、すぐ構え直さない（殴って止められる）
  - 大ボスは赤い予告（§6.2）を使うので構えない。技を持たない的（ペンモン画面の技の実演）も構えない
  - 通信: ユニットの状態に「構えている」（`UnitFlags.WindingUp`）、地面の予告に技の形・向き・届く距離・構えの長さと進み具合（`TelegraphState`）を送る
- 攻撃の順番待ち（雑魚だけ）: 囲まれても一度に殴ってくるのは数体だけにする（`StageWorld.AttackRights`）
  - プレイヤー1人に、同時に「攻撃してよい」雑魚は 2 体まで（`Balance.AttackersPerPlayer`）。ステージのボス・大ボス・技を持たない的は数えない
  - 権利は毎刻み配り直す。技の待ち時間が明けていて、凍っても飛ばされてもいない雑魚に、近い順に渡す（距離が同じなら Id の順）。構え・突進の途中は持ったまま、撃ち終えたら手放す
  - 雑魚はそれぞれ一番近い元気なプレイヤーの枠を取り合う（協力で 2 人なら 4 体まで）。ダウンした人の枠は無い
  - 権利の無い雑魚は、技が届く距離＋1.5 マスの所で止まり、歩く速さの 30% でゆっくり横へ回り込む（回る向きは雑魚ごとに違う）。近すぎたら下がる。待つ距離から 0.3 マスずれるまでは前後に動かない
- 当たった後の短い無敵: プレイヤーのペンモンは、敵の攻撃が当たってから 0.4 秒は無敵（`Balance.HitInvincibleSeconds`）。囲まれて同時に何発も当たり、一瞬で倒れないようにする
  - 必殺技・復活の無敵（§4.3・§4.5）とは別に数えるので、それより短くなることはない
  - 交代で出てきた子には引き継がない（交代して無敵のまま逃げる遊びにはしない）。倒れて次の子が出たときも同じ
  - 見た目は今の無敵と同じ点滅（§9.4）。通信では `UnitFlags.Invincible` に含めて送る
- 協力の人数で敵を強くする: 敵の HP を 1人×1.0 / 2人×1.9 / 3人×2.7 / 4人×3.4（ストーリーはひとりなので、ボスラッシュで効く。2〜4人で手ごたえがそろう値。§11）
- 先のワールドほど敵を強くする: 敵（雑魚・ボス・大ボス）の HP と攻撃を ワールド1 ×1 / ワールド2 ×2 / ワールド3 ×3.4 / ワールド4 ×6.4 / ワールド5 ×9.4（ガチャのパワーの範囲の真ん中 100 / 200 / 340 / 520 / 740 に合わせ、4・5 はその頃の編成に ★3 が混ざる分だけ上乗せする。`Balance.WorldEnemyScale`。§11 の試験で決めた）

## 5. ペンモン

### 5.1 数値

- 種類ごとの値: 属性・★・HP の倍率・攻撃の倍率・移動の速さ・技2つ
- 個体ごとの値: **パワー** ＝ 引いたときのパワー（ガチャで決まる。§7）＋ 強化で足した分（§7.3）
- HP ＝ HP の倍率 × パワー、技のダメージ ＝ 技の威力 × 攻撃の倍率 × パワー / 100（案）
- レベル上げは無い。強い個体を引くか、ほかの子を素材にして強化して強くなる（§7.3）

### 5.2 属性

氷・水・風・雷の4つ（案）。属性による有利・不利の倍率は無い。属性は、合体技の種類（§4.6）と必殺技（§4.3）を決めるだけ。

## 6. ステージ

### 6.1 ステージの形

- 横に長いマップを「エリア」（画面1枚分・16×9マス）に分けて、左から右へ進む。1ステージは5エリア＋ボスエリア（案）
- エリアに入ると出入口が閉じ、敵が2〜3回に分けて出てくる。全部倒すと開いて、次のエリアへ進める
  - 最初の波は、エリアに入って1秒後。次の波は、敵が残り2体以下になったらすぐ（全滅まで待つと間が空くため）
  - 敵はエリアの右寄りの、プレイヤーから4マス以上離れた所に出る
  - 開いたら「すすめ →」。誰か1人が次のエリアへ2マス入ると、次のエリアが始まって出入口が閉じる。遅れた人は閉じた出入口の内側へ引き寄せる
  - カメラは、出入口が閉じている間はエリアの真ん中。開いている間は、元気なプレイヤーの真ん中を追って次のエリアへ動く（縦は今のエリアの中）。闘技場の中では縦横に追う（§9.1）
  - エリアに入ったときに「エリア 2」「ボスエリア！」を画面の真ん中に出す。右上にはエリアの進み具合と残りの敵の数（§9.8）
- 各ステージの最後のエリアに、そのステージのボス（強い野生ペンモン。§4.7）。ワールドの3ステージ目は大ボス
  - ワールド4・5の1・2ステージ目のボスは、ステージのボスの代わりに**巨大ペンモン**1体（§6.4。属性の大技も使う）。巨大ペンモンのエリアは大ボスと同じ闘技場（`AreaDef.Arena`）
- **大ボスの闘技場**: 大ボスの出るエリアだけ、横 32 × 縦 18 マスの楕円（横長の丸）にする。狭い四角では、大ボスの攻撃から逃げる先がすぐ壁になるため。人数で広さは変えない。観客席は置かない。ステージのボスのエリアは、ほかと同じ 16×9 の四角
  - 前のエリアの右の出入口から、楕円の左端につながる（左端の高さは前のエリアの真ん中）。開いている間に通れるのは、つながる所（幅3マス）だけ
  - 誰か1人が楕円へ2マス入ると闘技場が始まり、戻れなくなる。外にいた人は楕円の中へ引き寄せる
  - 柵（楕円の縁）は壁と同じ。飛ばされて当たると、柵の面に対して跳ね返る（柵へ向かう速さが 60% で逆向きになり、柵に沿う速さはそのまま）
  - 敵は楕円の中の右寄りに、大ボスは楕円の真ん中に出る
  - どのエリアが闘技場かは、エリアの定義に印を付ける（`AreaDef.Arena`。巨大ペンモンの戦いなど）。大ボスがいるエリアは、印が無くても必ず闘技場（`AreaDef.IsArena`）。形と位置は `StageLayout` がステージの定義から計算する（通信で送らない。ゲストもステージの番号から引く）
  - 闘技場が続くとき（ボスラッシュ）は §6.4
- 最後のエリアの敵を全部倒したらクリア
- ステージの中身（エリアの数・波ごとの敵の数と種類・ボス）は `Core/Stage/StageTable.cs` に持つ
- 15ステージのボス: 海岸 キングス / マゼラ / **オオトウゾクカモメ**、氷山 マカロ / エレペン / **ヒョウアザラシ**、深海 ロワイヤル / ライジン / **シャチ**、嵐の崖 巨大キガシラ / 巨大シュレタ / **オオフルマカモメ**、火山の入り江 巨大オヤブン / 巨大ライジン / **サメ**（太字は大ボス。5-3 のサメがゲームの最後）
- 雑魚の種類は、先のワールドほど ★2・★3 を混ぜる（見た目にも手ごわくする）。ワールド4は ★3 を半分まで、ワールド5は ★3 だけの波も出す。大ボス・巨大ペンモンのエリアは、攻撃をよけやすいよう雑魚を少なめにする

### 6.2 ワールドと大ボス

| ワールド | 背景 | 大ボス（天敵） | 大ボスの攻撃（この順に繰り返す） |
| --- | --- | --- | --- |
| 1 海岸 | 砂浜と流氷 | オオトウゾクカモメ | 急降下（突進）→ 羽の雨 |
| 2 氷山 | 氷の洞くつ | ヒョウアザラシ | 体当たり（突進）→ 氷の下から飛び出す |
| 3 深海 | 夜の海・氷の割れ目 | シャチ | 波 → 闘技場を横切る突進 → 突進 |
| 4 嵐の崖 | 暗い灰色の岩と白い波しぶき・冷たい灰青 | オオフルマカモメ | 突風 → 動く竜巻 → 急降下（突進） |
| 5 火山の入り江 | 黒い岩と赤く光る溶岩の筋・暖かいだいだい | サメ | 背びれ → 食いつき（飛び出し）→ 突進 |

- オオフルマカモメ（104）・サメ（105）は、ストーリーの 4-3・5-3 と、開発用のステージ「新しい大ボス」（番号 99。§6.4）で戦える。ボスラッシュでも使う

- ボスの攻撃は、出る少し前（0.8〜1.1秒）に地面へ赤い範囲を出して知らせる（よけられるようにするため）。攻撃が近づくほど赤が濃くなり、出た瞬間に警報が鳴る。予告の間、大ボスは動かない
- 攻撃の形（`Core/Bosses/BigBossTable.cs`。数値もここ）
  - 突進: 一番近いプレイヤーへ向けた赤い帯 → その上をまっすぐ突っ込む。柵に当たる所で止まる（赤い帯も柵まで）。シャチの「横切る突進」は、プレイヤーのいる側へ横一直線に柵まで
  - 羽の雨: 元気なプレイヤー全員の足元と、ばらばらの場所に赤い円 → そこへ降ってくる。ばらばらの円は、ふつうのエリアの広さで3か所。広い場では広さの比の平方根だけ増やす（闘技場で5か所）
  - 飛び出し: もぐって（暗い影になる。攻撃が効かず、上を通れる）、一番近いプレイヤーの足元に赤い円 → そこから飛び出す
  - 波: 一番近いプレイヤーの高さを中心にした太さ4マスの赤い帯を、柵から柵まで → 波で押し流す。上か下へ2.5マスほど歩けばよけられる（楕円の上半分・下半分を丸ごと流すと、柵ぎわから逃げきれないため。`Balance.BigBossWaveHalfWidth`）
  - 突風（オオフルマカモメ）: ボスから一番近いプレイヤーの方へ、半径 9 マス・左右 35° の赤い扇 → 扇の中のプレイヤーを、ボスから外向きに 1.1 秒押し流す（毎秒 10 マス。歩くより速いが、逆らって歩けば流される距離が縮む。押されている間も歩けて技も出せる）。押されただけでは痛くなく、押されたまま柵に当たると1回だけ痛く、少し跳ね返って押しが終わる（`GustState`）
  - 竜巻（オオフルマカモメ）: 1つは一番近いプレイヤーの足元、残り2つは闘技場のばらばらの場所に赤い円 → 竜巻が立つ（4 秒）。巨大ペンモンの竜巻と同じに近くを吸い込み、中にいる間は削る。さらに、一番近いプレイヤーの方へ毎秒 1.1 マスでゆっくり動く（闘技場の外へは出ない）
  - 背びれ（サメ）: もぐって（攻撃が効かず、上を通れる）、一番近いプレイヤーの方へ柵の手前まで（最大 9 マス）の細い赤い線 → 背びれだけ出して毎秒 10 マスでその上を走る。触れると飛ばされる（当たるのは背びれだけなので、体の半径より細い）。走り終えるたびに向きを変え、短い予告（0.5 秒）で次の線を出して走り直す。3 回走ったら浮き上がる
  - 食いつき（サメ）: 飛び出しと同じ（円はアザラシより大きい半径 2 マス）。飛び出した後、円の縁のすぐ外に溶岩のしぶき（半径 0.9 マスのだいだいの円）が3つ残り、3 秒の間、中にいると 0.5 秒ごとに少し削られる。しぶきはよけた人が立っている所に出るので、出た瞬間には当てない（最初の 0.5 秒の間に歩いて出られる）
- 攻撃と攻撃の間はボスごとに 1.1〜1.6秒（カモメ 1.6・アザラシ 1.5・シャチ 1.3・オオフルマカモメ 1.2・サメ 1.1）。その間は、一番近いプレイヤーへ3マスの所まで寄ってくる。ここが反撃のチャンス。出てから2秒は攻撃しない
- 大ボスの HP ＝ HP の倍率 × 25 × 30 × 人数の倍率 × ワールドの倍率、攻撃 ＝ 1.5 × ワールドの倍率（技の威力に掛ける）。HP の倍率（カモメ 1.3 / アザラシ 1.2 / シャチ 1.4 / オオフルマカモメ 2.0 / サメ 2.3）と攻撃ごとの威力は、各ワールドの3ステージ目がそろった手ごたえになるよう §11 の試験で合わせた（`BigBossTable`）。飛ばされる強さは 1/10（予告の場所がずれないように）。番号は 101〜（ペンモンと重ならない）
- 大ボスは野生のペンモンではないので、暗い色にしない。頭の上に「BOSS」、画面の上の真ん中に HP のバー

### 6.3 結果

- 結果画面: 「クリア！」/「やられた…」と、倒した敵の数。ソロは「もう一度」（同じステージ）・「タイトルへ」。協力のホストは「ステージを選ぶ」（全員で待ちの窓へ戻る。§8）・「タイトルへ」。協力に「もう一度」は無い（同じものに挑むときも、待ちの窓でそのまま「開始」）
- 結果の見せ方（`ResultScreen`・`StageRunner.Result.cs`・`StageView.Result.cs`）。時間は実時間で進める
  - 決着した瞬間: BGM を止めてジングル。ソロだけ最後の一撃をスロー（0.3 倍を 0.5 秒 → 0.4 秒で戻す。協力は通信の時間とずれるのでしない）。HUD のプレート・端の印・スマホのボタンは隠す
  - 0.3 秒: 見出し（「クリア！」は金・「やられた…」は淡い青）が画面のまん中に大きく叩きつけられて弾む。クリアなら後ろで光の筋が回り、画面の下の左右の角から紙ふぶきが打ち上がる
  - 1.0 秒: カメラがペンモンへゆっくり寄り、画面の左寄りに映す（右は結果の札の場所）。同時に見出しが右の列の上へすべり、下にステージの名札が出る
    - クリア: プレイヤーはみんなカメラの方を向いて跳ねて喜ぶ（ヒレを上げて振る・3回に1回は空中で1回転。ダウンしていた子も起き上がる）。ソロは控えの2体も、先頭の子の左右の奥に煙から順に出てきて一緒に喜ぶ
    - やられた: 少し引いて、倒れた姿をそのまま映す
  - 1.5 秒から 0.55 秒おき: 右の列に札が右からすべり込み、数字が 0 から数え上がる。「倒した数」→「コイン」（コインが見出しから散って札へ吸い込まれる）→「初クリア ボーナス」（金の札。初めてのときだけ）→「「次のステージ名」解放！」（緑の札。ゆっくりふくらみ続ける。最後のステージでは出ない）。出ない札は詰める
  - 最後の札の後: ボタンが下からすべり込む。ゲストは「タイトルへ」だけをまん中に置き、下に「ホストが次のステージを選ぶのを待っています」
  - 途中で画面を押す・攻撃のボタンで、最後の姿まで飛ばす。出そろってから 0.5 秒たつと、攻撃のボタンで左のボタン（「もう一度」/「ステージを選ぶ」）
- クリア: コイン（§7）。協力では全員がもらえる
- 失敗: 倒した敵の数に応じて少しだけコイン（案）
- ストーリーのコイン: クリア 100（初めてのクリアは＋100）/ 失敗 倒した数 × 1。結果の画面に「コイン +○○」と出す
- ボスラッシュの結果は §6.5
- ステージの解放: 1ステージ目と、1つ前をクリアしたステージ。タイトルでは、解放した中で一番先のステージを最初に選んでおく

### 6.4 闘技場の連戦・巨大ペンモン・本気・難易度（ボスラッシュの土台）

ボスラッシュ（§6.5）のための仕組み。開発用のステージ「闘技場3連戦」（番号 100。`Core/Stage/DevStageTable.cs`）でも確かめられる。エディタの `Tools > PenmonScramble > Dev > 闘技場3連戦（ふつう / むずかしい / げきむず）` から、タイトルを飛ばしてひとりで遊べる。記録（クリア・コイン）には何も書かない

- 開発用のステージ「新しい大ボス」（番号 99）: オオフルマカモメ → サメ → 本気のオオフルマカモメ → 本気のサメ の4連戦（ワールド3の強さ）。`Tools > PenmonScramble > Dev > 新しい大ボス（ふつう / げきむず）` から遊べる。記録には何も書かない

- **闘技場が続く**: 前の闘技場の右端と次の闘技場の左端の間を 4 マス空け、幅 3 マスの通り道でつなぐ（`StageLayout.Passage`・`Balance.ArenaCorridorLength`）。通り道の両はしは楕円の中へ 2 マス入れて、とがった先のすき間を埋める。楕円の外に出ている所の両側には、闘技場と同じ柵を立てる
  - 勝つと右端の柵と次の左端の柵が開き、通り道が通れる。誰か1人が次の楕円へ2マス入ると次の戦いが始まり、遅れた人は楕円の中へ引き寄せる（ふつうのエリア → 闘技場と同じ）。大ボスはいつもどおり空から降りてくる
  - 最初のエリアが闘技場なら、始まりの四角を置かず、最初から闘技場（楕円の真ん中が原点）の左寄りに立って始める
- **戦いの合間**: 闘技場で勝って次のエリアがあるときは、真ん中に「ROUND CLEAR!」。元気な子（控えも）はそれぞれ最大 HP の 30% 回復（最大を超えない）、ダウンしていた人は先頭の子を HP 30% で起こす。倒れた控えは起こさない（3体で粘った分の得を残すため）。次の闘技場に入るまで敵は出ない
  - 闘技場が2つ以上あるステージでは、入ったときの知らせが「ROUND 2」になる。闘技場の戦いの間は、どの戦いもボスの曲
- **巨大ペンモン**（`BossRank.Giant`・`SpeciesTable.GiantStats`）: ステージのボスをさらに大きく（半径 ＝ ペンギンの 3 倍）・硬く（ステージのボスの HP × 1.6。案）する。飛ばされる強さは大ボスと同じ 1/10。技の待ち時間はステージのボス（×2）より長い ×3.5（大技も出すので。拡散の技が 1 秒おきに飛んでくると、大技をよける余裕が無くなるため。`Balance.GiantCooldownScale`）。技1・技2で戦いながら、6 秒おき（最初は出てから 3 秒）に、大ボスと同じ赤い予告の大技を属性ごとに1つ出す（`Core/Bosses/GiantAttacks.cs`。予告の間は動かない。ふつうの技を構えている途中には出さない）
  - 氷: つらら（羽の雨と同じ形。足元とばらばらの場所。予告 1.0 秒）
  - 水: 横一列の波（シャチの波と同じ形。予告 1.1 秒）
  - 風: 竜巻。1つは一番近いプレイヤーの足元、残り2つはばらばらの場所に赤い円（予告 1.0 秒）→ 3 秒残る竜巻（`AreaEffectKind.Vortex`）。円の 1.6 倍の範囲にいる相手を、毎秒 2.2 マスで中心へ寄せる（吹っ飛ばさないので、歩けば抜け出せる）。円の中にいる間は 0.5 秒ごとに少し当たる。床には赤みを混ぜた属性の色の円で出す
  - 雷: 稲妻の帯。足元から一番近いプレイヤーの方へ、柵まで届く幅 2.2 マスの赤い帯（予告 1.0 秒）→ ボスは動かず、帯に稲妻が走る
  - 2体組は、大技を1体ずつ交互に出す（もう1体が予告している間は出さない・前に出したのが自分なら、もう1体の番）
  - 2体以上のボスを同じ波で出すときは、真ん中から縦に 4 マスずつずらして置く
- **大ボスの本気**（`BossRank.Serious`）: 頭の上の札が「BOSS」ではなく「本気」、体の縁から赤い湯気が立ちのぼり続ける。HP が半分を切ると一度吠える（全体が 0.5 秒止まり、まわりへ輪が広がって画面が大きく揺れる）。吠えた後は、予告が 2 割短く・休みが 3 割短くなり、攻撃が1つ増える（`BigBossDef.Rage`。案）。赤い湯気も濃く・速くなる
  - オオトウゾクカモメ: 羽の雨が休まずに2回続けて降る / ヒョウアザラシ: 飛び出しが休まずに3回続く / シャチ: 波が2本同時（2本目は1本目から帯の太さ＋1.6 マス離して、闘技場の真ん中寄りへ。間に立てばどちらにも当たらない）
  - オオフルマカモメ: 竜巻が2つ増えて5つ / サメ: 背びれが2本（2本目は1本目の線から 40° 開いた線を、同時に同じ速さで走る。走り直すたびに2本とも出る）
- **難易度**（`Difficulty`: ふつう / むずかしい / げきむず。`Balance.Difficulty.cs`）: 敵（雑魚・ボス・大ボス）の HP ×1 / ×2 / ×3.5、攻撃 ×1 / ×1.6 / ×3、雑魚とボスの構え・大ボスと巨大ペンモンの赤い予告の長さ ×1 / ×0.9 / ×0.65。げきむずは予告をぐっと短くして、予告を見てよけきれる人にも手ごたえを残す（§11 の試験で決めた）。ストーリーはいつも「ふつう」

- 闘技場の見た目（コロシアム）: 床は石の円形の舞台の絵（`Art/Stage/Colosseum.png`。1枚を5ステージで使い、ステージのワールドの色を掛ける。絵が無ければストーリーの闘技場の床で代わりにする）。柵は太い石の柱・平たい石の笠・低い石の壁で、奥の柵の4本に1本へ竿を立て、ワールドの2色の旗を交互に下げる。手前の柱は奥より低くする（足元を隠さないため。`ArenaFenceStyle.Colosseum`）

## 7. ガチャ・コイン・コレクション

- コイン: ステージの結果でもらう（§6.3）
- ガチャ: 1回100コイン（案）。最初の3回は無料（設定の「初期化」で記録を作り直すと、また3回無料）
- ★の出る確率: ★1 70% / ★2 25% / ★3 5%（案）
- パワー: 引いたときに範囲内でランダム。範囲は、解放したワールドが多いほど上がる（案）
  - ワールド1まで: 80〜120 / ワールド2まで: 160〜240 / ワールド3まで: 280〜400 / ワールド4まで: 430〜610 / ワールド5まで: 610〜870（§11 の試験では変えず、敵の倍率の方で合わせた）
  - ★2 は ×1.2、★3 は ×1.5
- 同じ種類がかぶったら、別の個体として増える
- 持てるのは100体まで（案）。いっぱいのときはガチャを引けない。いらない個体はコインに換えられる（★1: 10 / ★2: 30 / ★3: 100。案）
- 編成で選んでいる3体は換えられない。売るボタンは2回押しで確定（間違えて売らないように）
- 数値は `Balance.Collection.cs`（強化は `Balance.Growth.cs`）

### 7.1 ガチャ画面

タイトルの「ガチャ」から開く（初回は名前を決めた後に自動で開く。§2）。画面いっぱいに3Dのガチャの部屋を映す（`Menu/GachaScreen`・`GachaStage`）。

- 3D: ペンギンと同じトゥーンの形で組んだガチャマシン（ピンクの丸い胴・ガラスの丸い窓にカプセルがたくさん・金のふた・前の左にレバー、右に取り出し口・星の飾り）と、マシンの右手前の台。奥に星が浮かび、マシンを後ろから照らす。3Dの空間の離れた所に組んで、専用のカメラで撮る（開いている間だけ描く）
- 画面: 左上に「もどる」と見出し、右上に持っている数（ペンモン 37/100）とコイン、右下に「確率」と「1回引く（100コイン）」（無料の回が残っていれば「無料で引く のこり N 回」）。無料の回を引き終わるまでは「もどる」を出さない（最初の3回は必ず引いてもらうため）
- 引く流れ:
  1. レバーが1回転する（1/4 回るごとにカチッ。窓の中のカプセルがかき混ざる）
  2. 取り出し口からカプセル（水色とだいだい・白い合わせ目）が飛び出し、はねながら転がって台に止まる。その間にカメラが台へ寄る
  3. カプセルがだんだん大きく3回揺れる
  4. ★3 だけ: 部屋が暗くなり、台から金の光の柱が立つ（ここで当たりと分かる）
  5. カプセルが★の色に光る（★1 白 / ★2 水色 / ★3 金）→ ★が1つずつ出る（後ろの光もそのたびに大きくなる）
  6. 殻が上と下に割れて飛び、煙とコイン・星がはじけて、ゲーム中と同じ3Dの子が飛び出す。弾みながら1回転して正面を向き、そのあとは技1・技2のポーズを順にくり返す
  7. 右から結果のカードがすべり込む: ★・名前・属性・個性・パワーと HP・技2つ（技のカード: 形のアイコン・名前・［形・特徴］と一言の説明・3段階の●。文はペンモン画面の技の欄と同じ `SkillTexts`）。まだ持っていなかった種類なら金の「NEW!」の札
- 演出の間は画面のどこを押してもとばせる（「タップでスキップ」）。とばすと、出てきた子が台に立ってカードが出た所になる
- もう一度引くと、台の子は煙で消えて、カメラがマシンの前に戻ってから始める
- 「確率」の窓: ★ごとの確率と1種類あたりの確率・その★の子の名前・今引いたときのパワーの範囲（`Balance` と `SpeciesTable` から作る）

### 7.2 ペンモン画面

タイトルの「ペンモン」から開く。持っている子を見て、編成の3体を決める画面（`Menu/PenguinListScreen`）。

- 左上: 編成の帯。色の付いた帯に「編成」と3枠を並べ、一覧より大きく出す。1番目の枠の上には「先頭」の札（ステージで最初に場に出る子。枠の中の文字にかぶらないよう、枠の外に置く）
- 左下: 持っている子の一覧（4列・縦にスクロール。パワー順 / 番号順 / 新しい順）。カードは顔・★・名前・パワーと、下に属性の色の帯（★・名前・パワーは1行ずつ。長い名前や桁の多いパワーは、その行だけ字を縮めて枠に収める）。編成にいる子は左上に編成の番号（1〜3）の金色のバッジを付け、縁の色も変える。上限解放した子は顔の下に小さな◆（1回も解放していない子には出さない。一覧が◇だらけにならないように）
- 右: 選んだ子の図鑑カード（`PenmonDetailPanel`）
  - 顔・★・名前・属性の札・個性（§5.3）・パワー（小さく上限）と HP。顔の下に上限解放の◆（◆◆◇◇。解放した分が金）
  - 体力・攻撃・速さの棒（見出しと棒を横に並べて1段。20種類の中でどのくらいか。いちばん低い種類でも棒の 2 割は出す。`SpeciesProfile`）
  - 技の実演の小窓: 選んだ技を、本番と同じ計算（`SkillPractice`）で動かして見せる。動かない的3体（★1 の水・風・雷の子。暗い色）に向かって「構える → 出す → 収まるのを待つ → 元の位置へ戻る」をくり返す。待ち時間 0.5 秒以下の技は 1.6 秒押しっぱなしにして連打を見せる。ダメージの数字はその個体の本当の値。的は倒れない。音は出さない・揺らさない
  - 小窓の下に、技1・技2・必殺技のタブを横に3つ（`SkillTabView`）: 形のアイコン（属性の色）・「技1」などの見出し・名前だけを出す。押すと実演と下の詳しい欄がその技に替わる。別の子を選んでも、見ている技（技1・技2・必殺技のどれか）はそのまま。必殺技のタブはステージの必殺技ボタンと同じ金の面（アイコンも金）
  - タブの下に、選んでいる技の詳しい欄（`SkillDetailView`）: ［形・特徴］・一言の説明・威力／出しやすさ／範囲の3段階（●）。1つの技だけを出すので字を大きくする。選んでいるタブと同じ色の面にして、つながって見せる
  - 必殺技の詳しい欄: ［ゲージ満タンで1回］と一言の説明・威力（●）と範囲（「全体」/ 風は「半径5」）。出しやすさはゲージで出すので出さない。範囲は画面全体に効くものがあるので、●ではなく言葉にする
  - 必殺技の実演: 毎回ゲージを満タンにしてから出す。場を小窓に映る広さと同じにして、大波・雷などの効き目が全部小窓に入るようにする。カットインの 0.6 秒は本番どおり実演の場が止まり、小窓の中に小さな帯（顔と技の名前）が出る。音は出さない・揺らさない
  - 下に「編成に入れる」「強化」「売る」
- 編成のしかた: 一覧か枠の子を選ぶ →「編成に入れる」（もう編成にいる子なら「並びを変える」）→ 3枠が光るので、入れたい枠を押す。もう編成にいる子なら入れ替える。光っている間にもう一度ボタン（「やめる」）を押すか、別の子を選ぶとやめる
- 技の3段階の目安（`SkillProfile`）。形ごとに数値の意味が違うので、直してから比べる
  - 威力: 1回出したときに1体へ与えるおおよその威力。設置は「当たる回数 × 0.35」を掛ける。12 以上で2、26 以上で3
  - 出しやすさ: 待ち時間 0.5 秒以下で3、2.5 秒以下で2、それより長いと1
  - 範囲: 当たる床のおおよその広さ（マス²）。3 以上で2、9 以上で3
- 技の説明と個性の文は `Core/Penguins/SpeciesTexts.cs`（数値の表と分けて、文だけ直せるようにする）

### 7.3 強化・上限解放

ペンモン画面の「強化」から、選んだ子の強化の窓を重ねて開く（`Menu/EnhanceScreen`。計算は `PlayerRecord.Enhance.cs`、数値は `Balance.Growth.cs`。数値はすべて案）。

- 素材: どの子でも1〜10体まとめて素材にできる。素材にした子は居なくなる。編成の3体と強化する子自身は素材にできない
- 1体ごとに上がるパワー ＝ 素材の★の基本値（★1: 8 / ★2: 20 / ★3: 50）＋ 素材のパワー × 10%
- 上限 ＝ 引いたときのパワー × (1.5 ＋ 0.25 × 上限解放の回数)。最大 ×2.5。上限を超える分は捨てる
- 上限解放: 同じ種類の子を素材にすると、1体につき上限解放が1回増える（最大4回）。上限解放を先に数えてから上限を決める（同じ種類と一緒に入れた素材の分も、上がった上限まで入る）。4回解放した子に同じ種類を入れても、パワーは上限まで足す
- コイン ＝ 素材1体につき、強化する子の今のパワー × 0.5。足りなければ押せない
- 何も変わらない（上限まで上がっていて、上限解放もできない）ときは押せない（「上限に達しています」）
- ★3 や、強化する子より強い子を素材に入れたときは、売るのと同じ2回押し（「本当に強化する？」）
- 窓の中
  - 左: 強化する子の顔・◆・★と名前・「パワー 150 → 182」・ゲージ（今のパワーの上に、強化後まで伸びる分を明るい緑で重ねる。全体が強化後の上限）・「上限 225 → 262 上限UP！」・「上限まで あと ○」（あふれるときは赤で「上限をこえる ○ はむだになります」）。これから灯る◆は明滅する
  - 右: 素材を選ぶ一覧（一覧と同じカード）。並びは 素材にできる同じ種類 → 素材にできる子 → 編成の子、それぞれ弱い順。編成の子は暗く押せない（番号のバッジつき）。同じ種類の子には顔の上に金の「上限UP」の札。押すと選ぶ／外す。「選び直す」で全部外す
  - 下: 案内の一言・必要なコイン・「強化する」
- 強化した瞬間（どこを押してもとばせる）: 素材の顔がカードの位置から強化する子の顔へ吸い込まれる → 顔が光ってふくらむ → パワーの数字が数え上がる → 上限解放なら◆が1つずつ金に灯る
- 強化した直後（演出の前）に保存する

## 8. オンライン

- 共通基盤の `OnlineSession`（Unity Relay・参加コード・最大4人）を使う。ブラウザでもつながるように、通信は WebSocket
- Unity のプロジェクトを Unity Gaming Services の Project ID にリンクし、ダッシュボードで Relay を有効にしておく必要がある（Project Settings > Services）
- つながらなかったとき: ふつうは「接続できませんでした / コードや通信状況を確認してください」。サービスの準備ができていない（リンクしていないなど、プレイヤーには直せない）ときは「いまはオンラインで遊べません」と出し分ける（`ModeSelectPanel`）
- **ホストがすべて計算する**: ゲストは入力（移動の向き・押したボタン）だけを、変わったときに送る。ホストは純C#のステージ計算を進めて、全員の位置・HP・起きたこと（技・合体・撃破）を毎秒15回（計算2回に1回）送る
- ゲストの画面は、届いた位置の間を補間して描く。ホスト・ソロの画面も同じ「スナップショット」から描く（描き方を分けない）
- 遊ぶもの: オンラインはボスラッシュ（§6.5）とミニゲームのゴルフ（§13.3）・サッカー（§13.4）・野球（§13.5）。待ちの窓の札の並びはボスラッシュ・ゴルフ・サッカー・野球。ホストが待ちの窓の札で選んだ遊び（`scramble.room.choice`）と、その遊びの選択（ボスラッシュのステージと難易度 `scramble.rush.choice`・ゴルフのコース `scramble.golf.choice`・サッカーのスタジアムと遊び方と席の赤・青 `scramble.soccer.choice`・野球の球場と遊び方と席の赤・青 `scramble.baseball.choice`）を、ゲストへ名前付きメッセージで送る。どれもゲストが部屋に入ったら `〜.ask` で頼む形（ホストから先に送ると、ゲストの受け取る準備より先に届いて捨てられることがあるため。共通の `RoomChoiceLink`）。遊ぶステージ・コース自体はスナップショットで届く
- 開始したら、全員の端末で選ばれた遊びに始め方を聞く（`RoomModeSelector.StartElsewhere`）。ボスラッシュは本編のシーンの中で始める。ミニゲーム（ゴルフ・サッカー・野球）は全員がそのミニゲームのシーンへ移る（部屋は試合ごと次のシーンへ引き継ぐ。下の「別のシーンへ移る」）
- ホストひとりでも「開始」できる（共通基盤の `ModeSelectPanel` の「開始できる人数」を 1 にする。`OnlineSession.StartMatch(allowAlone)`）
- 席: ホストが P1、ゲストは参加順に P2〜P4。足元の席の色の輪と頭の上の名前で見分ける
- 名前: 部屋に入ったときに各自の名前をホストへ送り、ホストが「開始」で全員分を配る（共通基盤の `OnlineSession`・`SeatNames`）。届かなかった人は「P2」など
- 結果の「ステージを選ぶ」はホストだけが押せる。押すと全員が部屋をつないだまま待ちの窓（§3.3）へ戻り、ホストがステージと難易度を選び直して「開始」する。ゲストは自動でついていく。「タイトルへ」を押すと部屋から抜ける（ホストなら全員タイトルへ）
  - 戻り方: ホストが名前付きメッセージ（`session.room`）でゲストへ知らせ、全員がタイトルへ戻るのと同じくシーンを読み直す。部屋（参加コード・参加者・名前）は共通基盤の `OnlineSession` が読み直しの間だけ預かって、新しいシーンへ引き継ぐ（`OnlineSession.ReturnToRoom`。画面を作り直すのはシーンの読み直しに任せ、部屋だけを残すため）。席は次の「開始」で配り直す
  - 読み直している間に落ちた人: ゲストはそのまま部屋から外れる。ゲストから見てホストが落ちていたら、部屋を引き継がずにロビーへ
  - 待ちの窓での選択のやり取りは最初に入ったときと同じ（ゲストが頼み、ホストは窓を開いたときにも送る。どちらが先に読み直し終わっても届く）
- 別のシーンへ移る（ミニゲーム）: 開始の後に `OnlineSession.CarryMatchToNextScene` を呼んでからシーンを移ると、部屋・参加者・名前に加えて試合中のまま（席番号・人数）次のシーンの `OnlineSession` へ引き継ぐ（待ちの窓へ戻るときと同じ預け方）。移っている間に抜けた人は、ホストの引き継ぎで席から外す（`ConnectedSeats`）。ゲストから見てホストが落ちていたら引き継がず、ゲームはロビーへ戻る。移った先の受け口がそろうまでに届いたメッセージは捨てられるので、移った先で「準備できた」をやり取りしてから始める（§13.3・§13.4・§13.5）
  - 試合中の通信路はミニゲームで共通の `MiniGameLink`（名前のもとに `.snapshot`（ホスト → 全員）・`.input`・`.ready`（ゲスト → ホスト）を付けた名前付きメッセージ。ゴルフは `scramble.golf`、サッカーは `scramble.soccer`、野球は `scramble.baseball`）。中身は各ミニゲームの Core の Codec
- 遅れが気になったら、自分の移動だけ手元で先に動かす（後で判断。未定）
- 編成: ゲストは開始時に自分の3体（種類・パワー）をホストへ送る。ホストは全員の分がそろうか、3秒たったら始める（届かなかった人は仮の3体）
- 切断: ゲストが落ちたら、そのプレイヤーは消える（残りで続ける。次の「開始」からは残りの人数で敵の HP を決める）。ホストが落ちたら全員タイトルへ戻る
- 報酬は各自の端末で保存する（ホストから「クリアした」と届いたら、自分の記録に書く）
- スナップショットの頭には、ステージの番号（1 バイト。ボスラッシュは 101〜105）・難易度・いまの闘技場が何戦目か・勝った戦いの数を入れる（ゲストの HUD・結果・報酬に使う）。ユニットの見た目の印（`UnitFlags`）は 2 バイト（本気・吠えた後を足したため）

## 9. 見た目と演出

### 9.1 描き方

- ステージは3Dで描く。Core は床の上の2D（x が右、y が奥）のままで、Core の (x, y) を3Dの床の (x, 0, y) に置くだけ（`CoreConversions.ToFloor`）。スナップショットも変えない
- カメラ: 透視・斜め上から見下ろす（55°・画角 30°）。エリア（16×9マス）と奥のペンモンの頭までが画面に収まるように、画面の縦横比に合わせて構える（`StageCamera`・`AreaCameraFit`）。引くときは向きを変えずに距離だけ伸ばす（床に映る広さがそのまま倍になる）。前後の重なりは奥行きで決まる。半透明の演出どうしの順番だけ `SortingDepth`（床の範囲 → はじける演出・光 → 文字）
- 闘技場のカメラ（`StageView.Camera.cs`・`CameraFraming`）
  - 元気なプレイヤー（ダウンしていない人）をみんな映す真ん中を、縦横に追う。協力で離れたら、端から 1.5 マス空けて映せるだけ引く。ただし 1.3 倍まで（スマホの横画面でペンモンが小さくなりすぎないように）
  - 映す範囲は闘技場（楕円を囲む 32×18 の四角）の外へ出さない（暗い床を映しすぎないように）
  - 入ったとき: カメラがゆっくり引いて闘技場の全体（2倍）を見せ、まん中に大ボスが空から降りてくる（§9.3）。着いてから 1.2 秒見せたら、プレイヤーへゆっくり戻る（大ボスが出てこなくても 4 秒で戻る）。「ボスエリア！」の知らせは同じ
- 陰影: トゥーン調（明るい・影の2段＋小さなつや・縁を少し明るく・縁の暗い線。`Shaders/Toon.shader`）。太陽は左上の奥から1つ。影はどの環境も足元の丸い影（本物の影は使わない。立ち位置が分かりやすく軽い）
- 画質（`RenderPipelineSetup`。Rebuild とビルドの前に毎回そろえる）: URP。縁の線はどの環境もあり（線だけを不透明の後にまとめて描く）。MSAA はスマホ・ブラウザ 2、PC 4。スマホは毎秒60回、PC は垂直同期、ブラウザは画面の書き換えに合わせて描く
- 重さを測る: `StageBenchmark`（ボット4人で場面ごとに測る。`Tools/PenmonScramble/Benchmark/*`）。どの端末でも毎秒60回（ブラウザは画面の書き換えに合わせて）を保つのが目安
  - 場面: 1エリアの敵が一番多い所（よけないボットに強めの3体。20 秒）と、ボスラッシュの闘技場で床に出るものが多い3戦（103 の風の巨大ペンモン2体＝竜巻・104 の本気のオオフルマカモメ＝吠えた後は竜巻5つ・105 の本気のサメ＝背びれ2本と溶岩のしぶき。うまい人のボットに、ふつうに挑む人の編成。吠えた後まで入るよう 30 秒）
  - 場面はステージの1エリアだけを切り出して回す。床・柵・カメラは番号から引かず、その切り出した定義で組む（`StageView.StageOverride`。闘技場が四角に描かれないように）
- 形はすべてコードで作る（`ToyMeshes`: 球・卵形・しずく・角の丸い円柱・輪・星・氷の塊）。当たり判定（Collider）は付けない（当たりは Core が持つ）

### 9.2 ペンモン

- 球・卵形を組んだおもちゃのペンギン: 胴・白いお腹・顔・目・くちばし・ヒレ2枚・足2本・頭の寝ぐせ（`PenguinModelBuilder`）
- 20種類の見た目は定義表 `PenguinLooks`（Game 側。Core の `SpeciesTable` とは分ける）: 色（背中・お腹・くちばし・足・顔・ヒレ・ひとみ）・体型（太さ・背の高さ・頭の大きさ）・目の形・飾り（題材のペンギンの模様と個性の小物。`OrnamentKind`）。属性は飾りの色で分かる（氷は水色・水は青・風は緑・雷は黄色）
- 大きさは当たりの円に胴の太さをそろえる。ステージのボス（大きい野生のペンモン）は、ペンモンを大きくして使う
- 動きはコードでつける（`PenguinMotion`。数値は同じファイルの定数）。物理演算は使わない
  - 立っている: ゆっくり呼吸、2〜5秒ごとにまばたき
  - 歩く: 体を左右に揺らして足を交互に出す。速いほど揺れも速い。進む向きへなめらかに回る
  - 技（§4.2 の形ごと）: 近接は体をひねってヒレで払う・弾は振りかぶって投げる・突進は深くかがんで飛び出し、お腹ですべる・拡散はヒレを交差させてから開く・周囲はヒレを広げて1回転・設置は跳んで踏みしめる・落下はヒレを空へ上げて振り下ろす
  - 必殺技・合体技: 大きくかがんで跳んで1回転、着地でつぶれる
  - 被弾: のけぞって震える
  - 吹っ飛び: 飛ばしてきた側へ向き直り、後ろへ転がりながら弧を描いて飛ぶ。弱いとのけぞってすべるだけ。速度はスナップショットに無いので、当たった直後に歩くより速く（6マス/秒〜）動いていたら吹っ飛びとみなす
  - ダウン: お腹を下にして倒れ、ヒレと足をじたばたさせる
  - 撃破: 後ろへのけぞりながら回って昇り、小さくなって消える
  - 喜ぶ（クリアの結果）: かがんで跳ね、ヒレを上げて振り、着地でつぶれるのを繰り返す。3回に1回は空中で1回転。並んだ子は始まりを少しずらす（`PenguinMotion.Cheer.cs`）
  - 両ヒレで持って振る（ミニゲームのゴルフのクラブ）: 少し前かがみになってヒレを体の前で合わせ、振る角度に合わせて体を少しひねり、ヒレも振る。頭は逆へ回して前の物を見続ける。持つ物そのものは使う側が胴に付けて同じ角度で回す（`PenguinMotion.Hold.cs`）
  - 頭を抱える（ゴルフで池に落ちた）: ヒレを頭の上まで上げて前へ寄せ、うなだれて首を横に振る

### 9.3 大ボス

- 形がペンモンと違うので、体ごとに組み立てる（`BigBossModelBuilder`・`BigBossMotion`）。大きさは当たりの半径に合わせる。暗い色にしない。頭の上に「BOSS」
- オオトウゾクカモメ: 茶色の海鳥。いつも宙で羽ばたく（足元の丸い影が当たりの位置）。急降下の予告で高く上がって翼を振り上げ、突進中は翼をたたんで床すれすれを飛ぶ。羽の雨の予告で胸を張って激しく羽ばたき、出た瞬間に翼を打ち下ろす
- ヒョウアザラシ: 灰色にヒョウ柄。体をくねらせ前ヒレでこいで這う。体当たりの予告で胸を起こし、口を開けて歯を鳴らす。もぐると床の下へ沈み、暗い影が波紋を立てながら飛び出す場所へ進む（見た目だけ。Core の位置は飛び出すまで変わらない）。出るときは口を開けて床から飛び出す
- シャチ: 黒と白・高い背びれ。尾を上下に振って泳ぐ。波の予告で尾を床に残して体を起こし、出た瞬間に打ち付ける。突進の予告で身を引いて尾を速く振り、口を開けて突っ込む
- オオフルマカモメ: 灰色の大きな海鳥。太いくちばし（先が黄色・上に鼻の管）と長い翼。カモメより低く浮き、小さくゆっくり羽ばたいて滑空する。突風の予告で胸を起こし、翼を前へ振りかぶって口を開け、出た瞬間に翼を前へあおぐ（扇の中に緑の風の輪が並ぶ）。竜巻の予告で体を左右にひねって激しく羽ばたく。急降下はカモメと同じ
- サメ: 青灰色・白いお腹・大きな背びれ・上が長い縦の尾びれ・えらの筋・丸い歯。尾を左右に振って泳ぐ（シャチと見分ける）。もぐると水平に沈み、背びれだけを床の上に出したまま向きを変えて走る（足元に暗い影と波紋）。突進の予告で浮き上がって鼻先を上げ、大口を開ける。本気の2本目の背びれは、同じ色の背びれが白い泡の輪を連れて床を走る（`EffectView`）
- 闘技場に現れるとき: 画面の上の外から回りながら落ちてきて、着地で大きくつぶれる（1秒。床に着くのは 0.6 秒）。落ちる間は足元の影が小さく、近づくほど大きくなる。「BOSS」の文字は着いてから出す。着いた瞬間に床が揺れ、白い輪が広がり、重い音が鳴る
- どの攻撃を構えているかは、赤い範囲が持っている攻撃の種類から読む（`BossWarning.Kind` をスナップショットでも送る。`BigBossTelegraph`）。範囲が消えた瞬間が攻撃。突風の扇は扇の形の赤で描く（`WarningView`）
- 本気（§6.4）: 頭の上に赤い「本気」。体の縁から小さな赤い煙が 0.28 秒ごとに立ちのぼる（吠えた後は 0.12 秒ごと）。もぐっている・降りてくる間は出さない

### 9.4 状態の見た目

- 野生のペンモン（雑魚・ステージのボス）: 同じ形を暗い色で
- プレイヤー: 足元に席の色の輪。頭の上に席の色で名前（無ければ「P1」など）。長い名前は横に広がりすぎないよう小さくする。字は UI と同じ丸ゴシック（日本語の名前も出せるように）
- 被弾: 一瞬（0.1秒）白く光る
- 凍る: 水色になって半透明の氷の塊に包まれ、動きが止まる。凍ったまま飛ばされると、転がらずに塊ごとすべる。溶けると氷が砕けて飛び散る
- ダウン: 灰色で倒れる。足元に復活の範囲とたまり具合（§4.5）
- 無敵（必殺技・復活・当たった直後。§4.7）: 点滅（足元の丸い影と輪は残す）。どの無敵かは見分けない
- 突進: 半透明の残像
- 構え（雑魚・ステージのボス。§4.7）: 体がぷくっと膨らんで小刻みに震え、白く脈打つ（脈は数段に丸めて、色ごとの素材を増やしすぎない）。地面には、淡いクリーム色のうすい予告を出す（`TelegraphView`）: 近接は扇、周囲は自分のまわりの円、拡散は弾が広がる扇、弾・突進は向きの帯、設置は置く場所の円（落下は技が出てから落ちる場所の予告が出るので、構えの間は出さない）。うすい下地の上に、技が出るまでに中から満ちていく面を重ねる。何体も同時に構えるので、大ボスの赤い予告より淡く薄くする
- 交代・ダウン・起き上がり: 白い煙がぽんと出る。交代した子は小さく出てから弾んで元の大きさになる

### 9.5 技の見た目

- 床に出すもの（設置の円・落下の予告・大ボスの赤い予告・構えの予告・近接のはじける丸・席の輪・復活の範囲）は床に寝かせた板（`FloorDecal`・`DecalSprites`）
- 近接は前に丸がはじける。周囲は床の輪が広がって光る。設置はうっすらした円。落下は落ちる場所の赤っぽい輪 → 落ちたら丸がはじける。合体技は床の輪と光＋胸の高さに光
- 弾: 属性の色の小さな球のまわりが光り、床に丸い影。敵の弾は暗い色で光も弱い
- 頭の上の文字・ダメージ数字: いつもカメラの方を向き、ほかの物に隠れない
- 敵を倒すと、コインと星が上へはじけて弧を描いて落ち、床で1回はねて消える。ボスは多く広く
- 演出用の素材は `StageMaterials` で使い回す（光の当たらない半透明 `Shaders/Fx.shader`）

### 9.6 UI の顔・地面・タイトル・アイコン

- 一覧・ガチャ・カットインの顔: Rebuild のたびに、ゲーム中と同じ3Dのペンモン20種類と大ボス5体を撮って `Art/Portraits/Penguin01.png`〜`Penguin20.png`・`Boss101.png`〜`Boss105.png` を作る（`PenmonScrambleSceneBuilder.Portraits.cs`・`CreatureArt`）。少し斜め前から（顔は右向き）・背景透過・512×512。ペンモンはどの種類も同じ大きさで足元をそろえ（体型の違いが分かるように）、大ボスは体に合わせて目いっぱいに撮る。生成物なので手で直さない（見た目は `PenguinLooks` / `BigBossModelBuilder` を直す）
  - 撮る間はシェーダーの裏読み込み（非同期コンパイル）を止め、先に空撮りして準備させる（準備が間に合わないと仮の水色一色で撮れるため）。それでも写っている所の半分より多くが同じ色なら撮り損ねとみなし、書き込まずに前の絵を残して警告を出す。アプリのアイコンも同じ
- 地面: `Art/Stage/World1.png`〜`World5.png`（ComfyUI。1344×768。プロンプトは `Tools/Art/gen.py`）を、1エリア（16:9）に引き伸ばしてトゥーンの床の板に貼る。1つおきに少し暗く、ボスエリアは赤っぽく色を掛ける。横長の画面で映るエリアの外には、同じ絵を暗くして敷く。エリアの境目の出入口は床に置いた低い柵（`StageTheme`）
- 大ボスの闘技場: 楕円に切った床に、ワールドごとの闘技場の絵 `Art/Stage/Arena1.png`〜`Arena5.png`（ComfyUI。1344×768。楕円を囲む四角に引き伸ばして貼る）。海岸＝砂の闘技場・氷山＝氷のリンク・深海＝割れた氷の舞台・嵐の崖＝しぶきに濡れた石の舞台・火山の入り江＝細い溶岩の筋が光る黒い石の舞台（溶岩は赤い予告の範囲と紛れないよう細く暗く）。絵が無ければワールドの地面を赤っぽくして敷く。楕円の外は暗い床
  - ワールド4・5の地面・闘技場の絵がまだ無いときは、前のワールドの絵を借りて色を替えて敷く（嵐の崖＝氷山の絵を灰青に、火山の入り江＝海岸の絵を暗い赤茶に。`StageTheme.FallbackArtWorld`）
  - 柵: 楕円の縁に沿って、丸い柱（1.1 マスおき）・柱の上の玉（1本おきに2色）・柱をつなぐ太い横木を並べる、おもちゃらしい柵（`ArenaFence`。色はワールドごとに `StageTheme`）。実行時に作り、部品の種類ごとに1つのメッシュへまとめる。入口（前のエリアからの通り道）にかかる柱は、入口が開いている間だけ消える
- タイトル画面: 後ろでゲーム中と同じ3Dのペンモンが乱戦し続けるジオラマ（`Menu/TitleDiorama`。床はワールド1の地面の絵）。カメラはステージより低く（38°）寄せて、顔が見えるようにする。ロゴは開くと上から落ちてきて弾み、そのあとゆっくり上下に揺れる（「タップしてスタート」では大きくまん中より上、ロビーでは小さく上のまん中。`TitleLogoMotion`）。画面の上下は暗いぼかしを敷いて、ジオラマの上でも文字とボタンを読めるようにする。部品の置き方は §3.3
  - まん中に自分の編成の3体（先頭が手前のまん中。編成が空なら アデリン・ジェンツ・オヤブン）。野生のペンモン（20種類からばらばら・暗い色）が奥と左右から煙とともに出て、いちばん近い味方へ歩いてくる。届いたら殴りかかり（味方はのけぞる）、味方は自分の技の形で振って吹っ飛ばす。飛んで止まったら撃破の動きでコインと星になって消える。同時に最大8体
  - 4.5〜7.5秒ごとに味方の誰かが必殺技で跳び、着地のまわり（2.8マス）をまとめて吹っ飛ばす
  - 見た目だけなので Core のステージは使わない（乱数も UnityEngine.Random）。音は出さない（タイトルの BGM だけ）。タイトルが閉じたら全部消して、ステージのカメラに戻す

### 9.8 HUD（ステージ中の画面表示）

字を読まなくても乱戦の最中にひと目で分かるよう、顔とバーとつぶで見せる（`StageHud`。組み立ては `PenmonScrambleSceneBuilder.Hud.cs` / `PenmonScrambleSceneBuilder.HudPlates.cs`、絵は `PenmonScrambleSceneBuilder.HudArt.cs`）。プレートはセーフエリアの内側に置き、タイトルの間は出さない（自分の3体が届いてから出す）。板は斜めに切った札（上が右へ傾いた平行四辺形・白い縁）で、白で描いて色を掛ける

- 左上: 自分のプレート
  - 場に出ている子の大きな丸い顔（属性の色の丸に、顔の絵の胸から上）。まわりの5つに区切った輪が必殺技のゲージ（敵1体分で1区切り。§4.3）。満タンになると輪が金に光って、後ろの光が脈打ち、外の輪が回り、顔の下に「必殺OK」の札が弾む（スマホの必殺技のボタンと同じ見せ方）
  - 顔の後ろから出る名札（席の色。「P1  アデリン」）と HP のバー（「HP」と「120 / 150」）。HP は半分を切ると黄色、3割を切ると赤く点滅する。減った分は明るい残りとして少し（0.45秒）残ってから追いつき、減った瞬間にバーが揺れる。交代したときは残りも揺れも出さない
  - 3体とも倒れたら、顔を灰色にして HP のところに「ダウン… 仲間が近くにいると復活」
  - HP のバーの下に3体の小さな顔（下に細い HP のバー）。場に出ている子は金の輪、次に出る子（§4.1）は白い輪。交代の待ちの間は次の子の顔に暗い扇がかかって時計回りに晴れ、明けたら顔が1回弾み、白い輪が脈打つ。倒れた子は灰色に赤い×
- 右上（メニューボタンの左）: 「エリア」と、エリアのつぶ（済み＝金・今＝白く大きく脈打つ・まだ＝暗い）。エリアが2つ以上あれば最後は赤い「ボス」の札。ボスラッシュは「ROUND」と戦いのつぶで、最後は赤い王冠（§6.5）。その下に暗い色のペンモンの顔と「のこり 3」。出入口が開いたら金色で「すすめ →」
- 上のまん中: ボスがいる間だけ、ボスの顔・赤い名札（「BOSS  名前」）・HP のバー（減り方は自分の HP と同じ）。出たときは上から滑り込む。ステージのボスの顔は暗い色、大ボスはそのまま
- 画面の端の印（`EdgeMarkers`）: 画面の外にある大ボス・仲間・大ボスの予告を、画面の端から指す。外を指すとがった丸（暗い縁）で、大ボスは赤に顔、仲間は席の色に顔と名前（ダウンしていても出す。起こしに行けるように）、予告はだいだいに「！」（脈打つ）。予告の帯は端から端までのどこかが見えていれば出さない。もぐっている大ボスは出さない。上の HUD のプレートとスマホのボタンを避けた枠の縁に置く。印は8つまで（大ボス・仲間・予告の順）
- 画面の真ん中の知らせ（「エリア 2」「ボスエリア！」「すすめ →」「合体！○○」、闘技場の連戦では「ROUND 2」「ROUND CLEAR!」「FINAL ROUND」。§6.4・§6.5）: 太字で縁取りと影。出た瞬間に大きく出て縮み、1.5秒で消える

## 10. セーブ

- PlayerPrefs に JSON で保存（キー: `PenmonScramble.Save`。**一度配ったら変えない**）。データのバージョン（`version`。いまは 3）を入れる
- 保存するもの: コイン・持っている個体（固有ID `id`・種類 `speciesNo`・引いたときのパワー `basePower`・強化で足した分 `boost`・上限解放の回数 `limitBreak`）・編成の3体・クリア済みのステージ（番号）・ボスラッシュのクリア済み（`clearedRush`。ステージ番号 × 10 ＋ 難易度）・無料ガチャを使った回数・ミニゲームの記録（`miniGames`。v3〜。§13）
- ガチャを引いた直後（演出の前）・ステージの結果の後・ミニゲームの結果の後・売った後・編成を変えた後・強化した直後に保存する
- **v1 → v2 だけの例外**: version が 2 より小さい記録は読まずに、新しい記録ですぐ上書きする（ユーザー承認済み。CLAUDE.md §3.5 の例外。`SaveStore.OldestReadableVersion`）。退避はしない。名前と音量は別のキーなので残る。消したときは、「タップしてスタート」の後に「新しいバージョンになったので、記録を初めからにしました」と出してから、いつもの流れ（名前 → 無料ガチャ3回）へ進む。v2 からはまた「足すだけ」に戻す
- 設定の「初期化」（§3.3）は、同じキーに新しい記録（`SaveData.CreateNew`）を書く（`SaveStore.Reset`）。キーも項目も変えない。前に退避した読めない記録（下の Broken）には触らない
- 読めない記録（JSON でない・`version` が無い）は消さずに `PenmonScramble.Save.Broken.1`〜`.10` の空いている所へ退避して、新しく始める（CLAUDE.md §3.5）
- 読んだ記録の食い違いは直す: いない子・重なった子を編成から外し、足りない分はパワーの高い子で埋める。知らない種類の子（新しい版で増えた子）は消さずに残す
- 記録とは別に、共通基盤が PlayerPrefs に持つもの（キーは**一度配ったら変えない**）: 名前 `UserProfile.Name`、音量 `Audio_BgmVolume` / `Audio_SeVolume`（ほか `Audio_MasterVolume`・`Audio_IsMute`・`Audio_IsBgmOff`）。名前が無い記録（前の版から上げた人）は、次に「タップしてスタート」を押したときに名前を決めてもらう
- v2 → v3: ミニゲームの記録の表（`miniGames`）を足した。v2 の記録はそのまま読み、空の表で始める（消すもの・名前を変えるものは無い）
- 項目を足すときは `SaveData.CurrentVersion` を上げ、`SaveStore.Upgrade` に古い記録に無かったときの値を書く。ステージの番号（`StageDef.No`）も記録に残るので変えない

## 11. バランスの試験場

人の代わりにボットで戦わせて、手ごたえを数値で合わせる仕組み（`Core/Sim/`。Unity に依存しない）。エディタの `Tools > PenmonScramble > Balance > Run` で全条件を回し（1分ほど。Play しなくてよい）、結果の表を `Docs/BALANCE_REPORT.md` に書き出す

- **ボット**（`StageBot`）: 赤い予告・雑魚とボスの構え・突進の道・敵の竜巻と背びれと溶岩の中にいたら、近い安全な所（同じ距離なら闘技場の真ん中寄り）へ歩く。歩く先がすぐ危ない所なら立ち止まる。場に出ている子の HP が 3 割を切ったら、もっと元気な控えと交代する。倒れた仲間がいれば起こしに行き、出入口が開いたら次のエリアへ進む。それ以外は近い敵へ歩き、技1を出し続け、ときどき技2、ゲージがたまれば必殺技
  - うまさは3段階: うまい人（Expert。気づいてから 0.15 秒で動く）/ ふつうの人（Casual。0.35 秒で動き、危ないものの 2 割を見落とす）/ よけない（Brawler。よけず・交代せず・進まない。重さの計測とスクショの台本で使う）
- **測る条件**: ストーリー 1-1〜5-3（ひとり）× うまさ2段階、ボスラッシュ 5ステージ × 3難易度 × 1〜4人 × うまさ2段階。1条件を種を変えて 40 回
- **想定の編成**（`BalanceParty`。その場面に来る人が持っていそうな3体）
  - 1-1: 無料3回の子（強化なし）
  - ストーリー・ボスラッシュ ふつう: そのワールドのガチャの子（★ はワールド1 ★2・★1・★1 / 2・3 ★2・★2・★1 / 4・5 ★3・★2・★2）を、上限までの 3 割強化
  - 5-3: ワールド5の ★3・★2・★2 を、上限解放1回の上限の 8 割まで
  - むずかしい: ふつうと同じ★の子を、上限解放2回で上限まで
  - げきむず: ふつうの★を1つずつ上げた子（★3 中心）を、上限解放4回で上限まで
- **測るもの**: クリアできたか・かかった時間・受けたダメージ（3体の最大 HP の合計に対する割合）・倒れた子の数・ダウンの回数・ボスの戦いの長さ・ボスに当たった回数。20 分で決着がつかなければ失敗に数える
- **目標**（ふつうの人＝ Casual、うまい人＝ Expert）。いまはすべてそろっている

  | 場面 | 目標 | 目標の幅 |
  | --- | --- | --- |
  | 1-1 | ふつうの人でクリアできる・HP の半分ほど削られる | クリア 90% 以上・ダメージ 30〜70% |
  | ワールド1〜4 の3ステージ目 | ふつうの人で 6〜7 割クリア・大ボスに何回か当たる | 55〜80% |
  | 5-3 | 強化を進めた子で、ふつうの人で半分ほど | 40〜65% |
  | ボスラッシュ ふつう / むずかしい | ふつうの人 2〜4人で 7 割 / 5 割ほど | 60〜85% / 40〜65% |
  | げきむず | うまい人4人で 3〜5 割 | 25〜55% |

- **コインの流れ**: 遊び方ごとに、1時間（1回ごとに戦い以外で 30 秒かかるとして）にもらえるコイン・引けるガチャの回数・強化（素材1体＝ガチャ 100 枚＋強化のコイン）の回数を表にする。ボスラッシュはストーリーのくり返しより多く、先のステージ・上の難易度ほど多い
- ボットは人より手数が多く迷わないので、ここでそろえた後に実機で遊んで確かめる。手ごたえが違えば、ボットのうまさ（気づくまでの秒数・見落とす割合）か目標の数値を直して測り直す

## 13. ミニゲーム

本編とは別に遊べる小さなゲーム。最初はペンモンゴルフ、2本目はペンモンサッカー、3本目はペンモンベースボール。今後も同じ仕組みで足していくので、ミニゲームの共通部分（入口・記録・解放）と、ミニゲームごとの部分を分けて作る（`Scripts/MiniGames/Shared/` と `Scripts/MiniGames/<名前>/`。本編の Core・Game はミニゲームを知らない）

### 13.1 共通の仕組み

- 定義表（`MiniGameTable`）: 1つのミニゲームにつき1行（Id・名前・一言の説明・シーン名・最大の人数・ベストは小さいほど良いか・ベストの単位・コースの一覧・コースの呼び名（ゴルフは「コース」、サッカーは「スタジアム」、野球は「球場」））。表に1行足せばミニゲーム画面にカードが並ぶ。Id とコースの番号は記録に残るので**一度配ったら変えない**
- シーン: ミニゲームごとに別のシーン（本編のシーンを重くしないように）。シーンは各ミニゲームの SceneBuilder で生成し、Rebuild で本編の後に作ってビルドの一覧に足す
- 本編へ戻る: 本編のシーンを読み直す。どの画面から始めるかはシーンをまたいで残す「戻り先」（`LobbyReturn`）で渡す。遊んでいたミニゲームとコース（`MiniGameLaunch`）も残し、ミニゲーム画面はそのコースを選んだ状態で開く
- コースの解放（ストーリー連動。`MiniGameUnlock`）: コースの景色はストーリーのワールドと同じで、そのワールドに入れたら（前のワールドの 3 ステージ目をクリア）開く。ワールド1のコースは最初から開いている
- みんなで遊ぶ: 本編の待ちの窓に、ミニゲームの札と選択の板（`IRoomMode`）を並べる（§3.3）。チームで戦うミニゲーム（サッカー・野球）は、対戦 / 協力と赤・青のチーム分け（`MiniGameTeams`・`MiniGameRoomChoice`・`MiniGameRoomSetup`）、待ちの窓の板（`MiniGameTeamRoomPanel`）、MVP の選び方（`MiniGameMvp`）、チームの色（`MiniGameTeamColors`）を共通で使う。開始したら `MiniGameLaunch.StartOnline` で部屋を試合ごと引き継いでミニゲームのシーンへ移る（§8）。席番号と人数も `MiniGameLaunch` で渡す。結果からホストが待ちの窓へ戻すと（`OnlineSession.ReturnToRoom` → `MiniGameLaunch.ReturnToRoom`）、全員が本編のシーンを読み直して、同じ顔ぶれの待ちの窓から
- 記録（`MiniGameRecords`。§10）: ミニゲームとコースごとに1行（`gameId`・`courseNo`・回った回数 `plays`・ベスト `best`・ミニゲームごとの数 `special`）。次のミニゲームは項目を足さずに、この表に行を足す。知らない Id の行（新しい版で増えたミニゲーム）は消さずに残す

#### 新しいミニゲームを足すときの手順

1. 純C#の `Scripts/MiniGames/<名前>/Core`（asmdef `PenmonScramble.<名前>.Core`。`noEngineReferences: true`）と、`Scripts/MiniGames/<名前>/Game`（asmdef `PenmonScramble.<名前>.Game`）を作る。テストの asmdef（`Tests/Editor/PenmonScramble.Tests.asmdef`）の参照に Core を足し、`Tests/Editor/MiniGames/` にテストを足す
2. `MiniGameTable.All` に1行足す（項目は上の定義表どおり。Id は定数にする）。カードの絵は `Editor/MiniGames/PenmonScrambleSceneBuilder.MiniGames.cs` の `MiniGameCardArt()` に、表と同じ並びで足す
3. `Editor/MiniGames/<名前>/<名前>SceneBuilder` でシーンを作る。その `BuildScene()` の最後で `PenmonScrambleSceneBuilder.AddSceneToBuildSettings(ScenePath, atStart: false)` を呼ぶ。本編の `Editor/PenmonScrambleSceneBuilder.cs` の `BuildScene()`（`GolfSceneBuilder.BuildScene()` などが並ぶ所）にも1行足す
4. 待ちの窓の板（オンラインがあるなら）: `IRoomMode` を実装した板を作る（ゴルフは `GolfRoomPanel`、チーム戦は `MiniGameTeamRoomPanel` を継ぐ）。`Editor/PenmonScrambleSceneBuilder.RoomModes.cs` の `CreateRoomModes` の配列に足す。`RoomModeSelector` は配列の並びで札を出す
5. 報酬の計算は Core に書く。Game 側の結果処理（ゴルフは `GolfRoundPlay.Flow.cs`、サッカーは `SoccerMatchPlay.Flow.cs`、野球は `BaseballMatch.Result.cs`）で `MiniGameReward.Apply` に渡し、直後に保存する
6. コース選びの中身を `IMiniGameCourseGuide`（Core）として作り、Game 側の `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSceneLoad)]` の静的メソッドで `MiniGameGuides.Register(MiniGameTable.<名前>Id, ...)` する（ゴルフは `GolfSceneRunner.RegisterGuide`）
7. 仕様書 §13 に章を足す（§13.3 ゴルフ・§13.4 サッカー・§13.5 ベースボールの形）

### 13.2 ミニゲーム画面（`MiniGameHubScreen`）

- ロビーの左の列の「ミニゲーム」から開く。左上に「もどる」、上に見出し、右上にコイン
- 1段目: ミニゲームのカードが横に並ぶ（絵・名前・一言の説明）。押すとそのミニゲームのコース選びへ
- 2段目（コース選び）: 見出しはミニゲームの名前、その下に一言の説明。コースのカード（「コース 1」（サッカーは「スタジアム 1」、野球は「球場 1」。表のコースの呼び名）・景色の名前・ベスト「ベスト 8打（−1）」/「まだ記録がありません」・コースの中身（2行。1行目「3ホール  パー 2・3・4（合計 9）」・2行目に仕掛けの一言「流氷の壁と海」。サッカー・野球は1行目が CPU の強さ）・報酬の一言（まだ回っていなければ初回ボーナスも））を ◀ ▶ で選ぶ。開いていないコースも見られ、「ワールド 2 に入ると解放」と出て「ひとりで」「みんなで」を押せない。まだ作っていないコースは「このコースは準備中」（サッカーは「このスタジアムは準備中」、野球は「この球場は準備中」）で押せない。最初は、開いていて遊べる中で一番先のコース
- 下に「ひとりで」と「みんなで」。「みんなで」は、待ちの窓で遊ぶもの＝そのミニゲーム・そのコースを選んでおいて、ミニゲーム画面を閉じ、ロビーの「みんなで遊ぶ」の窓（部屋を作る / コードで参加）を開く（待ちの窓に札があるミニゲームだけ押せる）
- コースの中身は2行（`MiniGameGuides.TwoLines`）: 1行目は強さ（ゴルフはホールとパー）、2行目は仕掛けの一言。1行に並べると枠の幅を越えて折り返し、上下の行に重なるため。カードと待ちの窓の枠は2行ぶんの高さを取る。全ミニゲーム × 全コース（待ちの窓は ひとり・協力 1〜4人・対戦）の文は `Tools > PenmonScramble > Check > UI Text Layout` で枠に入るかを測る（`UiLayoutCheck.MiniGames`）。一言はカードの幅（◀ ▶ の内側）に入るよう、だいたい20字まで
- コースの中身・ベストの見せ方・報酬の一言は、各ミニゲームが登録する `IMiniGameCourseGuide`（`MiniGameGuides`。ゴルフは `GolfCourseGuide` を `GolfSceneRunner` が、サッカーは `SoccerCourseGuide` を `SoccerSceneRunner` が、野球は `BaseballCourseGuide` を `BaseballSceneRunner` が起動時に登録）から出す（共通側はミニゲームの中身を知らない）
- 報酬を書くのは共通の `MiniGameReward`（コインを足して記録の表に1回分を書く）。報酬の計算は各ミニゲームの Core
- 「もどる」/ Esc / OPTIONS は1段ずつ戻る（コース選び → カード → ロビー）

### 13.3 ペンモンゴルフ

- ミニゲーム画面の「ひとりで」から、開いているコースを3ホール回って、結果でコインとベストがもらえる。待ちの窓でゴルフを選べば、最大4人で順番に回れる（下の「みんなで」）。5コースとも遊べる（ストーリーを進めると開く。§13.1）。表にあってまだ作っていないコースは、ミニゲーム画面・待ちの窓で「このコースは準備中」になり選べない（シーンを開いてもコースの名前と「もどる」だけ。いまは無い）
- コース: 5コース × 3ホール。1 海岸 / 2 氷山 / 3 深海 / 4 嵐の崖 / 5 火山の入り江（ワールド1〜5 の景色。ワールドごとにギミックがある。下の「コース」）。ベストは3ホールの合計の打数（小さいほど良い）。コースの定義は `GolfCourseTable`（ホールの形はコースごとのファイル。`GolfCourse1`〜`GolfCourse5`）
- 計算はすべて純C#の `Golf.Core`（Unity の物理は使わない。オンラインではホストの計算を全員に配る）。数値は `GolfRules`（ルール）・`GolfBalance`（球の動き）

#### ホール（`GolfHoleDef`）

- 上から見た地面の上の座標（m）。地面の形（多角形。外へ出たら場外）・壁（線分。跳ね返りの強さと高さ）・地面の種類の範囲（多角形）・ティーとカップの位置・パー
- 壁の種類: ふつう（跳ね返り 0.72）・柔らかい（0.45）・バンパー（1.05。当たると少し速くなる）。高い壁（0.6m）と低い壁（0.2m。浮いた球は越える）
- 地面の種類: 池・場外（落ちたら打つ前の位置へ）・砂地（摩擦 3.2 倍）・坂（押す力の場。摩擦 1.6 より強い坂では止まった球も転がり出す）・ジャンプ台（速さ 1.5 以上で上を通ると上へ跳ぶ）・氷の床（摩擦 0.35 倍。よく滑る）・押し流す帯（水流・風の帯。坂と同じく押すが床は平ら）・間欠泉（決まった間隔 `MiniGameCycle` で噴き、噴いている間だけジャンプ台になる）
- 崖: 地面の縁に柵を立てない所（`GolfHoleDef.WallsAlong` で一部の辺だけ柵にする）。縁から出たら場外と同じ
- 動く物（`GolfMover`。ギミック）: 形（壁の並び）が時刻だけで決まる動きをする。行ったり来たりする塊（`Block`。端でゆっくり折り返す）と、回る風車（`Windmill`。中心から伸びる羽根）。当たると壁の動く速さも受けて弾かれる（止まっている球も押されれば動き出す）
- ワープの泡（`GolfWarp`）: 地面を転がる球の中心が入口から 0.42m に入ると、速さと向きはそのままで出口へ飛ぶ（片道。浮いた球は入らない）
- ギミックはどれも**ホールの時刻だけで決まる**（下の「ホールの時刻」。オンラインで全員そろうように。乱数は使わない）

#### 球の動き（`GolfBallSim`）

- 1/120 秒ずつ進める（描画のフレームに関係なく同じ打ち方なら同じ結果）。球の半径 0.18m、速さの上限 13m/s（1歩で半径より進まないので壁をすり抜けない）
- 打ち出しの速さ: ゲージ 0% で 1.2m/s 〜 100% で 10m/s。転がりは一定の摩擦（毎秒 1.6m/s 遅くなる）で止まる（100% で平らな地面を約 30m）
- 壁: 壁に向かう速さを跳ね返りの強さ倍で返し、壁に沿う速さはそのまま
- 浮いている間（ジャンプ台）は放物線（重力 9.8）。摩擦・坂・カップは効かず、壁は高さより上なら越える
- カップ（半径 0.3m）: 上を通るとき 3.2m/s より遅ければ入る。速すぎると縁に引かれて曲がり、通り過ぎる（「おしい」）
- 球どうし: 同じ重さで弾き合う（跳ね返り 0.92。打っていない人の球も動く）。カップの中の球・コースから外した球には当たらない
- 坂・押し流す帯に壁へ押しつけられ、ほとんど動いていない球（0.08m/s 以下）は止まった扱い（跳ね返されては押し戻されるのをくり返して、いつまでも止まらないのを防ぐ）

#### 1ホールの進行（`GolfHoleWorld`）

- ティーに全員の球を、カップの方向と直角に 0.55m ずつずらして並べる
- 打順の人が向きを決めて打つ → 全部の球が止まるまで待つ → 次の人。1打ずつ交代し、終わった人は飛ばす。打順は1ホール目が席の順、2ホール目からは前のホールまでの打数が少ない順（同じなら席の順。`GolfTurnOrder`）
- 番の始めはカップを向く。持ち時間 20 秒。過ぎたら、いま向いている向き・ゲージ 50% で自動で打つ
- 池・場外: 打った本人が落ちたら 1 打足して打つ前の位置へ。弾かれて落ちた人は戻すだけ（打数は増えない）
- カップに入った人は抜ける（弾かれて入っても入り）。打数の上限はパー＋4。上限まで打っても入らなければ「上限＋1」打で終わり、球をコースから外す
- 全員が終わったらホールの終わり。1打で転がる時間は最大 25 秒（止まらなくても次へ進む）
- 起きたこと（打った・特殊ショット・雷の加速・壁・球どうし・ジャンプ・間欠泉・着地・水切り・ワープ・動く物からよけた・おしい・カップイン・落ちた・番・上限・ホールの終わり）はイベントで表示・音へ渡す
- 打順の終わりに、動く物の通る範囲（風車は羽根の届く円、塊は両端の形を囲む範囲）に掛かって止まった球を、範囲の外のいちばん近い所へよける（狙っている間は球を動かさないので、動く物が止まった球をすり抜けないように）。その後、池・場外の上で止まっている球は落とす（凍った道の上で止まった球は、氷が消えて落ちる。打った本人なら 1 打足す）
- ホールの時刻（`GolfHoleWorld.Time`）: ホールが始まってからの秒。狙っている間・全体を見せている間・喜ぶのを見せている間・振り下ろしている間も進み（`Idle`。持ち時間は減らさない）、転がっている間は球と同じ 1/120 秒刻みで進む。ひとりでメニューを開いている間は止まる。ホールのやり直しで 0 に戻る

#### 1コースのラウンド（`GolfRound`）

- 3ホールを続けて回る。ホールごとの全員の打数をスコアカードに残し、2ホール目からは前のホールまでの打数が少ない順に打つ
- 1打の入力は `GolfShot`（打つ子・向き・強さ・特殊 ON・風の右左）
- ホールをやり直す（メニュー）: そのホールをはじめから。そのホールで使った特殊ショットは戻る。「もう一度」: スコアカードも特殊ショットも空に戻してコースのはじめから

#### 特殊ショット（`GolfSpecial`・`GolfSpecialBalance`）

- 属性ごとに1種類。★（1〜3）が高いほど強い。パワー（育成）は効かない。各子 1コースに1回（使ったかは `GolfTeam`）。同じ属性の子が2体いれば2回使える
- 打つ前に「特殊」を ON にして打つ。ON にできるのは、いま選んでいる子がまだ使っていないときだけ。子を替える・番が替わると OFF に戻る

| 属性 | 名前 | 効き目 | ★1 / ★2 / ★3 |
| --- | --- | --- | --- |
| 氷 | アイスロード | 通った道が凍る。凍った道の上は摩擦 0.3 倍で止まりにくく、池・砂地も凍って渡れる（場外は落ちる）。地面を進んだ分だけ短くなる | 凍る長さ 7 / 10 / 13m |
| 水 | 水切りバウンド | 打ち出しから上へ 3m/s で跳ぶ（頂点 約 0.46m。低い壁は越え、高い壁は越えない）。着くたびに、跳ねる回数が残っていればまた跳ぶ（池の上でも跳ねる。場外では跳ねない）。跳ねるたびに上へ・前への速さは 0.85 倍 | 跳ねる回数 1 / 2 / 3 |
| 風 | 追い風カーブ | 打つ前に右か左を選ぶ。進んだ距離あたり決まった角度で曲がる（最初の 8m の間。地面でも空中でも）。曲がり方が強さによらないので、ガイド線も曲がって見える | 1m あたり 0.10 / 0.14 / 0.18 ラジアン（8m で約 46° / 64° / 82°） |
| 雷 | イナズマブースト | 打った後、球が転がっている間にもう一度押すと、その場で加速して向きを少し変える（1打に1回。速さ 0.3m/s 未満の球は加速できない）。向きはいまの進む向きから ±上限まで | 加速 +3 / +4.5 / +6m/s・向き ±20° / 35° / 50° |

#### ガイド線（`GolfGuide`）

- 球から、向いている向きへまっすぐ最初に当たる所まで（最大 9m）。壁なら跳ね返った後の向きを 1.6m だけ見せる（バンクショットを狙える）。ほかの人の球に当たるならそこまで。坂と摩擦は見ない（強さと坂は自分で読む）。動く物・ワープ・押し流す帯・間欠泉も見ない（動きと間合いは自分で読む。線は止まっている壁だけ）
- 風の特殊ショットを ON にしているときは、球が実際に通るのと同じ曲がった線。雷の加速が使える間は、球から加速する向きへの線を出す

#### 操作

- タッチ・キーボード・コントローラーで同じ手ごたえにする（`GolfShotControl`）
  - 向き: ←→ / 左スティック（押し始めはゆっくり、押し続けると速く回る）/ 画面のボタンの無い所を横にドラッグ（マウスの左ドラッグも）
  - 打つ: J / ×（南）/ スマホは右下の「打つ」大ボタンでゲージを動かし始め、もう一度で止める。止めるとペンモンが振り下ろし、クラブが球に当たった瞬間に打つ（振り下ろしている間は持ち時間を止める）。ゲージを動かしている間は向きを変えられない
  - 打つ子: K / ○（東）で次の子へ、または左下のカードを押す（ゲージを動かす前だけ）
  - 特殊: L / △（北）/ スマホは「特殊」のボタン（狙う間・まだ使っていない子のときだけ出る）。OFF ↔ ON、風の子は OFF → 右 → 左 → OFF の順に替わる（ゲージを動かす前だけ）
  - 雷の加速: 転がっている間に ←→ / スティック / 横のドラッグで向きを合わせ、J / × / 「打つ」で加速
  - メニュー: Esc / OPTIONS / 右上の「‖」
  - 見回す: 右スティック / 画面の2本指のドラッグ（マウスの右ドラッグ）。番が替わると戻る
- パワーゲージ（`GolfPowerGauge`。Core）: 0 → 100% → 0 … を 1.6 秒で1往復し、端でも止まらない（端を待って 100% を狙うだけにならないように）
- 打つ子（`GolfTeam`。Core）: 本編の編成の3体（並びのまま）。表に無い子は外し、空なら アデリン・ジェンツ・オヤブン。ふつうのショットはどの子でも同じ

#### 見た目

- コース（`GolfHoleView`）: おもちゃのミニゴルフの台。地面はワールドの地面の絵（`CreatureArt`。絵の無いワールドは本編と同じく前のワールドの絵を借りる）を、縦横比を保ってコースを覆うように貼った厚み 0.5m の台。台の下には同じ絵を暗くした広い床、背景はワールドの空の色
  - 地面の種類: 池＝水色に白い波の縁・場外＝暗い色・砂地＝砂色に濃い縁・坂＝下る向きへ傾けた床（押す力から求めた傾きの半分、最大 0.35m）に白い「く」の字の矢印・ジャンプ台＝赤い少し高い台に白い輪。高さは見た目だけ（Core は平らなまま。球・打つ子・ガイド線をこの高さに乗せる。`GolfSurface`）
  - 壁: 角の丸い柱を寝かせたおもちゃの柵。ふつう・低い壁はワールドの柵の色（本編の闘技場の柵と同じ白と帯の色）、バンパーは黄色に赤い帯（球が当たると膨らんで弾む）、柔らかい壁は水色のスポンジ（深海では緑の海藻に葉の色の帯）
  - 景色ごとの色（`GolfScenery`）: 砂地は氷山では雪だまり（白）・火山では灰。池は氷山で冷たい水色・深海で暗い青。場外は火山では溶岩（橙に黄色い光る縁。落ちたときの輪も黄色）
  - ギミック（`GolfHoleView.Gimmicks`。ホールの時刻で毎フレーム写す）: 氷の床＝水色に白い縁。押し流す帯＝景色の色の平らな帯に、流れる向きへ流れていく印（海流は白い「く」の字、風は細い白い筋）。間欠泉＝暗い噴き出し口と岩の輪。噴く 0.8 秒前から輪が小刻みに揺れ、噴いている間は白い柱が伸びる。動く塊＝角の丸い岩（氷山は氷の塊、火山は黒い岩に溶岩の色の帯）。風車＝茶色の柱と、交互に赤と白の羽根。ワープの泡＝入口は透きとおった泡（ふわふわ揺れる）と色の輪、出口は同じ色の輪（泡ごとに色を変える）。ワープ・間欠泉で跳んだ・動く物からよけた所には輪が広がる
  - カップ: 黒い穴に白い縁。紅白の棒の先の旗（ワールドの色）がゆっくりはためき、カップインで跳ねて1回転する。ティーは濃い緑のマットと左右の白い玉。池に落ちると白い輪が広がる
- 球（`GolfBallView`）: 白い球に席の色の帯（本編の席の色と同じ）。進んだ分だけ転がって帯が回る。足元に丸い影（浮くと小さく）。カップに入ると穴へ沈んで見えなくなる
- ガイド線（`GolfGuideView`）: 白い点が前へ流れる点線（特殊を ON にしているとき・雷の加速の向きは水色）、壁で跳ね返った後は黄色。当たる所に白い輪
- 特殊ショット: 打った瞬間に名前の知らせ（属性の色）。氷は通った後に水色の凍った道が残り、番が替わると溶けて消える。水切りは跳ねた所に輪（池の上なら水しぶき）。雷は加速した所に黄色い輪
- 打つ子（`GolfShooter`）: 選んだペンモンが、おもちゃの木のクラブ（パター。頭の帯は属性の色）を両ヒレで持って球の横に立つ（右打ち: 狙う向きが体の左。狙う向きを変えると球のまわりを回り込む）。立つ位置は、構えたときのクラブの頭が球に触れるよう、体型ごとに測って決める
  - 構える → ゲージに合わせて振りかぶる（100% で 115°）→ だんだん速く振り下ろす → 当たった勢いで振り抜く（強いほど大きく）→ しばらく止めてから、球の方へ向いて見送る。持ち時間切れの自動の1打はその場で振り抜く
  - カップイン: カップの横（カメラの側）にぽんと出て、クラブを置いて跳ねて喜ぶ（2.2 秒。この間は次の番を始めない）。池・場外: その場でクラブを置いて頭を抱える（1.5 秒）
  - 子を替える・離れた所へ移るときは、小さくぽんと出てくる
- カメラ（`GolfCamera`）: ホールの始めは全体を見せる（2.4 秒。ひとりなら打つボタンで飛ばせる。みんなでは飛ばせない）→ 球の後ろ斜め上から狙う向きを見る → 打ったら少し引いて高くから球を追う → 止まったら次の人の球の後ろへ。どの切り替えも同じなめらかな追い方で移る
- HUD（`GolfHud`）: 左上にホールの札（「1. はじまりの浜」・パー）と「2 打目（上限 7）」、その下に打順の表（席の色の丸・名前・打数。いまの番は ▶、入った人は「カップイン」、上限で終わった人は「上限」）。上のまん中に持ち時間の輪（残り 5 秒から赤く脈打つ）。左下にいまの番の人の3体のカード（属性の色の丸に顔・★。打つ子は大きく金の輪。特殊を ON にしている子は輪が水色に脈打つ。特殊ショットを使った子は暗くする）と、その上に特殊ショットの札（属性の色の板に「アイスロード ★★」と「OFF（L / △ で ON）」/「ON」/「ON → 右へ曲げる」/「このコースでは使った」。雷の加速が使える間は加速の案内）。右にパワーゲージ（弱いと緑・中くらいで黄色・強いと赤。動かしている間は枠が脈打つ）。右上にメニューの「‖」。PC では下に操作の説明
  - 知らせ（まん中。大きく出て縮み、消える）: 「ホール 1  パー 2」・特殊ショットの名前・カップインの呼び名（「ホールインワン！」「バーディー！」「パー！」「ボギー！」…。`GolfScoreNames`）・「おしい！」・「ポチャン！  1打たす」・「P2 の番」（2人以上。喜ぶのを見せ終わってから。みんなでは自分の番は「あなたの番」）・「P2 が抜けました」
- BGM: ゴルフ専用の曲（`MusicTrack.Golf`。口笛の明るくのんびりした曲。素材と入手先は §9.7。素材が無ければコードで作る仮の曲）。本編から来たときの曲は引き継がず、シーンに入ったら差し替える。結果で止め（本編と同じく結果の音を聞かせるため）、「もう一度」で頭から流し直す。本編へ戻ると本編のタイトルの曲になる
- 音（`GolfSounds`。本編と同じくコードで作るチップチューン `ToySynth`）: 打つ（木の「コン」。強いほど高く大きい）・壁（「トン」。強く当たるほど大きい）・球どうし（「カチッ」）・おしい（下がる音）・カップイン（「カラン」2回とジングル）・ホールインワン（「カラン」の後に上がる音を2回重ねて高い音を伸ばす。ふつうのカップインと聞き分けられるように）・池（「ポチャン」）・ジャンプ・着地（低い「ポン」）・打つ子を替えた・特殊（キラッ）・雷の加速（ビリッ）・水切り（ピチャッ）・間欠泉（シュワッ）・ワープ（ポワン）・動く物からよけた（ぽふっ）・上限で終わり（下がる2音）・ホールの始め（「ホール 1  パー 2」で短いファンファーレ）・番が替わった（2人以上で「P2 の番」/「あなたの番」と一緒に「ピンポン」）・持ち時間（自分の番だけ、残り 5 秒から 1 秒ごとに「カチッ」。ほかの人の番では鳴らさない）・結果（本編のクリアと同じジングル）

#### ホールの間・結果・メニュー

- ホールの間: 全員が終わったら（喜ぶのを見せ終わってから 1.4 秒）スコアカードを出す。見出し「ホール 1 おわり」、行は ホール 1〜3・合計／パー／全員（席の色の帯・名前・ホールごとの打数・合計とパーとの差）。パーより少ない打数は金、多い打数は水色、まだのホールは「−」。「ホール 2 へ」の札（J / × / Enter / 押す）で次のホールへ
- 結果（3ホールの後。`GolfRoundPlay.Flow`・`GolfResultText`。右の欄と札はミニゲームで共通の `MiniGameResultPanel`）: 左にスコアカード（見出し「ラウンド終了！」）、右に合計「9 打（±0）」・「はじめての記録！」/「ベスト更新！（前は 10 打）」/「ベスト 8 打」・コインの内訳（回った・パーより少ない・ホールインワン・初めて回った）と合計。下に「もう一度」（同じコースをはじめから）・「コースを選ぶ」（ミニゲーム画面のコース選びへ）・「ロビーへ」の札（左右で選んで決定。最初は「もう一度」）
- 報酬（`GolfReward`）: 回った 40 ＋ パーより少ない打数 1 につき 15 ＋ ホールインワン 1 回につき 50 ＋ そのコースを初めて回ったら 100。マイナスにはしない
  - 控えめにした理由（本編と比べて決めた）: ストーリーをくり返すと1回 100・1時間に約 3500（§11 のコインの流れ）。ゴルフは1回（3ホール）に2〜3分かかるので、ふつうに回って（パー前後で 40〜70）1時間に 800〜1400、うまく回っても 2000 ほどで、ストーリーより少ない。パーより 4 打少なくないと 1回 100 を超えず、ホールインワンはボットの総当たりでも1打あたり 1% 未満（コースの確認）なので、ゴルフだけでコインを稼ぐのが一番得にはならない。初回ボーナスは 5 コースで 500（ガチャ 5 回分）だけ
- 記録: 結果を出すときに、自分（ひとりなら席 0、みんなでは自分の席）の合計の打数をベスト（小さいほど良い）、ホールインワンの数を `special` に足し、コインを足してすぐ保存する（`MiniGameReward`）
- メニュー（本編のステージ中のメニュー `StageMenu` の見た目を使う。ひとりなら開いている間は止まる）: つづける・ホールをやり直す（確認あり）・遊び方（下の「遊び方」）・設定（音量）・ミニゲームへ（確認あり。いまのスコアは残らない）。みんなででは止まらず（見出し「メニュー」・「みんなで遊んでいる間は 止まりません」）、「ホールをやり直す」は出さない。「ミニゲームへ」は部屋から抜ける（ホストなら部屋を閉じて、ほかの人は全員ロビーへ）。上の帯にコース名と「ホール 1 / 3」。ホールの間・結果の間は開かない

#### 遊び方（`GolfSceneBuilder.HowToPlay`・`GolfHowToPlayPages`）

- メニューの「遊び方」から開く。画面は本編の遊び方（§3.1）と同じで、操作の絵とルールのページだけがゴルフのもの
- 操作: キーボード（左に A D と ← →＝向き、右に J K L＝打つ・打つ子・特殊、左上に Esc＝メニュー）・PS5（左の列に 左スティック＝向き・右スティック＝見回す・OPTIONS＝メニュー、右の列に × 打つ・○ 打つ子を替える・△ 特殊ショット）・スマホ（ゴルフの HUD の配置を縮めて、打つ大ボタン・特殊のボタン・左下の打つ子のカード・まん中に「← ドラッグで向き →」・右上の ‖）。押したキー・ボタンは光る
- ルール（ゴルフのルールを変えたらここも直す）: 打って カップへ・打つ子を選ぶ・アイスロード（氷）・水切りバウンド（水）・追い風カーブ（風）・イナズマブースト（雷）・池と上限・いろいろな仕掛け・みんなで・コインと記録。顔はその話に合うペンモン（特殊ショットはその属性の子）

#### みんなで（オンライン。`GolfOnlinePlay`・`GolfCodec`。通信路はミニゲームで共通の `MiniGameLink`）

- 待ちの窓でホストがゴルフとコースを選んで「開始」すると、全員がゴルフのシーンへ移る（部屋は試合ごと引き継ぐ。§8）。最大4人。ホストひとりでも始められる
- 始まるまで: ゲストはシーンに入ったら「準備できた」と自分の編成の3体（種類）をホストへ送る（`scramble.golf.ready`。最初のスナップショットが届くまで 0.5 秒ごとに送り直す）。ホストは、つながっている全員の準備がそろうか 6 秒たったら、各自の3体でラウンドを作って始める（届かなかった人は仮の3体＝アデリン・ジェンツ・オヤブン。移っている間に抜けた人は、はじめから外す）。待つ間は「みんなの準備を待っています…」/「ホストを待っています…」。ゲストは 20 秒たっても届かなければロビーへ
- **ホストがすべて計算する**（球の計算は小数のずれで端末ごとに変わりうるので、ゲストは計算しない）。ホストはスナップショット（`GolfSnapshot`: コース・ホール・番・打つ順・持ち時間・ホールの時刻・番の人の手元・全員の球・打数・3体と選んでいる子と使った特殊・スコアカード・抜けた人・前に送ってからの出来事）を 0.05 秒ごとに送る（出来事があったフレームは待たずに。`scramble.golf.snapshot`。届く方で送る）
- ゲストは写しのラウンド（`GolfRound.CreateMirror`）に写す。出来事は起きたホールの印つきで届き、順に「打数・番・カップイン」だけを進めてから見せ（カップインの呼び名や喜ぶ子を、その時点の打数と番の人で出すため）、最後に状態で全部を上書きする。ホールが替わっていればホールを始め直す。球は前の位置から届いた位置へ、送る間隔をかけてなめらかに動かす（池の戻し・ワープなど大きく飛んだ球はその場へ）。ホールの時刻も手元で進めながら、届いた時刻へ送る間隔をかけて少しずつ寄せる（0.5 秒より大きくずれていたらその場で合わせる）ので、動く物・間欠泉は全員に同じ様子で見える。中身の並びの版（`GolfCodec.FormatVersion`）は 2
- 自分の番のゲストは、狙っている様子（打つ子・向き・ゲージ・特殊の ON と風の向き。`GolfAim`）を変わったときに 0.1 秒以上あけて送り、ゲージを止めたら「振り下ろした」、雷は「加速」を送る（`scramble.golf.input`）。手元の向きと選んだ子は、届いたスナップショットで戻さない。ホストは番の人からだけ受け、振り下ろしはホストでも振り下ろしてクラブが当たった瞬間に打つ（ひとりと同じ間合い）。打ったゲストは、球が動き出したと届くまで振り抜いたまま待つ（1.5 秒届かなければ打ち直せる）
- ほかの人の番は、その人の向き・ガイド線・ゲージ・選んだ子・特殊の札が見える（操作はできず、スマホのボタンも出さない）。ほかの人が振り下ろすと、その場の子も振り下ろす
- 持ち時間は全員同じ（ホストの時間。切れたらホストがその向き・50% で打つ）。ホールの始めに全体を見せる間は飛ばせない
- ホールの間: 次のホールへ進めるのはホストだけ。ゲストのスコアカードは「ホストが次のホールへ進めるのを待っています」
- 抜けた人: ゲストが落ちたら、その人の球を消して打順から外し、残りで続ける（「P2 が抜けました」。その後のホールもはじめから外れる。スコアカードは「（ぬけた）」で、順位には入らない）。ホストが落ちたら、ゲストはロビーへ
- 結果: スコアカードの名前の前に順位（同じ打数は同じ順位）。右の欄の合計の前にも「1位」。報酬は各自の端末で、自分の打数から決めて自分の記録に書く。順位のボーナス 1位 +40 / 2位 +20 / 3位 +10（ひとりでは無し。オンラインは1回が長いぶん、少し上乗せする）。札は、ホストは「コースを選ぶ」（全員で同じ顔ぶれのまま待ちの窓へ）・「ロビーへ」（部屋を閉じる）、ゲストは「ロビーへ」（部屋から抜ける）だけで「ホストがコースを選ぶと、みんなで待ちの窓へ戻ります」。「もう一度」は出さない（同じコースは待ちの窓でそのまま「開始」）

### 13.4 ペンモンサッカー

- ミニゲーム画面にカード（芝の上のサッカーボールの絵・「ペンモンサッカー」・「編成の3体でチームを組んで、3分間の試合」）が出る。スタジアムは 1 海岸 / 2 氷山 / 3 深海 / 4 嵐の崖 / 5 火山の入り江（ワールド1〜5。番号は一度配ったら変えない）。どのスタジアムも、そのワールドに入ると開く（ゴルフと同じ `MiniGameUnlock`。まだなら「ワールド N に入ると解放」）。カードの中身は `SoccerCourseGuide`（`SoccerSceneRunner` が起動時に登録）: 1行目に強さ「CPUの強さ ★★☆☆☆」・2行目に仕掛けの一言「氷の床（ボールも子もよく滑る）」と、報酬の一言（「報酬 20 コイン ＋ 勝つと 40 ＋ 1点ごとに 5」、まだ遊んでいなければ「初めて勝つと ボーナス +100」）。「みんなで」を押すと、待ちの窓でサッカーとそのスタジアムを選んだ状態で「みんなで遊ぶ」の窓が開く（下の「みんなで」）
- シーン（`SoccerScene`。`SoccerSceneBuilder` で生成）: ミニゲーム画面の「ひとりで」から開くと、そのスタジアムでひとりで1試合（`SoccerMatchPlay`）。部屋の待ちの窓から来たときは、引き継いだ部屋でみんなで1試合（`SoccerOnlinePlay`。部屋を引き継げなかったらロビーへ）。この版に無いスタジアムの番号なら、スタジアムの名前と「スタジアムは準備中です」と「もどる」だけ
- スタジアム（`SoccerStadiumTable`）: 番号・名前・景色のワールド・CPU の強さ（★1〜★5）・仕掛けの一言・CPU に出る野生のペンモンの種類（本編のそのワールドの雑魚と同じ混ぜ方。試合ごとに重ならないように3体。★が高い子ほど必殺シュートが強い）

  | 番号 | スタジアム | CPU | 仕掛け | CPU の種類 |
  | --- | --- | --- | --- | --- |
  | 1 | 海岸 | ★1 | なし | ★1 が10 |
  | 2 | 氷山 | ★2 | 氷の床 | ★1 が10・★2 が6 |
  | 3 | 深海 | ★3 | 水流の帯 | ★1 が4・★2 が6 |
  | 4 | 嵐の崖 | ★4 | 風の帯・バンパーの柱・四隅のバンパー | ★2 が6・★3 が4 |
  | 5 | 火山の入り江 | ★5 | 間欠泉 | ★2 が4・★3 が4 |

- スタジアムの仕掛け（`SoccerPitchTable`・`SoccerGimmicks`・`SoccerWorld.Gimmicks`。数値は `SoccerBalance.Gimmicks`。どれも案）: ピッチの形はどのスタジアムも同じで、仕掛けを重ねる。赤と青で有利・不利が出ないよう、真ん中を中心に 180° 回すか左右を裏返すと重なる形に置き、ゴールの前（キーパーの動く所）・キックオフの並びには置かない。時間で変わる物はピッチの時刻（`SoccerWorld.Time`。演出の間は止まる）だけで決まり、ゲストへはスナップショットで時刻を送る
  - 氷の床（氷山）: 真ん中の帯（横 12 マス）と、両陣地の柵ぎわに1枚ずつ。ボールの転がりの摩擦 ×0.3、子の歩き出し・止まりの速さ ×0.18（速さは変えない。すべって止まれない）、転んだ子の勢いの消え方 ×0.25
  - 水流の帯（深海）: 両陣地に縦の帯（X が 5〜8.5 マス）。左と右はいつも反対へ流れ、8 秒ごとに向きが替わる。地面のボール（高さ 0.3 マスまで）を毎秒 9 で押し（押す向きに 4.5 より遅い間だけ）、帯の中の子は毎秒 1.5 マス流される（歩く速さに足すだけで勢いには残さない。持って運ぶ間も効くように）
  - 風の帯（嵐の崖）: 真ん中の縦の帯（横 9 マス）。3 秒吹いて 2 秒止み、吹くたびに向きが替わる（縦）。ボールを毎秒 8 で押し（5 まで）、浮いた球は 1.6 倍強く流す。子は毎秒 1 マス流される
  - バンパー（嵐の崖）: 風の帯の中に柱2本（半径 0.65 マス。当たりは12角形の壁）と、四隅の斜めの柵。当たったボールは、壁に向かう速さを 1.25 倍・少なくとも 7 で弾き返す（速さの上限はいちばん強いシュート）。子には柵と同じ（柱は回り込む）
  - 間欠泉（火山の入り江）: 6 つ（半径 1.25 マス）。6 秒ごとに 1.5 秒噴き、口ごとに時をずらす（180° 回して重なる2つは同じ時）。噴いている口の上の地面のボールを上へ跳ね上げ（上向き 7・口の外へ 2.5・横の速さは半分）、足元に持っている子からも離す。跳ね上げた後 0.3 秒は誰も持てない。1回噴く間に跳ね上げるのは1度だけ
- 記録: `SaveData` は変えない。ゴルフで作ったミニゲームの記録の表に `gameId = "soccer"` の行を足す。ベスト＝1試合の得失点差の最高（大きいほど良い。PK戦で決まった試合は 3分の間の点だけで数えるので 0。見せ方は「+3」「±0」「−1」）、special＝勝った回数（PK勝ちも含む）。初めて勝ったかは、書く前の勝った回数が 0 かで決める（項目を足さないため）。結果を出すときにコインと記録を書いて保存する
- 計算はすべて純C#の `Soccer.Core`（Unity の物理は使わない）。1/30 秒の固定の刻み。数値は `SoccerRules`（ルール）・`SoccerBalance`（ボールと動き）。ゴルフの Core は参照しない（汎用の形の計算はゴルフから共通の `MiniGameGeometry` へ移して両方で使う）
  - ピッチ（`SoccerPitchDef`・`SoccerPitchTable`）: 横 28 × 縦 16 マスの長方形の四隅を斜めに切り、壁で囲む（ボールは外へ出ず跳ね返る）。左右の壁の真ん中にゴールの口（幅 5・高さ 1.6 マス）と、その奥に網の箱。赤は左のゴールを守って右へ攻め、青はその反対
  - ボール（`SoccerWorld`）: 地面を一定の摩擦で転がる（氷の床ではよく転がる）。壁で跳ね返る（速さは 70% 残る）・網は勢いを吸う・バンパーは強く弾き返す。浮いた球は簡単な放物線で落ちて弱く跳ねる。速い球も壁をすり抜けないよう、1歩をボールの半径の半分より短く分けて進める
  - 持つ: 離れたボールに、この歩でボールが通った線から届く子（0.72 マス）がいれば持つ（足元の少し前に吸い付く。何人も届くなら、ボールが先に通りかかった子）。頭より高い球・転んでいる子は持てない。持っている子は歩く速さ ×0.85。蹴った子は 0.4 秒は持てない。誰も触らないまま 8 秒たつと、ボールが一番近い子の方へ自分で転がる。持っているボールは子の足元から置き直す（壁ぎわ・角でもボールが壁の外へ出ない）
  - 子どうしは重ならない（重なったら半分ずつ押し離す。すべっている子は押されない）
  - ボタンは「押しているか」で届き、押した瞬間は前の歩と比べて決める。持っているときは シュートのボタン＝シュート・パスのボタン＝パス、持っていないときは シュートのボタン＝スライディング・パスのボタン＝ダッシュ（どのボタンかは下の「操作」）
  - シュート: 持っている間に押した瞬間からためて（0.8 秒で満タン）離すと蹴る（持つ前から押しっぱなしのボタンではためない。スライディングで奪ったあと勝手に蹴らないように）。強さはためた長さ、満タンなら浮いた球。向きはスティック（倒していなければ向いている向き）で、相手のゴールの口へ最大 15° 寄せる（`SoccerAim`。もう口へ向いているとき・ゴールと反対へ蹴るときは変えない）
  - パス（`SoccerWorld.Actions.cs`）: スティックの向き（倒していなければ向いている向き）の ±60° にいる味方のうち一番近い子（1.2 マスより遠い子）の足元へ、着いたときに秒速 3 マス残る速さ（秒速 6〜15 マス）で転がす。受ける子が走っていれば、その先へ転がす。前に味方がいなければ向いている向きへ秒速 7 マスで蹴り出す。ためている間は出せない
  - スライディング: スティックの向き（倒していなければ向いている向き）へ 0.35 秒すべる（秒速 10 マス・約 3.5 マス。すべる間は向きを変えられない）。持っている相手のボール（子の中心から 0.92 マス）か体に届いたら奪い、奪われた子は 1 秒転ぶ（動けない・持てない）。離れたボールを拾っても成功。外すと 0.5 秒起き上がれない。すべり始めてから 1.2 秒は次を出せない
  - ダッシュ: 0.5 秒だけ歩く速さ ×1.45（転がるボールを追いかけるため）。次に出せるまで 3 秒
  - ゴール: ボールの中心がゴールの線を越えたら点（持ったまま運び込んでも点）。バーより高い球はゴールの口で跳ね返る。点が入ったら次のキックオフまで誰も持てない
  - キーパー（`SoccerWorld.Keeper.cs`・`SoccerKeeperSave`）: ペンモンではないおもちゃのキーパーが両チームに1体ずつ（強さは同じ。操作しない・スライディングされない）。ゴールの線の 0.7 マス前の線の上だけを横に動き、ふだんはゴールの真ん中とボールの間（ボールの縦の位置の 0.45 倍）に立ち、シュートが来たら通る所へ寄る
    - 止めるか: シュートがキーパーの線に着く 0.6 秒前に、その道筋ごとに1回だけ決める。気づくまで 0.2 秒は動けず、その後は秒速 4 マス・最大 1.7 マスまで飛びつける。立ったまま腕で届くのは 0.55 マス。「動ける距離 − 届かせるのに要る距離」が大きいほど止める割合が上がり（余裕 0 で 50%、±0.5 マスで 100% / 0%）、バーの高さの球は 3 割止めにくい。割合はいつも 3%〜97% に収める。乱数はホストの `System.Random`（同じ種なら同じ結果）
    - 結果の目安: 遠くからの弱い球・真正面の球はほぼ止める。7 マスくらいから端へ強く蹴るとほぼ入る。真ん中寄りの球は強さと距離で五分五分になる
    - 止めると決めたら通る所へ飛ぶ（運よく止める球には間に合う速さで飛ぶ）。止めないと決めたら指先が届かない所へ（真正面の球なら反対へ読み違えて）飛ぶ。止めないと決めた球が体に当たったら、勢いを半分にしてはじく。秒速 5 マスより遅い球は、決めた後でも取る
    - 飛びついたら 0.7 秒倒れて起き上がる。取ったら 0.9 秒胸の前で持ってから、一番近い味方の足元へ転がす（味方がいなければ前の、相手のいない側へ 7 マス）。投げた後 0.6 秒はそのキーパーは取らない
    - 相手の子が持ったまま手の届く所（体の中心から 0.77 マス）まで近づくと、足元のボールを取る（味方の子からは取らない）。ペンモンはキーパーを通り抜けない
- 見た目（`SoccerView`）: おもちゃのフットサル場。芝のマット（刈り目の縞・厚みのある台）に白い線（外の線・真ん中の線・センターサークル・センターマーク）、まわりにワールドの地面の絵、ワールドの柵の色の低い柵（強い球が当たると弾む）、白いゴールの枠と、ボールが当たると膨らんで揺れる網。ボールは白に12枚の黒い五角形で、転がった分だけ回り、浮くと影が小さくなる。仕掛け（`SoccerView.Gimmicks`）: 氷の床は白い縁の水色の板、水流は青い帯に流れる「く」の字、風は流れる白い筋（止んでいる間は縮む）、バンパーの柱は黄色に赤い帯（弾くと膨らむ）、柵のバンパーは黄と赤の少し太く高い柵（弾くと弾む）、間欠泉は溶岩の光る縁の暗い口と岩の輪（噴く 0.9 秒前から揺れる）と、噴いている間だけ伸びる白い柱。弾く音は「ボヨン」、噴く音は「シュワーッ」。時刻はゲストには 1/15 秒ごとにしか届かないので、見た目は手元の時計を進め、届いた時刻から 0.1 秒までのずれを許す（帯の印がカクつかないように）
  - 子は本編の3Dのペンモン。ためる間は右足を引いて体をひねり（満タンで震える）、蹴ると足を振り抜く（強いほど大きく）。点を取ると喜び、取られると頭を抱える。全員の頭にチームの色（赤・青）のはちまき（後ろで結んだ端を垂らす。野生の子を暗くしても・凍っても、はちまきの色は変えない。`PenguinModelBuilder.AddTeamHeadband`）。動かしている子の足元に太い輪、ためている間はその外に黄色い弧がたまる（満タンで白とオレンジに点滅）。自分が動かしている子の頭の上には、先を下へ向けた黄色いしずく（▼）が上下に弾む（`SoccerControlMarker`。足元の輪は斜め上のカメラでは小さく隠れやすいので、隠れない頭の上を一番の手がかりにする）
  - キーパーはゼンマイのおもちゃの人形（台の上にチームの色の胴・帽子・大きな手袋・背中で回るねじ）。横へちょこちょこ跳ねて動き、飛びつくと横へ倒れ、取ると弾み、投げるときは下から振る。点を取られるとうなだれる
  - カメラ（`SoccerCamera`）: 斜め上からピッチ全体（柵とゴールの網まで）が収まる一番近い所に置き、ボールの方へ少し（2 割ほど）寄る。ゴールの瞬間はそのゴールへぐっと寄り、キックオフで戻る。スマホ（タッチの端末）では、右下のボタン（パス・シュート・必殺・交代）の下に両方のゴール（網と、その前 2.5m のキーパーの所）が入らないよう、見る所を少しずらし・少し引いた中で一番大きく映る置き方にする（`SoccerCamera.Avoid.cs`。ボールやゴールへ寄るときも、ゴールがボタンにかかる手前で止める。窓の大きさが変わったら収め直す）
  - 音（`SoccerSounds`）: 蹴る（強いほど低く大きい）・柵・柱とバー・網・着地・持つ・キーパーが飛ぶ / 取る / はじく / 投げる・笛（キックオフ）・ゴールのファンファーレ・自分の動かす子が替わった「ピコッ」。観客の声（チップチューンのノイズと声の束）: 点が入ったら（PK戦も）ファンファーレに歓声「ワーッ」を重ね、柱・バーに当たった・PK戦で止められた / 外れたらどよめき「おお〜」
- 動かす子の切り替え（`SoccerControl`）: 人はチームの3体のうち1体を動かし、残りは AI が動かす。動かしている子の足元にチームの色を白へ寄せた太く大きい輪（ゆっくり脈打つ）、AI の子は灰色へ寄せたチームの色の細い輪（6体に同じくらいの輪があると自分の子が見分けにくかったため、差をはっきりさせた。席の色の輪だと、赤のチームの P1 に青い輪が付いて相手に見えたため、輪はチームの色にそろえた。人の見分けは頭の上の名前）。自分の動かす子が替わった瞬間（交代ボタンでも自動でも）は、足元の輪と頭の上の印がポンと膨らんで戻り、小さく「ピコッ」と鳴る（音は試合が動いている間だけ。キックオフの並び直し・PK戦の番の替わりでは鳴らさない）
  - 味方がボールを持ったらその子へすぐ替わる。自分がパスしたら受ける子へ、味方のキーパーが投げたら受ける子へ替わる
  - 自分のチームが持っていないときは、ボールに一番早く着ける味方へ自動で替わる（転がるボールは追いつける秒、持たれたボールは走る秒で比べる）。替わってから 0.8 秒は替わらず、今の子より 0.5 秒以上早い子にだけ替わる。すべっている間・自分のパスが転がっている間（誰かが持つまで、長くても 2 秒）・味方のキーパーが持っている間は替えない。転んでいる子は 0.8 秒遅いとして比べる
  - 交代のボタンで、今の子を除いてボールに一番早く着ける味方へ替わる（スマホのボタンにはその子の顔を出す）
  - 人が動かしている子（オンラインで同じチームのほかの人）へは替わらない。同じチームに人が2人以上いるときは、席の若い人から順に動かす子を決める（同じ子を2人で動かさない）。替わった瞬間に押していたボタンは、離すまで新しい子へ届けない
  - 席ごとの操作の行き先は `SoccerHumans`（ひとりは席 0 だけ、みんなでのホストは全員の分）。人の入力が渡らなかった子は AI が動かす
- AI（`SoccerAi`）: 人が動かしていない子をすべて動かす。出すのは人と同じ入力だけ。乱数は種から作る `System.Random`
  - チームごとに、ボールを取りに行く子（持っている子）を1体だけ決める（ボールに一番早く着く子。今の子より 0.35 秒以上早い子がいるときだけ替える。味方の人の子が一番早ければ、AI の子は誰も取りに行かない）。キーパーが持っている間は誰も行かない
  - ほかの子には持ち場を配る（持ち場の場所への距離の合計が一番小さい配り方。決め直すのは考え直す間隔の 2 倍ごと）。攻め（味方が持っている・転がるボールに先に着ける）は「前（ボールより 5 マス前の、ボールと反対の側）」「後ろ（ボールの 4.5 マス後ろ）」、守りは「ゴールとボールの間（ゴールから 3 割の所）」「ボールを持っていない一番危ない相手の、ゴール側」。4人のチームは「横」「最後尾」/「少し前に残る」を足す
  - 持っているとき: 相手のゴールへ運ぶ（前 3.5 マスにいる相手を横へよけ、縦の壁に寄りすぎたら内へ）。シュートの届く距離（強さで 9〜10.5 マス）でコースが空いていれば、キーパーのいない側の柱の 0.7 マス内側を狙ってためて蹴る（ため 0.6 ＋ 1 マスにつき 0.03、0.95 まで。満タンの浮いた球は蹴らない）。4 マスより近いか、キーパーが 2.2 マスより近ければコースが空いていなくても蹴る。ゴールの線の近くで角度が無い所では蹴らずに中へ運ぶ。2.2 マスに相手がいればコースの空いた味方へパス、いなくても前の空いた味方がいれば（賢さの割合で）パス
  - 取りに行く子: 転がるボールは追いつける所へ。相手が持っていれば、相手が 0.3 秒先に着く所の 0.8 マス自分のゴール側へ回り込み、ボールが 1.6 マスに入って向きが合っていればスライディング（出すかは考え直すたびに乱数）。ボールが 4 マスより遠ければダッシュすることがある。持ち場の子も、相手が持っているボールが 2.5 マスに来たら奪いに行く

  - AI の強さ: 人のチームの人が動かしていない子は ★3。協力の CPU はスタジアムの強さに、2人目から1人増えるごとに ★ を1つ足す（★5 まで。案）。必殺シュートは CPU のチームの AI だけが使う（対戦では AI は使わない）
  - 通信: ホストがすべて計算する。ゲストは入力（スティックの向き・シュート・パス・必殺のボタンを押しているか・交代を押した回数）を、ボタン・交代が変わったらすぐ、スティックだけの変わりは 1/30 秒より短くならない間隔で送る（`SoccerNetInput`。向きは各成分 −127〜127 に丸める）。ホストは届いた入力を歩ごとに使い、1歩の間に「押して離した」が両方届いても、その歩は押している扱いにする（短く押したシュート・スライディングを落とさないように。`SoccerRemoteInput`）
  - スナップショット（`SoccerSnapshot`・`SoccerCodec`。毎秒15回）: スタジアム・遊び方・1チームの子の数・席ごとのチーム（抜けた席は −1）と動かしている子と入れた点・子ごとの種類・試合の段と時間・ピッチの時刻（仕掛けの様子）・点・ゲージ・ボール・飛んでいる必殺シュート（属性・消えているか）・子とキーパーの位置と状態・PK戦（本数と結果・蹴る子・ため）と、前に送ってから起きたこと。ゲストは計算せず、写しの試合（`SoccerMatch.CreateMirror`・`ApplySnapshot`）に書き込んで、ひとりと同じ見た目・HUD・音で描く。位置は、いま描いている所から届いた所へ、次が届くまでの 1/15 秒をかけて寄せる（キックオフ・PK戦の構えでは一瞬で並べ直す）。形の違う（子の数・席の数が違う）スナップショットは無視する
  - 始め方: ゲストはシーンに入ったら「準備できた（編成の種類）」をホストへ送る（最初のスナップショットが届くまで 0.5 秒ごとに送り直す。20 秒届かなければロビーへ）。ホストは全員の分がそろうか 6 秒たったら始める（届かなかった人は仮の種類で埋める）。移っている間に抜けた人の子は、はじめから AI。ホストのスタジアムがこの版に無いゲストはロビーへ
  - 見分け: 人が動かしている子の足元に、チームの色を白へ寄せた太い輪（AI の子は細く沈んだ輪）、ほかの人の子の頭の上にその人の名前を席の色で（長い名前は小さく。`SoccerNameTags`。HUD の字を子の頭の位置へ置き直す）。自分の子には名前の代わりに黄色い印（▼）を出す（各自の端末で、自分の子だけ）
  - PK戦: 蹴る子は試合と同じくチームの子の番号の順。入力を渡す人は、蹴る側はそのチームの蹴った本数で、守る側は相手の蹴った本数で、チームの人を席の若い順に回す（1人のチームはいつもその人、2人のチームは交互）。番の人にだけ、ためゲージ・持ち時間・狙い方（守る番なら飛ぶ向き）の一言と足元の輪を出す。蹴る子の狙いはスナップショットに載せず、守る人の選びはホストにだけ届いて蹴った瞬間に決まる（守る人の選びを蹴る人に見せない）
  - 切断: ゲストが落ちたら、その人の子は AI が動かして続ける（「P2 が抜けました」）。ホストが落ちたらゲストはロビーへ
  - 結果: 勝ち負け・点・得失点差・報酬は、各自の端末で自分のチームから見て決め、自分の記録に書く（ひとりと同じ式・同じ記録の行）。点を一番入れた人（並んだら全員）を、結果の欄の左に「MVP」の板で出す（名前の下に席の色の帯と「2 点」。誰も入れていなければ出さない）。点は蹴った（パスした）瞬間に動かしていた人のもの（蹴った後に動かす子が替わっても、その人の点。自分のゴールへ入れた点・AI の子が入れた点は数えない。PK戦の点は数えない）。札は「スタジアムを選ぶ」（ホストだけ。全員が部屋をつないだまま待ちの窓へ）・「ロビーへ」（部屋から抜ける）。「もう一度」は出さない。ゲストには「ホストがスタジアムを選ぶと、みんなで待ちの窓へ戻ります」
- 試しのピッチ・スタジアムを試す・PK戦の確認（開発用）: エディタの `Tools > PenmonScramble > Soccer > 試しのピッチ` で、スタジアム1と同じ試合を、`スタジアムを試す > 2 氷山` などでそのスタジアムの仕掛けと CPU の強さの試合を（ストーリーを進めずに）、`PK戦の確認` で試合を飛ばして PK戦から遊ぶ（どちらも記録には書かず、結果の合計に「試しの試合は記録しません」）

### 13.5 ペンモンベースボール

- おもちゃの野球盤の形（守備は盤の穴、走者は自動）。名前に「野球盤」は使わない（他社の商品名のため）
- ミニゲーム画面にカード（土のダイヤモンドの上の白い球と赤い縫い目の絵・「ペンモンベースボール」・「魔球を曲げて、タイミングで打ち返す3イニングの試合」）が出る。球場は 1 海岸 / 2 氷山 / 3 深海 / 4 嵐の崖 / 5 火山の入り江（ワールド1〜5。番号は一度配ったら変えない）。5球場とも遊べ、どの球場もそのワールドに入ると開く（ゴルフ・サッカーと同じ `MiniGameUnlock`。まだなら「ワールド N に入ると解放」）。球場のカードの中身（`BaseballCourseGuide`。`BaseballSceneRunner` が起動時に登録）は1行目に強さ「CPUの強さ ★★☆☆☆」・2行目に盤の一言「外野が氷（よく転がり、長打が出やすい）」と、報酬の一言（「報酬 20 コイン ＋ 勝つと 50 ＋ 1点ごとに 8」、まだ勝っていなければ「初めて勝つと ボーナス +100」）。「みんなで」を押すと、待ちの窓で野球とその球場を選んだ状態で「みんなで遊ぶ」の窓が開く
- シーン（`BaseballScene`。`BaseballSceneBuilder` で生成）: ミニゲーム画面の「ひとりで」から、選んだ球場で試合を始める。まだ作っていない球場なら、球場の名前と「球場は準備中です」と「もどる」だけ
- 記録: `SaveData` は変えない。ミニゲームの記録の表に `gameId = "baseball"` の行を足す（ベスト＝1試合の得失点差の最高で、大きいほど良い。見せ方は「+3」「±0」「−1」。special＝勝った回数で、引き分けは数えない）。結果を出すとき（コインと記録を書いた直後）に保存する
- 計算はすべて純C#の `Baseball.Core`（Unity の物理は使わない）。1/30 秒の固定の刻み。数値は `BaseballRules`（ルール）・`BaseballBalance`（球とバット）。ゴルフ・サッカーの Core は参照しない
  - 盤（`BaseballFieldDef`・`BaseballFieldTable`）: ホームを原点にした扇形。ファウルラインはセンターから左右 45°、フェンスはホームから 14 マスの円弧（高さ 1）。マウンドはホームの 5.5 マス前。穴は種類（ゴロアウト・ゲッツー・フライアウト・単打・二塁打・三塁打）・位置・半径で持つ。穴に入らずに止まったら、ホームからの距離の札で決まる（内野の土 7.5 マスまで＝ゴロアウト、外野の芝 12.2 マスまで（フェンスの 1.8 マス手前まで）＝単打、フェンス際の帯＝二塁打）。ストライクのゾーンはホームの線の上の幅（片側 0.55）。試しの盤は、内野にゴロアウト4つ・二塁ベースの上にゲッツー（見た目も白い二塁ベースの真ん中が穴）・内野の間に単打2つ、外野の手前に単打2つ・フライアウト3つ・外野の間に二塁打2つ・フェンス際の隅に三塁打2つ
  - 投げる（`BaseballPitch`）: 球はマウンドからホームへ盤の上を一定の速さで転がる（ホームまで ストレート 0.7 秒・カーブ 1.0 秒・チェンジアップ 1.4 秒）。曲げる入力は横の速さを増やし（曲げやすさは球種ごと。カーブが一番）、道のりの 70% を過ぎたら横へは動かずまっすぐ来る。左右の溝の幅（±1.6）より外へは出ない。ホームの線を越えた所がゾーンの中ならストライク、外ならボール（見送ったとき）。ホームの後ろ 0.8 マスでミットに収まる
  - 振る（`BaseballBat`）: バットは打つ子の立つ所（ホームの左。右打ち）を軸に、盤の上で水平に回る（0.16 秒で −75° から 100° まで一定の速さ。0° がホームの上を横切る向き）。バットの線に球が前から触れたら当たり。当たった角度の 1.3 倍の向きへ飛ぶ（早い＝引っ張り＝左・遅い＝流し＝右。行き過ぎるとファウル）。強さは芯（軸から 1.15、幅 ±0.2）で一番、根元・先は 0.3 まで、角度が 15° を超えると下がる。ジャスト（15° まで）＆芯で強さ 0.9 以上の当たりだけ浮く（放物線）。バットの届かない所（手元より内・先より外）を通る球には当たらない。振れるのは1球に1回。振って当たらなければ空振り。振った時刻は 1/30 秒の歩の中まで渡す（`BaseballInput.SwingTime`。歩の刻みのままだとバットの角度が 36° ずつ飛び、ジャストが運になるため）。人の入力は、押した瞬間に画面に見えていた時刻（前の歩と今の歩の間の補間）で振ったことにする
  - 打席の中を動く（`BaseballBat.Move`・`BaseballInput.Move`）: 投げた球が来ている間、打つ子とバットの軸は左右へ動ける（構えの所から片側 0.6・毎秒 2.4）。動けるのは振り始めるまで（バントの構えのままでも動ける）。球ごとに構えの所へ戻る。ゾーンの端（0.55）の球にも芯が届き、ゾーンの外へ大きく外した球には届かない。曲げられる区間が終わってから球が来るまで（ストレートで約 0.2 秒）には半分ほどしか動けないので、曲げる球を読んで先に動くこと・最後に曲げる魔球に意味が残る
  - バント: 押している間、バットを 0° に寝かせて構える。当たると弱く転がる（芯で 4.2、手元・先で 7 割。先で当てると右へ・手元で当てると左へ最大 30°）。構えたまま球がミットに来たら空振りと同じ。離せば見送り
  - 打球（`BaseballBallSim`）: 浮いた球は放物線で飛び、浮いている間は穴に落ちない。着いたら横の速さを 6 割残して小さく跳ねる。フェンスより高く越えたらホームラン、低ければ跳ね返る（速さは 45% 残る）。転がる球は摩擦（毎秒 7）とすり鉢の引き（毎秒 0.6、内野と外野の境のあたりへ）で遅くなり、穴の上を速さ 5 より遅く通れば落ちる（速いと縁で曲がって通り過ぎる。ゴルフのカップと同じ形）。穴に入らずに止まったら止まった場所の札。ファウルラインの外（ホームの後ろも）へ転がったら、または浮いた球が外に着いたらファウル（ホームから 0.9 マスまではまだ決めない）
  - 球場（`BaseballStadiumTable`・盤は `BaseballFieldTable`）: 奥のワールドほど CPU が強く、盤に仕掛けがある。CPU の3体はそのワールドの雑魚の混ぜ方（サッカーと同じ）から試合ごとに選ぶ

  - 盤の時計（`BaseballClock`）: 仕掛けの様子（水流・風の向き・動く穴の位置・間欠泉）は盤の時計だけで決まる。時計は投げた球の番号から決め（番号 × 2.37 秒）、投げてから球が動いている間だけ進む。番号だけで決まるので、オンラインでもどの端末も同じ1球になり（通信の中身は変えない）、球ごとに風の向き・穴の位置が変わる。投げる前は次の球の投げた瞬間の様子で止まっていて、投げたら動き出す（次の球の様子へは滑らせて移る）
  - 1球（`BaseballBoard`）: 投げる → 振る・バント → 打球 → 結果（見送りのストライク・空振り・ボール・ファウル・フェアの結果）。起きたこと（投げた・曲げられる区間の終わり・振った・ホームの線・ミット・当たった・着いた・フェンス・穴の縁・穴に入った・止まった・ホームラン・ファウル）は `BaseballEvent` で表示と音へ渡す。投げた球とバットは1歩を 8 回に分けて動かし、バットが球を飛び越えないようにする
- カウント（`BaseballCount`）: 3ストライクで三振・4ボールで四球・3アウトで交代。ファウルは 2ストライク未満ならストライクを1つ足す（2ストライクからは足さない。バントのファウルも同じ）。打ってアウト（ゴロ・フライ・ゲッツー）はアウト1つ
- 走者と点（`BaseballBases`）: 単打・二塁打・三塁打は打者も走者も全員その塁の数だけ進む。ホームランは全員ホームへ。四球は押し出される走者だけ1つ進む。ゴロアウト（バントの犠打も）は全員1つ進む。ゲッツーは一塁に走者がいて2アウト未満なら一塁の走者もアウト（ほかは1つ進む）、それ以外はゴロアウトと同じ。フライアウトは三塁の走者だけホームへ（タッチアップ）。その打球で3アウトになったら点は入らず、走者も動かない
- 試合の流れ（`BaseballGame`）: 3イニング。表は先攻・裏は後攻が打ち、3アウトで交代。打順は編成の 1→2→3 をくり返し、イニングをまたいで続く。3回裏（サヨナラも）で後攻が勝ったらその時点で終わり、3回表が終わって後攻が勝っていたら裏はしない。2回裏以降、後攻が 10 点差でリードした時点、または2回裏・3回の終わりに 10 点差なら早く終わる。3回が終わって同点なら引き分け。投げる子は守る側が打席ごとに3体から選ぶ（前と同じ子でも良い）
- 魔球と必殺打（`BaseballSpecial`・`BaseballBalance.Special.cs`）: 子の属性で動きが、★（1〜3）で強さが決まる（パワーは効かせない）。各子1試合1回ずつで、魔球（その子が投げるとき）と必殺打（その子が打つとき）は別に数える（残りは `BaseballGame` が持つ）。魔球は投げたら使った扱い（ボールになっても）、必殺打は振って当てたときだけ使った扱い（ファウルも。空振り・見送り・バントでは残る）
  - 出し方: 投げる前に、投げる人は「魔球」、打つ人は「必殺打」の札を ON にしておく（Space / L1・画面の札。相手には見えない）。投げた瞬間に、出した側のカットイン（本編と同じ顔の帯。上が投げる子「○○の魔球！」・下が打つ子「○○の必殺打！」）を出して 0.6 秒盤を止める。魔球の ON は投げたら戻る。必殺打の ON はその打席の間残る（当てたら・打席が替わったら戻る）。札は投げる番は投げるまで、打つ番は投げるまでと打席が続く間の結果を見せている間だけ出す（残っていない子のときは出さない）
  - 魔球 氷「フリーズボール」: 道のりの 80%（まっすぐ来る区間）で凍って止まり（氷のかたまりで包む）、また動き出す。止まる秒は ★1 0.3〜0.45・★2 0.25〜0.6・★3 0.2〜0.75 秒の中で投げるたびに決まる（★が高いほど読みにくい）
  - 魔球 水「ゆらゆらボール」: 道のりに沿って左右に波打つ（ホームまでに 2.5 回。幅 ★1 0.22・★2 0.3・★3 0.38）。揺れの始まりは投げるたびに変わり、どちら側でホームを通るかが読めない
  - 魔球 風「旋風ボール」: 曲げる入力が 1.7 倍効き、曲げられる区間が終わると逆へ曲がり出す（★1 1.0・★2 1.4・★3 1.8 の横の速さ）
  - 魔球 雷「消える魔球」: 道のりの 30% で消え、★1 72%・★2 80%・★3 86% で現れる（見た目だけ。当たりは消えている間も変わらない）
  - 必殺打 氷「アイスロード」: 転がる打球の通り道が凍り（★1 5・★2 7・★3 9 マス。盤に氷の跡を残す）、その間は摩擦が 0.45 倍でアウトの穴の上を滑って渡る（ヒットの穴には落ちる）
  - 必殺打 水「水切りヒット」: 打球が水切りのように跳ねて進み（★の数だけ跳ぶ。跳んでいる間は穴に落ちない）、跳ねるたびに山が 0.8 倍・横の速さが 0.92 倍になる
  - 必殺打 風「追い風ヒット」: 打ってから 2 秒の間、打った人が ←→ / スティックで打球を左右に曲げられる（速さは変えず向きだけ。★1 9・★2 13・★3 17。打つ番の左右と同じスティック）
  - 必殺打 雷「イナズマ打ち」: 打球の速さが ★1 1.15・★2 1.25・★3 1.35 倍で、速さ 3 より速い間はどの穴にも落ちない

    - 対戦: 赤と青の両方に人がいないと開始できない。1対1・2対1・2対2・3対1 のどれでも良い
    - 協力: 人は全員赤（先攻）で、CPU（青。球場の野生のペンモン3体）と戦う。ひとりでも開始できる。CPU の強さは球場の強さに、2人目から1人増えるごとに ★ を1つ足す（★5 まで。`BaseballBalance.CoopCpuStars`）
  - 打順（`BaseballTeamPlan`）: 人が1人のチームはその人の編成（1〜3体）、2人のチームは A1・B1・A2・B2（席の若い人が A。編成にいない子は飛ばす）、3人・4人のチームは各自の先頭。人のいないチームは CPU（野生のペンモン3体）。打席の子を動かすのはその子の持ち主（打順のカードの左上に持ち主の名前を席の色で出す）
  - 投げる人: 守る側の人が打席ごとに交代で投げる（チームの人の席の若い順に回る）。投げる子は自分の子の中から選ぶ（1人のチームは全員が自分の子）。人のいないチームは CPU が投げる
  - ほかの人の番の間: 「〇〇 が打つ番です」「〇〇 が投げる番です」を出し、ボタン・スティック・球種の札は出さない
  - 通信: ホストがすべて計算する（試合の区切り・カウント・走者・点・魔球と必殺打の残り）。ゲストは自分の番の入力だけを送る（`BaseballNetInput`: 次に投げる球の番号・投げる子の選び・必殺打の ON・投げた知らせ（球種・魔球の ON・魔球の中の乱数）・1球の入力の記録）。ホストは区切りが変わるたびと毎秒15回（球が動いている間は 1/30 秒ごと）にスナップショットを送る（`BaseballSnapshot`: 組み方・試合の様子・区切り・投げた球の数・投げる人・今の球の投げ方と2人の入力の記録・決まった結果・打点。`BaseballCodec` の版 1）
    - 1球の計算（`BaseballPitchSession`）: 1球は投げ方（球種・魔球・必殺打・CPU の組み立て）と2人の入力の記録（`BaseballRoleLog`: 投げる人は歩ごとの曲げる入力、打つ人は歩ごとのバントの構えと、曲げる入力の欄（投げた球が来ている間は打席の中の左右・打った後は打球を曲げる入力）・振った歩と歩の中の時刻。値は 1/127 に丸めてから使う）だけで決まるので、どの端末も同じ記録から同じ1球を計算する。CPU の曲げる入力（組み立てから）と CPU の打った追い風ヒットの曲げ（盤から）は送らずに各端末で計算し、CPU の左右・振る・バントはホストが記録して送る
    - 自分の番の入力はその場で記録に書くので、振ったバット・曲げた球はすぐ動く。相手の入力は届くまで最後の値が続くと見なして進め、届いた記録が使った値と違えば投げた所から計算し直す（音・演出は続きだけを出す。跳んだ球は描く位置を寄せて消す）
    - 振った時刻は振った人の画面の時刻のまま（投げてからの歩と歩の中の時刻）。ホストは、結果が出た歩までの全員の入力が届いてから結果を試合に入れる（遅れている人の入力で結果が変わるかもしれないため。2.5 秒待っても届かなければ届いた所までで決める）。ゲストは結果が届いたら、自分の計算もホストの記録でそろえ直し、試合の様子と結果はホストの物を使う
    - 投げる・必殺打の ON は、投げた瞬間までホストが相手の側へ送らない（スナップショットに入るのは投げた後）
    - ゲストが投げるとき: 球種を押したら投げた知らせをホストへ送り、自分の端末では先回りして振りかぶって投げる（ホストより少し先に球が出るので、曲げる入力がホストへ遅れずに届く）。ホストの「投げた」が届いたら答え合わせをし、打つ人の必殺打が出ていればそのカットインを出して残りの間だけ止める。違っていたら（持ち時間切れでホストが先に投げたなど）ホストの球で投げ直す。ホストは持ち時間を 1.5 秒過ぎても知らせが届かなければ、前の球種でまっすぐ投げる
  - 始め方・切断: サッカーと同じ（ゲストは「準備できた（編成）」を送り、ホストは全員がそろうか 6 秒で始める。届かなかった人は仮の子）。ゲストが抜けたら「〇〇 が抜けました」を出し、その人の子は CPU が打つ。投げる番は残っている人で回し、チームに人がいなくなったら CPU が投げる。投げている途中・打っている途中ならその人の記録はそこで終わりにする。ホストが抜けたら全員ロビーへ
  - 結果: 各自の端末で、自分のチームの点で記録と報酬を書く（ひとりと同じ式）。左に MVP（打点の一番多い人。並んだら全員。誰も打点が無ければ出さない。押し出しの四球も打点）。「もう一度」は無く、「球場を選ぶ」はホストだけ（全員で待ちの窓へ戻る）。メニューの「試合をやり直す」は出さず、開いても止まらない

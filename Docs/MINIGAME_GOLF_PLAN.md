## ミニゲームの共通の仕組み（今後のミニゲームも乗せる土台）

ゴルフを作りながら、次のミニゲームでそのまま使える形にする。**ゴルフ固有の物は共通側に書かない**（共通基盤 `Common/` とゲーム本体の関係と同じ考え方）。

### フォルダと asmdef（案）

```text
Games/100_PenmonScramble/
  Scripts/
    Core/ ...（今のまま）
    Game/ ...（今のまま）
    MiniGames/
      Shared/Core/   PenmonScramble.MiniGames.Core     （純C#。ミニゲームの定義表・解放・報酬・記録の読み書き）
      Shared/Game/   PenmonScramble.MiniGames.Game     （ミニゲーム画面・部屋の切り替え・結果の共通の部品）
      Golf/Core/     PenmonScramble.Golf.Core          （純C#。球の計算・ホール・ルール・打順・特殊ショット）
      Golf/Game/     PenmonScramble.Golf.Game          （3D の表示・操作・HUD・通信）
  Editor/MiniGames/Golf/   GolfSceneBuilder など
  Tests/Editor/MiniGames/  共通とゴルフのテスト
```

- 各ミニゲームの Core は `noEngineReferences: true`。ペンモンの種類・属性・★は本編の `PenmonScramble.Core`（`SpeciesTable`）を参照して使う（逆向きの参照はしない。本編の Core はミニゲームを知らない）
- 名前空間は `PenmonScramble.MiniGames.*` / `PenmonScramble.Golf.*`

### ミニゲームの定義表 `MiniGameTable`（Shared/Core）

1つのミニゲームにつき1行。ミニゲーム画面・部屋の切り替え・記録はこの表から作る（表に1行足せば入口に並ぶ）。

| 項目 | ゴルフの値 |
| --- | --- |
| Id（記録に残るので一度配ったら変えない文字列） | `"golf"` |
| 名前・一言の説明 | ペンモンゴルフ / 編成の3体で打って、少ない打数でカップへ |
| 遊べる人数 | ひとり ○ / みんなで 1〜4人 |
| シーン名 | `GolfScene` |
| コース（遊ぶ単位）の一覧と解放の条件 | 5コース。解放はストーリーのクリア状況で決める関数 |
| カードの絵 | Rebuild で撮る（ゴルフのコースの絵） |

### 入口と画面の流れ

```text
ロビー（左の列: ガチャ・ペンモン・ミニゲーム・遊び方）
 └ ミニゲーム → ミニゲームを選ぶ画面（カードが並ぶ。今はゴルフだけ）
      └ ゴルフのカード → コースを選ぶ（◀ ▶。景色・3ホールのパー・ベスト・報酬・鍵）
           ├ ひとりで → ゴルフのシーン → 結果 →「もう一度」/「コースを選ぶ」/「ロビーへ」
           └ みんなで → 部屋を作る / コードで参加 → 待ちの窓（遊ぶもの = ゴルフ が選ばれた状態）
```

- ロビーの「みんなで遊ぶ（ボスラッシュ）」は「みんなで遊ぶ」に名前を変え、待ちの窓で遊ぶものを選ぶ（最初はボスラッシュ）
- 待ちの窓（今の `RushLobby`）の右側を「遊ぶものの札（ボスラッシュ / ゴルフ / …）＋ その遊びの選択の板」に広げる。遊びごとの選択の板（ボスラッシュ＝ステージと難易度、ゴルフ＝コース）は差し替えられる部品にする（`IRoomModePanel` のような共通の形）
- ホストが札を切り替えると、ゲストへ名前付きメッセージで届く（`scramble.room.mode`。今の `scramble.rush.choice` と同じく、ゲストから頼む形も入れる）
- 結果の「ステージを選ぶ／コースを選ぶ」で戻ると、同じ顔ぶれのまま待ちの窓へ（今の `OnlineSession.ReturnToRoom`）。ここで遊ぶものを替えられる

### シーン

- ミニゲームは**ミニゲームごとに別のシーン**にする（本編のシーンが重くならないように。足すたびに本編を触らずに済むように）。シーンは SceneBuilder（`GolfSceneBuilder`）で生成し、ビルドの一覧にも Editor スクリプトで足す
- 本編のシーンへ戻るときは、今の「タイトルへ」と同じく本編のシーンを読み直し、ロビー（またはミニゲーム画面・待ちの窓）から始める。どこへ戻るかはシーンをまたいで残す小さな「戻り先」で渡す（今の「ステージから戻ったときはロビーから」と同じ仕組みを広げる）
- オンラインの部屋は、今は「同じシーンの読み直し」だけを引き継げる。**別のシーンへ移っても部屋を引き継げる**ように共通基盤の `OnlineSession` を広げる（フェーズ 5 の最初に調べて決める。うまくいかなければゴルフを本編のシーンの中の1モードにする案に切り替える＝フェーズ 1 では両方に移れる作りにしておく）

### 記録（セーブ）— CLAUDE.md §3.5 を守る

- `SaveData` に**ミニゲーム共通の表を1つだけ足す**（version 2 → 3）。次のミニゲームからは項目を足さずに、この表に Id 違いの行を足すだけで済むようにする

```csharp
// 案。項目名は一度配ったら変えない
public List<MiniGameRecord> miniGames = new List<MiniGameRecord>();

[Serializable]
public sealed class MiniGameRecord
{
    public string gameId;   // "golf"
    public int courseNo;    // コース（遊ぶ単位）の番号。一度配ったら変えない
    public int plays;       // 回った回数（初回ボーナスの判定に使う）
    public int best;        // ベスト（ゴルフは打数。小さいほど良い。0 = まだ無い）
    public int special;     // ミニゲームごとの数（ゴルフはホールインワンの数）
}
```

- 古い記録（version 2）には空の表を入れる（`SaveStore.Upgrade`）。消すもの・名前を変えるものは無い。`OldestReadableVersion` は 2 のまま触らない
- 知らない `gameId` の行（新しい版で増えたミニゲーム）は、古い版で読んでも消さずに残す
- ゴルフの結果の後（コインと記録を書いた直後）に保存する
- 「ベストが小さいほど良いか大きいほど良いか」はミニゲームの定義表に持つ（次のミニゲームが点数制でも同じ表で済むように）

### 報酬

- 報酬の計算はミニゲームごとの Core に置き、共通側は「コインを足して記録を書く」だけ（`MiniGameReward`）
- 本編のステージより控えめにする（ミニゲームだけでコインを稼ぐのが一番得、にならないように。フェーズ 7 で本編の報酬と比べて決める）

### 新しいミニゲームを足すときの手順（このとおりに足せることをゴールにする）

1. `MiniGames/<名前>/Core`・`Game` と asmdef を作る
2. `MiniGameTable` に1行足す（Id・名前・人数・シーン名・解放・ベストの向き）
3. `<名前>SceneBuilder` でシーンを作り、ビルドの一覧に足す
4. 待ちの窓の選択の板（`IRoomModePanel`）を作る（オンラインがあるなら）
5. 報酬の計算を書き、`MiniGameReward` へ渡す
6. 仕様書 §13 に章を足す

## ゴルフのルール（案の数値はフェーズ 4・7 で決め直す）

### 1ホールの流れ

1. ティー（スタート）に全員の球が置かれる（重ならないよう少しずらす）
2. 打順の人が「どの子で打つか」を3体から選ぶ → 向きを決める → ゲージを止めて打つ
3. 球が止まる（全部の球の動きが止まる）まで待つ → 次の人
4. カップに入った人は抜ける。全員入るか打数の上限で終わり → 次のホール

### 打順・時間

- 1打ずつ交代。1ホール目は席の順（ひとりなら自分だけ）、2ホール目からは前のホールまでの打数が少ない順（同じなら席の順）
- 1打の持ち時間 20 秒（案）。過ぎたら、いま向いている向き・ゲージ 50% で自動で打つ（待たせすぎないように。ゲストの通信が切れかけでも進む）
- 打数の上限: パー ＋ 4（案）。上限まで打っても入らなければ「上限 ＋ 1」打で終わり

### 球の動き（Core で計算する）

- 球は平らな地面の上を転がり、摩擦で止まる。壁で跳ね返る（跳ね返りの強さは壁の種類で変える）
- 坂: 地面の上の「押す力の場」として持つ（見た目は傾いた床）
- 高さ: 球が浮くのは「ジャンプ台」と「特殊ショット（水）」のときだけ。浮いている間は簡単な放物線で、壁より高ければ越える（全部を本当の3Dの物理にしないのは、純C#で確かめやすく、オンラインで全員の見え方をそろえやすくするため）
- カップ: カップの上を通るとき、速さが一定より遅ければ入る。速すぎると縁で曲がって通り過ぎる
- 池・場外（溶岩・崖など）: 落ちたら 1 打足して、打つ前の位置に戻る
- 球同士: ぶつかると弾き合う（打っていない人の球も動く）。カップの中の球は当たらない
- Unity の物理（Rigidbody）は使わない。ホストの計算をそのまま全員に配るので、端末によって結果が変わらない

### 打つ子と特殊ショット

- 打つたびに編成の3体から選ぶ。ふつうのショットはどの子でも同じ（パワーは効かない）。子による違いは特殊ショットだけ
- 特殊ショットは、打つ前に「特殊」を ON にして打つ。各子 1コースに1回。使った子のカードは暗くなる
- 属性ごとの中身（案。★1 / ★2 / ★3 で強さが上がる）

| 属性 | 名前（案） | 効き目 | ★で変わる所 |
| --- | --- | --- | --- |
| 氷 | アイスロード | 球の通り道が凍り、止まりにくくなる。池・砂地の上も凍らせて渡れる | 凍らせる長さ |
| 水 | 水切りバウンド | 水切りのように地面で跳ねて進む。低い壁・池・障害物を越える | 跳ねる回数（1 / 2 / 3） |
| 風 | 追い風カーブ | 打つ前に右か左を選ぶと、大きく曲がって進む（ガイド線も曲がって見える） | 曲がる大きさ |
| 雷 | イナズマブースト | 打った後、もう一度ボタンを押すとその場で一瞬加速して向きを少し変えられる | 加速の強さ・変えられる角度 |

### スコアと報酬（案）

- 1ホールごとに打数、3ホールの合計が自分のスコア。表示はパーとの差（−1 バーディー、−2 イーグル、1打で入ればホールインワン）
- コイン ＝ 回った基本 40 ＋ パーより少ない打数 1 につき 15 ＋ ホールインワン 1 回につき 50（案。マイナスにはしない）
- オンラインの順位ボーナス: 1位 +40 / 2位 +20 / 3位 +10（案。ひとりでは無し。同じ打数は同じ順位）
- そのコースを初めて回ったら +100（案）
- 本編の1ステージの報酬と比べて控えめになるよう、フェーズ 7 で決め直す

## フェーズ 1: ミニゲームの共通基盤

ゴルフの中身は作らず、「入口 → 空のゴルフのシーン → 戻る」と記録の土台を通す。

### やること

1. `MiniGames/Shared/Core`・`Shared/Game`・`Golf/Core`・`Golf/Game` のフォルダと asmdef、テストの asmdef の参照を作る
2. `MiniGameTable`（ゴルフの1行）・コースの解放の判定（ストーリー連動。テストを書く）
3. 記録: `SaveData` に `miniGames` を足し version 3。`SaveStore.Upgrade` に古い記録の値（空の表）。読み書き・古い記録からの上げのテスト（version 2 の JSON をそのまま読んで、コイン・ペンモン・クリア済みが残ること）
4. ロビー左の列に「ミニゲーム」の丸いボタン（`TitleMenu` と SceneBuilder）
5. ミニゲームを選ぶ画面（`MiniGameHubScreen`）: 表からカードを並べる。カード → ゴルフのコース選び（コースのカード・鍵・ベスト。中身はフェーズ 4 で埋める）→「ひとりで」
6. `GolfScene` を `GolfSceneBuilder` で生成し、ビルドの一覧に足す。シーンには「もどる」だけ置き、本編のシーンのミニゲーム画面へ戻る（戻り先の受け渡し）

### 遊べる状態

ロビー →「ミニゲーム」→ ゴルフ → コース1 →「ひとりで」→ 空のゴルフのシーン →「もどる」でミニゲーム画面へ。古い記録がそのまま読める。

## フェーズ 2: ゴルフの計算（Core）と試しの1ホール

### やること

1. ホールの定義（`GolfHoleDef`。コードの定義表）: 地面の形（多角形）・壁（線分と跳ね返りの強さ）・坂（押す力の場）・池と場外・砂地・ジャンプ台・ティーとカップの位置・パー
2. 球の計算（`GolfBallSim`）: 一定の時間刻みで進める。摩擦・壁の跳ね返り・坂・浮いたときの放物線・カップ・池・球同士の衝突。止まったかの判定
3. 1ホールの進行（`GolfHoleWorld`）: 打順・打数・持ち時間・上限・カップイン・池の戻し。表示と音へは起きたこと（打った・壁に当たった・入った・落ちた）をイベントで出す
4. ガイド線の計算（最初の跳ね返りまで）を Core に置く（表示とオンラインのゲストで同じ線になるように）
5. テスト: まっすぐ打つと止まる距離・壁の跳ね返りの角度・カップに入る速さ・池で戻る・球同士の衝突・打順・上限
6. 開発用メニューから試しの1ホールを開く（`Tools > PenmonScramble > Golf > 試しのホール`）。見た目は仮（板と球と線）

### 遊べる状態

試しの1ホールで、向き・強さを決めて打ち、壁で跳ね返り、カップに入る。

## フェーズ 3: 見た目と操作

### やること

1. コースの3D: ホールの定義表から地面・壁・カップの旗・坂を組む（おもちゃのトゥーンの見た目。地面は今のワールドの地面の絵を使う）
2. 球: 白い球に、打つ人の席の色の帯（オンラインで見分けるため）
3. 打つ子: 今のペンモンの3Dに、クラブ（おもちゃの木のクラブ）を持たせる。構える → 振りかぶる（ゲージに合わせて引く）→ 打つ → 球を見送る、の動き（`Penguin3D` の動きの定義に足す）。カップインで喜ぶ・池で頭を抱える
4. 操作: 向き＝スティック / ←→（押し続けると速く回る）/ 画面のドラッグ。打つ＝J / ×（南）/ 右の大ボタンでゲージ開始 → もう一度で止めて打つ。打つ子の切り替え＝K / ○ / 子のカードを押す。特殊＝L / △ / 特殊のボタン。カメラで見回す＝右スティック / 画面の2本指（案）
5. ゲージ: 往復するパワーゲージ（端で一瞬止まらない。上から下へ戻る）
6. カメラ: 狙う間は球の後ろ斜め上からカップの方向を、打った後は球を追い、止まったら次の人の球へ寄る。ホールの始めにホール全体を見せる（「ホール 1  パー 3」）
7. HUD: 打順・打数・パー・持ち時間・3体のカード（属性の色・特殊を使ったか）・ガイド線
8. 音: 打つ音（強さで変える）・壁・カップイン・池（今の効果音の仕組みに足す）

- 特殊（L / △ / 特殊のボタン）の操作は、特殊ショットの中身と一緒にフェーズ 4 で入れる（フェーズ 3 ではボタンを置かない。押しても何も起きないボタンを見せないため）
- やり直しは K / ○ を打つ子の切り替えに使うので、試しのホールでは Space / LB にした

### 遊べる状態

試しの1ホールを、本番の見た目と操作で気持ちよく打てる（タッチ・キーボード・コントローラー）。

## フェーズ 5: オンライン対戦

### やること

1. 共通基盤 `OnlineSession` を、別のシーンへ移っても部屋を引き継げるように広げる（最初に調べる。だめならゴルフを本編のシーンの中のモードにする）
2. 待ちの窓に「遊ぶもの」の札（ボスラッシュ / ゴルフ）と、ゴルフの選択の板（コース・3ホールのパー・報酬）。解放はホストの記録。ゲストは見るだけ（`scramble.room.mode` と、ゴルフの選択のメッセージ）
3. 通信: 本編と同じく**ホストがすべて計算する**。ゲストは「打つ子・向き・ゲージを止めた強さ・特殊の ON / 右左・雷の2回目」を自分の番のときだけ送る。ホストは球の位置・打順・打数・起きたことをスナップショットで送る（狙っている人の向きとゲージも送って、ほかの人にも見えるようにする）
4. 開始時に各自の編成の3体（種類・★）をホストへ送る（本編の `StageCodec.Party` と同じ。届かなければ仮の3体）
5. 切断: ゲストが落ちたら、その人の球を消して打順から外す（残りで続ける）。ホストが落ちたら全員タイトルへ（本編と同じ）
6. 結果: 順位の表・順位ボーナス。報酬は各自の端末で保存。「コースを選ぶ」（ホストだけ）で待ちの窓へ戻る
7. ロビーの「みんなで遊ぶ（ボスラッシュ）」を「みんなで遊ぶ」に変える。ミニゲーム画面の「みんなで」からは、遊ぶもの＝ゴルフで部屋を作る

### 遊べる状態

友達と4人までコース1を順番に回れる。球を弾き合える。待ちの窓でボスラッシュとゴルフを切り替え、同じ顔ぶれで続けて遊べる。
